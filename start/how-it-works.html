How This Handbook Works

Five minutes here saves you an hour later. You'll learn how every page is laid out, how the three practice tracks fit together, what each kind of lab step means, and the few rules that keep AI-assisted coding honest.

Every topic page: Learn, Do, Check

Each topic has its own short page, so you can open exactly what you need in class. Every topic page follows the same three steps, shown as numbered banners:

1 · LEARN

The idea, made simple

A precise definition, the same idea in plain words, an everyday analogy, a diagram, how real products use it, and the developer mindset shift.

2 · DO

Drills, straight away

One or two hands-on drills that make the idea visible: run code, prompt your AI assistant, write a prompt, verify the result.

3 · CHECK

Prove you've got it

Two or three quick questions with hidden answers, and a one-line takeaway to carry forward.

Each module also has an Overview page (mental map and page list), a Build page (the Traincrest Assist milestone) and a Recap page (checklist and self-check). Tick Mark this page as done at the bottom of a page and the sidebar shows a ✓, saved in your own browser.

Three practice tracks

The six step types

Labs deliberately mix how you work. Real developers paste code, prompt AI assistants, write their own prompts and verify everything. Each step in a drill is tagged:

Run
Copy the code, run it, read the output. Code blocks show the file name; use the Copy button.
Ask AI
Paste a prompt into your AI coding assistant. You'll see why the prompt works, what you should get and a reference solution if your assistant gets stuck.
Your prompt
Write the prompt yourself from a template and a hint. Then open Compare with my prompt and see what you missed.
Verify
Run tests or commands, or tick a checklist. Never skip it: it's where you find out whether the AI's code actually works.
No-code
Try it in the Foundry playground, ChatGPT or Claude.ai. Fast intuition before code.
Think
A short design decision. Commit to an answer before opening the hidden one.

Working with AI coding assistants

You'll use an AI assistant inside VS Code throughout this course: GitHub Copilot (Chat, in agent mode), Claude Code (VS Code extension or terminal) or OpenAI Codex (IDE extension or terminal). Any one is enough; the prompts work in all three. Setup is in Workstation and AI assistant.

Using them is itself part of the curriculum. Every prompt you send an assistant is a small prompt-engineering exercise, which is exactly what Module 03 teaches.

The prompt template you'll see everywhere

Goal:        what to build or change, in one sentence
Context:     which files or folder, what already exists
Constraints: language, libraries, style, things it must NOT do
Done when:   how you will verify it (tests pass, command output, behaviour)

Five rules for AI-assisted coding

  1. Never paste secrets into a prompt. Keys stay in .env. If an assistant asks for your key, say no.
  2. Read the diff before you accept it. Agent modes can edit several files at once. Skim every change.
  3. Run the Verify step. Code that looks right is still a draft until the tests or checks pass.
  4. Iterate with evidence. If it fails, paste the exact error back: "pytest fails with … fix it without changing the tests".
  5. Use the reference solution as a last resort, and then compare: what did your assistant do differently, and why?
In the real world

Teams that get value from coding assistants treat them like a fast junior colleague: clear task, relevant files as context, explicit constraints and a definition of done. That's the same Context → Task → Constraints → Output structure you'll formalise in Module 03.

The case: TrainCrest and Traincrest Assist

TrainCrest· a technical training company (scenario, data and policies here are fictional)

TrainCrest runs instructor-led and self-paced courses in cloud, AI, data and security for learners in many countries. Learner support handles about 25,000 requests a month by email and chat, mostly in English but also in Spanish, Hindi, Arabic, Japanese and more. A 35-person team answers questions about schedules, payments, lab environments, exam vouchers and certificates. First responses take 11 hours on average.

Leadership wants Traincrest Assist: an AI assistant that answers policy questions correctly, checks enrolments and vouchers, finds the right course, raises tickets, and hands over to humans safely, at a predictable cost. Enrolment IDs look like TC-10293.
