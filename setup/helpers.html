Helpers and a Smoke Test

Every drill runs from one folder with one .env file and one tiny helper. Change providers by changing one line, without touching code. Then prove the whole pipe works with a smoke test.

.envllm.pyclaude_llm.pySmoke test
≈ 5 min

The .env file

In plain words

Your code never contains a key. Keys and settings live in .env, which stays on your machine (your .gitignore from Drill 00.3 keeps it out of Git), and python-dotenv loads it when a script starts.

Copy this as .env in genai-labs and fill in your values:

# Copy this file to .env and fill in your values. Never commit .env.

# Which provider llm.py uses: azure | openai | ollama
LLM_PROVIDER=azure

# --- Azure OpenAI in Microsoft Foundry (main track) ---
# Your endpoint + "openai/v1/" at the end
AZURE_OPENAI_BASE_URL=https://<resource-name>.openai.azure.com/openai/v1/
AZURE_OPENAI_API_KEY=<paste key from the Foundry portal>
AZURE_OPENAI_DEPLOYMENT=chat

# --- OpenAI (optional) ---
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4-mini

# --- Ollama, local and free (optional) ---
OLLAMA_MODEL=llama3.2

# --- Anthropic Claude (optional, used in "Open alternative" boxes) ---
ANTHROPIC_API_KEY=

# --- Cost meter (USD per 1M tokens; check your model's price list) ---
PRICE_IN_PER_M=0.40
PRICE_OUT_PER_M=1.60

# --- Model comparison drill (optional) ---
COMPARE_DEPLOYMENT=
COMPARE_WITH_OLLAMA=0
Common trap

Someone always pushes .env to a public repo "just for a minute". Automated scanners find leaked keys within minutes. If it happens, regenerate the key in the portal immediately; deleting the commit isn't enough.

The shared helpers

This is the only file that knows which provider you use. Every drill just does from llm import get_client, MODEL.

"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "azure").lower()


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")

Claude gets its own helper because it uses Anthropic's SDK. FALLBACK lets the API retry a request on another Claude model automatically if a safety check declines it.

"""Shared helper for the Claude 'Open alternative' boxes (native Anthropic SDK)."""
from anthropic import Anthropic
from dotenv import load_dotenv

load_dotenv()

client = Anthropic()  # reads ANTHROPIC_API_KEY
CLAUDE_MODEL = "claude-opus-5-5"

# If a safety check declines a request, let the API retry it on another
# Claude model automatically. Pass these with client.beta.messages.create(...).
FALLBACK = dict(betas=["server-side-fallback-2026-07-01"], fallbacks="default")


def text_of(response) -> str:
    """Join the text blocks of a Claude response (it can also contain other block types)."""
    if response.stop_reason == "refusal":
        return "[The model declined this request.]"
    return "".join(b.text for b in response.content if b.type == "text")
Traditional developer view

"Why a helper for three lines? I'll create the client in each script."

GenAI developer view

"Providers, models and endpoints change every few months. One seam means swapping a model is a config change, not a code hunt. It's the tiny ancestor of the LLM gateway in Module 08."

Smoke test

Drill 00.4

Prove the pipe works

~5 minAzure OpenAIPython

Goal: one successful call from your laptop to your model, with a token count.

  1. Run

    Create and run the smoke test

    """Smoke test: prove the pipe from your laptop to the model works."""
from llm import get_client, MODEL, PROVIDER

client = get_client()
response = client.chat.completions.create(
    model=MODEL,
    messages=[{"role": "user", "content": "Greet a developer starting a GenAI course, in one sentence."}],
)

print(f"[{PROVIDER} · {MODEL}]")
print(response.choices[0].message.content)
print("tokens:", response.usage.prompt_tokens, "in /", response.usage.completion_tokens, "out")

    [azure · chat]
Welcome aboard! You're about to turn "what if" into working code, one prompt at a time.

  2. Ask AI

    Let your assistant explain the helper

    Explain #llm.py to me line by line as if I'm new to Python packages and environment variables.
Then tell me exactly which lines in .env it reads for each LLM_PROVIDER value.
Don't change any files.

    What you should get: an explanation that mentions load_dotenv(), the three providers, and that on Azure MODEL is the deployment name. (In Claude Code or Codex, use @llm.py instead of #llm.py.)

  3. Verify
    • The script printed a greeting and a token count.
    • Change LLM_PROVIDER to ollama (if installed) and run again: the provider in brackets changes, the code doesn't.
    • Optional Claude check: run the script below.
    """Smoke test for the Claude track."""
from claude_llm import client, CLAUDE_MODEL, FALLBACK, text_of

response = client.beta.messages.create(
    model=CLAUDE_MODEL,
    max_tokens=4000,
    system="You are a friendly technical trainer.",
    messages=[{"role": "user", "content": "Greet a developer starting a GenAI course, in one sentence."}],
    **FALLBACK,
)
print(text_of(response))
print("tokens:", response.usage.input_tokens, "in /", response.usage.output_tokens, "out")
Takeaway

If lab00_hello.py prints a greeting and a token count, you're ready for every drill in Part I. If not, the troubleshooting page covers the usual causes.
