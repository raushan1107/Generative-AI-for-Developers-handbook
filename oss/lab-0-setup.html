Lab 0 · Set Up Your Open-Source Lab Environment

In this lab you install everything the course needs to run on free, open-source models, on your own computer: Python, VS Code, Ollama and three models. Then you create the project folder, configure it, and run a check that proves every piece works. Do this once, before the first day.

Python + VS CodeOllamaOpen models.env≈ 30–60 min
Estimated time: 30–60 minutes (mostly downloads)

Lab overview

ObjectivesInstall Python, VS Code and Ollama · download a chat model and an embedding model · create the lab project with a virtual environment · configure .env · verify everything with a check script
PrerequisitesA computer with 8 GB of RAM or more (16 GB recommended) and about 10 GB of free disk space · administrator rights to install software · an internet connection
You finish withA folder oss-genai-labs and a check that prints All checks passed

Exercise 1 · Install the tools

Task 1: Install Python

  1. Open a terminal (Windows: Terminal or PowerShell; macOS: Terminal; Linux: your terminal) and check whether Python 3.10 or later is installed: 
    $ python --version
    On macOS and Linux, try python3 --version if python isn't found. If you see Python 3.10 or higher, skip to Task 2.
  2. Otherwise install Python 3.12 from python.org/downloads.
    • Windows: run the installer and tick Add python.exe to PATH on the first screen, then select Install Now.
    • macOS: run the .pkg installer. Use python3 and pip3 in the commands below.
    • Linux (Ubuntu/Debian): sudo apt install python3 python3-venv python3-pip
  3. Close and reopen the terminal, then run python --version again. Expected: Python 3.12.x (any 3.10 or later works).

Task 2: Install VS Code

  1. Download and install Visual Studio Code from code.visualstudio.com.
  2. Open VS Code, select the Extensions view (Ctrl+Shift+X, or ⌘+Shift+X on macOS), search for Python and install the extension published by Microsoft.
  3. Optional: install an AI coding assistant (GitHub Copilot, Claude Code or Codex). The labs don't require one.

Task 3: Install Ollama

Ollama downloads and runs open-source models on your computer and serves them on http://localhost:11434.

  1. Go to ollama.com/download and install it for your system:
    • Windows: download and run OllamaSetup.exe. When it finishes, Ollama runs in the background; you'll see its icon in the system tray.
    • macOS: download the app, move it to Applications and open it once. It runs in the menu bar.
    • Linux: run curl -fsSL https://ollama.com/install.sh | sh
  2. Open a new terminal and check the installation: 
    $ ollama --version
    Expected (your version number will differ) 
    ollama version is 0.40.2
  3. Open http://localhost:11434 in your browser. Expected: the text Ollama is running.
Checkpoint

Python, VS Code and Ollama are installed, and http://localhost:11434 says Ollama is running.

Exercise 2 · Download open models

Task 1: Pull the models

  1. Download the chat model (Meta's Llama 3.2, 3 billion parameters, about 2 GB): 
    $ ollama pull llama3.2
    You'll see download progress bars, then success.
  2. Download the embedding model used in Labs 2 and 3 (about 270 MB): 
    $ ollama pull nomic-embed-text
  3. Only if your computer has 16 GB of RAM or more: download a stronger model for Lab 3's agent (Alibaba's Qwen 2.5, 7 billion parameters, about 4.7 GB): 
    $ ollama pull qwen2.5:7b
  4. List what you have: 
    $ ollama list
    Expected (IDs and dates will differ) 
    NAME                       ID              SIZE      MODIFIED
qwen2.5:7b                 845dbda0ea48    4.7 GB    22 minutes ago
llama3.2:latest            a80c4f17acd5    2.0 GB    About an hour ago
nomic-embed-text:latest    0a109f422b47    274 MB    25 hours ago

Task 2: Talk to a model in the terminal

  1. Start an interactive chat: 
    $ ollama run llama3.2
  2. At the >>> prompt, type Explain what a token is in one sentence. and press Enter. The first answer takes longer while the model loads into memory.
  3. Type /bye to leave. Ollama keeps running in the background.
Checkpoint

ollama list shows llama3.2 and nomic-embed-text, and the model answered in the terminal.

Exercise 3 · Create the lab project

Task 1: Create the folder and the virtual environment

  1. Create a folder named oss-genai-labs (for example in your Documents folder) and open it in VS Code: File › Open Folder…
  2. Open VS Code's terminal: Terminal › New Terminal. Create and activate a virtual environment, an isolated set of Python packages for this project: 
    # Windows (PowerShell)
$ python -m venv .venv
$ .venv\Scripts\Activate.ps1
# macOS / Linux
$ python3 -m venv .venv
$ source .venv/bin/activate
    Your prompt now starts with (.venv). If PowerShell refuses to run the script, run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once and try again.
  3. If VS Code asks whether to use the new environment for the workspace, select Yes.

Task 2: Install the packages

  1. Create a file requirements.txt in the folder with this content: 
    openai
python-dotenv
pydantic
tiktoken
numpy
rank_bm25
pytest
  2. Install them: 
    $ pip install -r requirements.txt
    Expected: the last line starts with Successfully installed.

Task 3: Copy the lab data

  1. Copy the data folder from code/oss-labs/data in the handbook into your project. It holds the fictional TrainCrest course catalogue, ten help-centre articles and three internal staff documents used in Labs 2 and 3.
  2. Your folder now looks like this: 
    oss-genai-labs/
├── .venv/
├── data/
│   ├── courses.json
│   ├── help/          10 help-centre articles (.md)
│   └── internal/      3 staff documents (.md, .txt, .csv)
└── requirements.txt

Exercise 4 · Configure settings and keys

Settings live in a file named .env, never in code, so you can change models or providers without editing programs, and secrets never end up in files you share.

Task 1: Create .env

  1. Create a file named .env (with the leading dot) in the project folder and paste: 
    # Copy this file to .env (same folder). Never share or commit .env.

# ---- Option A (default): Ollama on this computer -------------------------------
# No account and no key. Ollama doesn't check the key; "ollama" is just a placeholder
# because the OpenAI library requires some value.
LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
CHAT_MODEL=llama3.2
# Tool calling and agents (Lab 2 exercise 2, Lab 3) work much better with a 7B model, if you have 16 GB of RAM:
#   ollama pull qwen2.5:7b   and then set   AGENT_MODEL=qwen2.5:7b
AGENT_MODEL=

# Embeddings (Labs 2 and 3) always come from Ollama.
EMBED_BASE_URL=http://localhost:11434/v1
EMBED_MODEL=nomic-embed-text

# ---- Option B: hosted open models with a free key (only if Option A is too slow) ----
# Replace the three LLM lines above with ONE of these, and paste your own key.
# Groq (console.groq.com > API Keys):
#   LLM_BASE_URL=https://api.groq.com/openai/v1
#   LLM_API_KEY=gsk_your_key_here
#   CHAT_MODEL=llama-3.1-8b-instant
# OpenRouter (openrouter.ai > Keys); pick a model whose id ends in ":free" on openrouter.ai/models:
#   LLM_BASE_URL=https://openrouter.ai/api/v1
#   LLM_API_KEY=sk-or-your_key_here
#   CHAT_MODEL=<model id ending in :free>
  2. Read the comments. With Ollama (Option A) there is no key to get: Ollama runs on your computer and doesn't check keys. The OpenAI Python library always sends one, so LLM_API_KEY=ollama is just a placeholder.
  3. If you pulled qwen2.5:7b, set AGENT_MODEL=qwen2.5:7b. Otherwise leave it empty: the agent uses CHAT_MODEL.

Task 2: Create the shared client

  1. Create client.py. Every lab program imports its settings and client from here: 
    """Shared helper for every open-source lab: OpenAI-compatible clients for open models.

Option A (default): Ollama on your own computer. Free, private, no key. Ollama ignores the API key,
but the OpenAI library insists on one, so .env holds the placeholder "ollama".
Option B: a hosted provider of open models, with a free key, if your computer is too slow.
Change LLM_BASE_URL, LLM_API_KEY and CHAT_MODEL in .env; nothing else changes.
Embeddings always come from Ollama in these labs (EMBED_BASE_URL)."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

BASE_URL = os.getenv("LLM_BASE_URL", "http://localhost:11434/v1")
API_KEY = os.getenv("LLM_API_KEY", "ollama")
CHAT_MODEL = os.getenv("CHAT_MODEL", "llama3.2")
AGENT_MODEL = os.getenv("AGENT_MODEL") or CHAT_MODEL        # for tool calling and agents (Labs 2 and 3)
EMBED_BASE_URL = os.getenv("EMBED_BASE_URL", "http://localhost:11434/v1")
EMBED_MODEL = os.getenv("EMBED_MODEL", "nomic-embed-text")


def get_client() -> OpenAI:
    return OpenAI(base_url=BASE_URL, api_key=API_KEY)


def get_embed_client() -> OpenAI:
    return OpenAI(base_url=EMBED_BASE_URL, api_key="ollama")

Task 3 (optional): Use a hosted open model with a free API key

Only if Option A is too slow on your computer (more than about a minute per answer). Hosted providers run the same kind of open models on fast hardware; they need an account and an API key, and your prompts are sent to them, so never paste personal or confidential data.

  1. Create a free account with an OpenAI-compatible provider of open models, for example Groq (console.groq.com) or OpenRouter (openrouter.ai).
  2. Create a key: Groq: API Keys › Create API Key; OpenRouter: Keys › Create Key. Copy it immediately: it's shown only once.
  3. In .env, replace the three LLM_/CHAT_MODEL lines with the provider's block from the comments, and paste your key after LLM_API_KEY=. Check the provider's model list for a current model name; free tiers and model names change.
  4. Keep EMBED_BASE_URL pointing at Ollama: nomic-embed-text is small and runs on any laptop.
  5. Treat the key like a password: don't paste it into chats, screenshots or code, and delete it in the provider's console when the course ends.
Checkpoint

.env and client.py exist in your project folder, and you know which option (A or B) you're using.

Exercise 5 · Check everything

  1. Create lab0_check.py: 
    """Lab 0: check your open-source lab environment. One line per check; fix any FAIL before Lab 1.
Run:  python lab0_check.py"""
import json
import sys
import time
import urllib.request

from client import BASE_URL, CHAT_MODEL, EMBED_BASE_URL, EMBED_MODEL, get_client, get_embed_client

OLLAMA = EMBED_BASE_URL.removesuffix("/v1")
failures = 0


def check(name, fn):
    global failures
    try:
        print(f"[ OK ] {name}: {fn()}")
    except Exception as e:
        failures += 1
        print(f"[FAIL] {name}: {type(e).__name__}: {e}")


def python_version():
    if sys.version_info < (3, 10):
        raise RuntimeError(f"Python {sys.version.split()[0]} is too old; install 3.10 or later")
    return sys.version.split()[0]


def ollama_running():
    with urllib.request.urlopen(f"{OLLAMA}/api/version", timeout=5) as r:
        return "Ollama " + json.load(r)["version"]


def models_pulled():
    with urllib.request.urlopen(f"{OLLAMA}/api/tags", timeout=5) as r:
        names = {m["name"] for m in json.load(r)["models"]}
    wanted = [EMBED_MODEL] + ([CHAT_MODEL] if "localhost" in BASE_URL else [])
    missing = [m for m in wanted if m not in names and f"{m}:latest" not in names]
    if missing:
        raise RuntimeError("not pulled yet: " + ", ".join(missing) + "  ->  run: ollama pull <name>")
    return ", ".join(sorted(names))


def chat_works():
    start = time.perf_counter()
    r = get_client().chat.completions.create(
        model=CHAT_MODEL, messages=[{"role": "user", "content": "Reply with exactly one word: ready"}])
    return f"{CHAT_MODEL} says {r.choices[0].message.content.strip()!r} in {time.perf_counter() - start:.1f}s"


def embeddings_work():
    r = get_embed_client().embeddings.create(model=EMBED_MODEL, input=["hello world"])
    return f"{EMBED_MODEL} returns {len(r.data[0].embedding)} numbers per text"


check("Python", python_version)
check("Ollama server", ollama_running)
check("Models", models_pulled)
check("Chat model", chat_works)
check("Embedding model", embeddings_work)
print("\nAll checks passed. You're ready for Lab 1." if not failures else f"\n{failures} check(s) failed. "
      "See Troubleshooting in Lab 0.")
  2. Run it: 
    $ python lab0_check.py
    Real output on a laptop without a GPU (your times and model list will differ) 
    [ OK ] Python: 3.10.0
[ OK ] Ollama server: Ollama 0.40.2
[ OK ] Models: llama3.2:latest, nomic-embed-text:latest, qwen2.5:1.5b, qwen2.5:7b
[ OK ] Chat model: llama3.2 says 'Yes' in 43.7s
[ OK ] Embedding model: nomic-embed-text returns 768 numbers per text

All checks passed. You're ready for Lab 1.
    Notice the model said Yes although it was asked to reply ready: small models don't always follow instructions exactly. You'll see that again, and learn to handle it. The first call is slow because the model is loaded into memory; later calls are faster.
Checkpoint

All five checks are [ OK ]. You're ready for Lab 1.

Troubleshooting

SymptomFix
python or ollama: command not foundClose and reopen the terminal (the installer changed PATH). On Windows, re-run the Python installer with Add python.exe to PATH ticked.
[FAIL] Ollama server: URLError ... refusedOllama isn't running. Windows/macOS: start the Ollama app. Linux: ollama serve in another terminal.
not pulled yet: llama3.2Run ollama pull llama3.2, then check again. Names must match .env exactly.
ModuleNotFoundError: No module named 'openai'The virtual environment isn't active, or packages aren't installed: activate .venv and run pip install -r requirements.txt.
Answers take minutes, or the computer freezesThe model is too big for your RAM. Use llama3.2, close other apps, or use Option B. ollama ps shows what's loaded.
Downloads fail on a company networkA proxy may block them. Ask IT, or download at home. Ollama honours the HTTPS_PROXY environment variable.
Option B: AuthenticationError (401)The key is wrong, has spaces around it, or was deleted. Create a new one and paste it again.
Option B: NotFoundError for the modelThe model name isn't offered (any more). Copy a current name from the provider's model list.

Review

  • Ollama runs open models locally and serves an OpenAI-compatible API on port 11434.
  • You have a chat model (llama3.2) and an embedding model (nomic-embed-text).
  • Settings live in .env; with Ollama the "key" is a placeholder, with a hosted provider it's a secret.
  • client.py gives every lab the same client, so switching provider is a three-line change.
