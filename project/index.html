Traincrest Assist: The Progressive Build

One real application, built one milestone per module. Each milestone applies that module's skills to the same codebase, so by the end of Part V you have a working, tested, deployed GenAI product, and the scars that come with building one.

12 milestones3 availableReference code per milestoneFastAPI · Azure OpenAI

The business problem

TrainCrest· a technical training company (scenario, data and policies are fictional)

TrainCrest runs instructor-led and self-paced courses in cloud, AI, data and security for learners in many countries. Learner support handles about 25,000 requests a month by email and chat, in English, Spanish, Hindi, Arabic, Japanese and more. Common topics: rescheduling, refunds, lab environments, exam vouchers, certificates and accounts. A 35-person team takes 11 hours on average to reply.

Traincrest Assist must answer policy questions correctly, check real enrolments and vouchers, recommend courses, raise and route tickets, hand over to humans safely, and do all that at a predictable cost, with evidence that it's accurate and secure.

Reference code and catching up

Every milestone page shows all the code, and the complete project snapshot for each milestone is in the handbook repository under code/traincrest-assist/m01, m02, m03. If you miss a session, copy the latest snapshot, add your .env, and continue. Each snapshot has been tested against a fake model: streaming, memory, history trimming, friendly errors, triage validation and repair, and the output guard.

In the real world

This is how GenAI products actually get built: a thin end-to-end slice first (Milestone 1), then hardening (2), then making behaviour deliberate and measurable (3), then capabilities (tools, retrieval, agents), then the production disciplines. Teams that start with an impressive agent demo usually end up rebuilding exactly these foundations later.
