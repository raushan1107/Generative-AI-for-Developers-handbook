RR Finance Assist: The Progressive Build

One real application, built one milestone per module. Each milestone applies that module's skills to the same codebase, so by the end of Part V you have a working, tested, deployed GenAI product, and the scars that come with building one.

12 milestones3 availableReference code per milestoneFastAPI · Azure OpenAI

The business problem

RR Finance Bank· a retail bank (the bank, customers, data and policies are fictional; nothing here is financial advice)

RR Finance Bank's contact centre handles about 40,000 customer messages a month by chat, email and the app, in English, Spanish, Arabic, Japanese and more. Common topics: lost and stolen cards, disputed payments, fraud, fees, transfers, loans and online-banking access. Agents search six policy handbooks for every answer, replies vary between agents, and a wrong answer about a fee or a dispute deadline is a compliance issue.

RR Finance Assist must answer policy questions correctly with citations, triage every message so fraud and lost cards reach the right team first, look up products and the customer's own transactions, prepare actions such as freezing a card or opening a dispute for a human to approve, never ask for security details, keep an audit trail, and do all that at a predictable cost, with evidence that it's accurate and secure.

Reference code and catching up

Every milestone page shows all the code, and the complete project snapshot for each milestone is in the handbook repository under code/rrfinance-assist/m01, m02, m03. If you miss a session, copy the latest snapshot, add your .env, and continue. Each snapshot has been tested against a fake model: streaming, memory, history trimming, friendly errors, triage validation and repair, and the output guard.

In the real world

This is how GenAI products actually get built: a thin end-to-end slice first (Milestone 1), then hardening (2), then making behaviour deliberate and measurable (3), then capabilities (tools, retrieval, agents), then the production disciplines. Teams that start with an impressive agent demo usually end up rebuilding exactly these foundations later.
