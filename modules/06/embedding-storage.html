Embedding Generation and Vector Storage

Embedding is the expensive, slow, easy-to-get-wrong step of indexing: one model change and every vector is useless. Done well, it's boring: batched, incremental, recorded in a manifest, and checked on load. You'll build TrainCrest's knowledge index, run it again to see it embed nothing, then edit one document and watch exactly one chunk being re-embedded.

1

Learn

Embed once, store everything you'll need, remember how.

Definition

Embedding generation turns each chunk into a vector with an embedding model, usually in batches. Vector storage keeps each vector together with the chunk's text, id and metadata in a store that supports similarity search and filtering. A RAG index also records how it was built (embedding model, dimensions, chunker version) so incompatible queries or updates are refused.

In plain words

Turn every chunk into numbers, save the numbers next to the words and labels, write down which model and chunker you used, and next time only redo the chunks that changed.

Imagine this

A warehouse. Every item gets a location code (the vector) and a label with what it is and who may collect it (text and metadata). The warehouse logbook says which coding system was used. When a delivery arrives, you shelve only the new and changed items; and if someone changes the coding system, you re-code the whole warehouse rather than mixing two systems on the same shelves.

Embedding generation

  • Batch: one API call can embed many texts (embed.py sends 64 at a time). Fewer round trips, fewer rate-limit hits.
  • Incremental: hash each chunk's text; re-embed only new or changed chunks and delete the removed ones. A nightly job over thousands of pages then costs cents, not dollars.
  • Same model for documents and questions, recorded in the manifest. Some models (for example nomic-embed-text) also recommend different prefixes for documents and queries; follow the model card.
  • Normalise vectors to length 1 so a dot product is the cosine similarity.
  • Retries: embedding APIs rate-limit too. The Module 02 retry rules apply to indexing jobs.

Vector storage: what each record holds

FieldUsed by
vectorSimilarity search
text (with its title header)The prompt: the model reads this, not the vector
id, source, titleCitations, links, logs, incremental updates
audience (or groups, tenant)Permission pre-filter: who may retrieve it
hash, updatedChange detection, freshness

Where to store it: a numpy file is fine for a few thousand chunks on a laptop. For production, use a service with indexes, filters, security and backups: Azure AI Search (vector + keyword + semantic ranking, filters, integrated vectorisation), Azure Cosmos DB or PostgreSQL with pgvector if your data already lives there, or a dedicated vector database. The record shape above stays the same.

In the real world

A team switched embedding deployments from one model to another "for better quality" and re-embedded only new documents. For a week, answers about old policies got worse: old vectors and new query vectors lived in different spaces, and nothing raised an error. A manifest check on load, as in kb_index.py, turns that silent failure into an obvious one. Mature teams build a second index with the new model, compare hit rates on their question set, then switch traffic.

Traditional developer view

"The index is a cache. If something looks wrong, rebuild it."

GenAI developer view

"The index is a versioned data asset. It records the model and chunker that built it, updates incrementally by hash, and refuses to mix incompatible vectors."

Common trap

Storing only vectors and ids, and fetching text from the source system at query time. The source page may have changed since indexing, so the text you send to the model no longer matches the vector that found it, and the citation points to words that aren't there. Store the text you embedded.

Interview cue

"I embed chunks in batches, re-embed only changed chunks using content hashes, store vector, text and metadata together, and keep a manifest of embedding model, dimensions and chunker version, so a mismatch fails loudly instead of degrading results silently."

  1. Run

    The index

    """Module 06 helper: the knowledge index (embedding generation + vector storage).
Embeds chunks in batches, re-embeds only chunks whose text changed, stores each vector with its
text and metadata, and records how the index was built, so a mismatch fails loudly instead of
returning nonsense. Search is hybrid (BM25 + vectors, merged with RRF) with an audience pre-filter."""
import hashlib
import json
import time
from pathlib import Path

import numpy as np

from embed import EMBED_MODEL, embed
from hybrid import bm25_ranking, rrf
from rag_chunks import CHUNKER_VERSION

INDEX_DIR = Path(__file__).parent / "data" / "kb_index"


def text_hash(text: str) -> str:
    return hashlib.sha1(text.encode("utf-8")).hexdigest()[:12]


def unit(v: np.ndarray) -> np.ndarray:
    return v / np.linalg.norm(v, axis=-1, keepdims=True)


class KnowledgeIndex:
    def __init__(self, chunks, vectors, manifest):
        self.chunks, self.vectors, self.manifest = chunks, vectors, manifest

    @classmethod
    def build(cls, chunks, previous=None):
        """Return (index, stats). Vectors of unchanged chunks are reused from `previous`,
        but only if it was built with the same embedding model and chunker."""
        reusable = {}
        if previous and previous.manifest["embed_model"] == EMBED_MODEL \
                and previous.manifest["chunker"] == CHUNKER_VERSION:
            reusable = {c["id"]: (c["hash"], previous.vectors[i]) for i, c in enumerate(previous.chunks)}
        chunks = [c | {"hash": text_hash(c["text"])} for c in chunks]
        stats = {"new": 0, "changed": 0, "unchanged": 0, "removed": len(set(reusable) - {c["id"] for c in chunks})}
        vectors, todo = [None] * len(chunks), []
        for i, c in enumerate(chunks):
            old = reusable.get(c["id"])
            if old and old[0] == c["hash"]:
                vectors[i] = old[1]
                stats["unchanged"] += 1
            else:
                todo.append(i)
                stats["changed" if old else "new"] += 1
        if todo:                                           # one batched call per 64 texts (see embed.py)
            for i, v in zip(todo, unit(embed([chunks[i]["text"] for i in todo]))):
                vectors[i] = v
        matrix = np.array(vectors, dtype=np.float32)
        manifest = {"embed_model": EMBED_MODEL, "dimensions": int(matrix.shape[1]), "chunker": CHUNKER_VERSION,
                    "chunks": len(chunks), "built": time.strftime("%Y-%m-%d %H:%M:%S")}
        return cls(chunks, matrix, manifest), stats

    def save(self, folder=INDEX_DIR):
        folder = Path(folder)
        folder.mkdir(parents=True, exist_ok=True)
        np.save(folder / "vectors.npy", self.vectors)
        (folder / "chunks.json").write_text(json.dumps(self.chunks, ensure_ascii=False, indent=1), encoding="utf-8")
        (folder / "manifest.json").write_text(json.dumps(self.manifest, indent=1), encoding="utf-8")

    @classmethod
    def load(cls, folder=INDEX_DIR, check_model=True):
        folder = Path(folder)
        manifest = json.loads((folder / "manifest.json").read_text(encoding="utf-8"))
        if check_model and manifest["embed_model"] != EMBED_MODEL:
            raise RuntimeError(f"index built with {manifest['embed_model']}, but EMBED_MODEL is {EMBED_MODEL}: rebuild it")
        chunks = json.loads((folder / "chunks.json").read_text(encoding="utf-8"))
        return cls(chunks, np.load(folder / "vectors.npy"), manifest)

    def search(self, query, k=4, audience=("public",), min_score=None):
        """Top k chunks the audience may see, best first. Each hit has 'score' (cosine with the query).
        With min_score, chunks below it are dropped, so an off-topic question can return nothing."""
        allowed = [i for i, c in enumerate(self.chunks) if c["audience"] in audience]   # permission pre-filter
        if not allowed:
            return []
        cosine = self.vectors[allowed] @ unit(embed([query])[0])
        vector_rank = [allowed[j] for j in np.argsort(-cosine)]
        keyword_rank = [allowed[j] for j in bm25_ranking(query, [self.chunks[i]["text"] for i in allowed])]
        score_of = dict(zip(allowed, cosine.tolist()))
        hits = [self.chunks[i] | {"score": round(score_of[i], 3)} for i in rrf([keyword_rank, vector_rank])]
        if min_score is not None:
            hits = [h for h in hits if h["score"] >= min_score]
        return hits[:k]


def load_or_build():
    """The index the later drills use. Built from the knowledge base on first use, then loaded."""
    try:
        return KnowledgeIndex.load()
    except FileNotFoundError:
        from ingest import load_knowledge_base
        from rag_chunks import chunk_all
        index, _ = KnowledgeIndex.build(chunk_all(load_knowledge_base()))
        index.save()
        return index

    Test it offline with a fake embedding function

    """Drill 06.5: the knowledge index, offline, with a fake embedding function.
Run:  pytest -q test_kb_index.py"""
import re
import zlib

import numpy as np
import pytest

import kb_index
from kb_index import KnowledgeIndex

CALLS = []


def fake_embed(texts):
    """Hashed bag of words: texts sharing words get similar vectors. Deterministic and free."""
    CALLS.append(len(texts))
    out = np.zeros((len(texts), 64), dtype=np.float32)
    for row, text in enumerate(texts):
        for word in re.findall(r"[a-z0-9]+", text.lower()):
            out[row, zlib.crc32(word.encode()) % 64] += 1
        out[row, 0] += 0.01
    return out


@pytest.fixture(autouse=True)
def offline(monkeypatch):
    monkeypatch.setattr(kb_index, "embed", fake_embed)
    CALLS.clear()


def chunks():
    return [
        {"id": "refunds#1", "title": "Refunds > How much", "text": "refund 50 percent cancel early", "audience": "public"},
        {"id": "labs#1", "title": "Labs > Extensions", "text": "lab extension 49 dollars 14 days", "audience": "public"},
        {"id": "approvals#1", "title": "Approvals > Limits", "text": "refund exception approval team lead",
         "audience": "staff"},
    ]


def test_only_new_and_changed_chunks_are_embedded():
    first, stats = KnowledgeIndex.build(chunks())
    assert stats == {"new": 3, "changed": 0, "unchanged": 0, "removed": 0} and CALLS == [3]
    edited = chunks()[:2]
    edited[1] = edited[1] | {"text": "lab extension 59 dollars 14 days"}
    second, stats = KnowledgeIndex.build(edited, previous=first)
    assert stats == {"new": 0, "changed": 1, "unchanged": 1, "removed": 1} and CALLS == [3, 1]
    assert np.allclose(second.vectors[0], first.vectors[0])


def test_a_different_embedding_model_means_a_full_rebuild(monkeypatch):
    first, _ = KnowledgeIndex.build(chunks())
    monkeypatch.setattr(kb_index, "EMBED_MODEL", "another-model")
    _, stats = KnowledgeIndex.build(chunks(), previous=first)
    assert stats["new"] == 3


def test_audience_is_a_pre_filter():
    index, _ = KnowledgeIndex.build(chunks())
    public = index.search("refund exception approval", k=3)
    assert "approvals#1" not in [h["id"] for h in public]
    assert index.search("refund exception approval", k=1, audience=("public", "staff"))[0]["id"] == "approvals#1"


def test_relevance_floor_can_return_nothing():
    index, _ = KnowledgeIndex.build(chunks())
    assert index.search("lab extension", min_score=0.2)[0]["id"] == "labs#1"
    assert index.search("capital of france", min_score=0.5) == []


def test_save_load_and_model_check(tmp_path, monkeypatch):
    index, _ = KnowledgeIndex.build(chunks())
    index.save(tmp_path)
    again = KnowledgeIndex.load(tmp_path)
    assert again.manifest["chunks"] == 3 and again.chunks[0]["hash"] == index.chunks[0]["hash"]
    monkeypatch.setattr(kb_index, "EMBED_MODEL", "another-model")
    with pytest.raises(RuntimeError, match="rebuild"):
        KnowledgeIndex.load(tmp_path)

3

Check

Embeddings and storage.

1. A nightly job re-embeds all 50,000 chunks although only 30 pages changed. What do you add?

A content hash per chunk stored in the index; compare on each run and embed only new or changed chunks, deleting removed ones. The job's cost and time then follow the size of the change, not of the corpus.

2. Why store the chunk's text in the vector store when you could look it up in the source system?

So the text sent to the model is exactly the text that was embedded and cited. The source may have changed since indexing; and fetching from it adds latency and another failure point.

3. What belongs in an index manifest, and what does each field protect against?

Embedding model and dimensions (mixing vector spaces), chunker version (ids and texts that no longer match the code), build time and chunk count (stale or partial indexes).

Takeaway

Batch, embed only what changed, store vector + text + metadata together, and record the model and chunker in a manifest that's checked on load.
