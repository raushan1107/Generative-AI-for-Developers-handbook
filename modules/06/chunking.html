Text Chunking for RAG

In Module 05 you chose chunks that search well. In RAG every retrieved chunk is also pasted into a prompt, so chunks must be findable, self-contained and affordable. And a chunker can lose text without any error: Milestone 5's dropped every article's introduction, and nobody noticed until a question needed one.

1

Learn

Chunks are what the model reads.

Definition

Text chunking splits each document into passages that are embedded, retrieved and inserted into prompts individually. For RAG a good chunk is retrievable (one focused idea), self-contained (understandable without its neighbours), complete (no part of the document is lost), and traceable (an id and source for citations).

In plain words

Cut each document into pieces small enough to find precisely and cheap to send, big enough to answer from, each labelled with where it came from. And make sure no text falls through the gaps.

Imagine this

A tailor cutting a pattern from cloth. Pieces must follow the seams (the document's sections), each piece is labelled so it can be put back together (ids and sources), and an experienced tailor checks the offcuts: a piece forgotten on the table means a garment with a hole.

What changes when chunks feed a prompt

ConcernSearch only (Module 05)RAG (this module)
SizeWhatever ranks bestAlso tokens sent: top-k × chunk size is paid on every question
CompletenessA missing paragraph is a missed search resultA missing paragraph is a fact the model can never use; it will say "not found" or guess
Context headerHelps rankingAlso tells the model what it's reading ("Labs › How long labs stay open")
IdentityAn id for the result listA stable id and source for citations, and an audience for filtering
Long sectionsSplit anywhereSplit at paragraph breaks, repeating the header, so each piece still makes sense alone
  • Small to retrieve, big to read is a common upgrade: index small chunks for precise matching, but send the parent section (or neighbours) to the model. Use it when answers need surrounding context.
  • Tables and lists should stay whole inside one chunk; a price table split in half produces wrong answers with real-looking citations.
  • Version your chunker. Changing it changes every chunk id and vector, so the index must be rebuilt (Milestone 6 records headings-v2 and refuses older indexes).
In the real world

A common production bug: a PDF extractor puts each page's header and footer into the text, and a fixed-size chunker splits mid-table. The bot then answers "the fee is $" with a citation. Teams catch these by sampling chunks by eye after every chunker change and by keeping a small set of questions whose answers sit in awkward places (intros, tables, footnotes), exactly like the five intro questions in Drill 06.4.

Traditional developer view

"Chunk size is a tuning knob: try 500, try 1,000, pick one."

GenAI developer view

"Chunking decides what the model can ever know. I check that no text is lost, measure recall and tokens sent on questions that hit awkward places, and version the chunker like code."

Common trap

Trusting a hit-rate table built only from "easy" questions. Milestone 5's chunker scored 20/20 in Module 05 and still dropped seven article introductions. Add questions whose answers sit in introductions, tables and footnotes, or you won't see the gap.

Interview cue

"For RAG I chunk along document structure with a title header on every chunk, split oversized sections at paragraph boundaries, keep tables whole, carry ids and sources for citations, and choose settings by measuring recall at k together with tokens per prompt."

"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")

Drill 06.4

Chunking for answers: recall and tokens

~20 minAzure OpenAI embeddingsPython

Goal: compare whole articles, Milestone 5's chunks and the new RAG chunker on the 20 help questions plus 5 whose answers sit in introductions, measuring both recall (hit@3) and the tokens each question would send to the model.

  1. Run

    The RAG chunker

    """Module 06 helper: chunking for answers, not just for search.
Milestone 5 cut articles at '## ' headings but dropped the text before the first heading.
Here the intro is kept as an 'Overview' chunk, long sections are split at paragraph breaks
(each piece keeps its 'Title > Section' header), and every chunk carries what citations need."""
import re

from ingest import Doc

CHUNKER_VERSION = "sections-v2"


def sections(doc: Doc):
    """Yield (heading, body) for the intro and each '## ' section."""
    text = re.sub(r"^# .+\n?", "", doc.text, count=1)          # the title goes into every header instead
    intro, *parts = re.split(r"^## ", text, flags=re.M)
    if intro.strip():
        yield "Overview", intro.strip()
    for part in parts:
        heading, _, body = part.partition("\n")
        if body.strip():
            yield heading.strip(), body.strip()


def split_long(body: str, max_chars: int):
    """Split at blank lines (then single lines) so no piece is longer than max_chars, where possible."""
    pieces, current = [], ""
    for para in re.split(r"\n\s*\n|\n(?=- )", body):
        para = para.strip()
        sep = "\n" if para.startswith("- ") else "\n\n"           # keep list items together visually
        if current and len(current) + len(para) + len(sep) > max_chars:
            pieces.append(current)
            current = para
        else:
            current = f"{current}{sep}{para}" if current else para
    return pieces + ([current] if current else [])


def chunk(doc: Doc, max_chars: int = 900):
    """Chunks as dicts: id like 'refunds-and-cancellations#2', the header, text, source and audience."""
    chunks = []
    for heading, body in sections(doc):
        for piece in split_long(body, max_chars):
            n = len(chunks) + 1
            chunks.append({"id": f"{doc.id}#{n}", "doc_id": doc.id, "title": f"{doc.title} > {heading}",
                           "text": f"{doc.title} > {heading}\n{piece}", "source": doc.source,
                           "audience": doc.audience})
    return chunks


def chunk_all(docs, max_chars: int = 900):
    return [c for d in docs for c in chunk(d, max_chars)]

  2. Run

    Measure four strategies

    """Drill 06.4: chunking for answers. Retrieval must find the answer (hit@3), but everything
retrieved is also sent to the model, so context size is cost and noise. Measure both."""
import json
import re

from ingest import DATA, load_folder
from kb_index import KnowledgeIndex
from rag_chunks import chunk_all
from rag_prompt import count_tokens

QUESTIONS = json.loads((DATA / "help_questions.json").read_text(encoding="utf-8"))
# Five more whose answers sit in an article's introduction, before its first '## ' heading.
INTRO_QUESTIONS = [
    {"question": "For a self-paced course, which day counts as the start date?",
     "source": "refunds-and-cancellations", "must_contain": "the day your access begins"},
    {"question": "Which certification courses come with an exam voucher?", "source": "exam-vouchers",
     "must_contain": "AZ-900, AZ-104 and AI-102"},
    {"question": "Is the content different in the self-paced version?", "source": "course-formats",
     "must_contain": "The content is the same"},
    {"question": "Do I need my own Azure subscription for the labs?", "source": "labs-and-sandboxes",
     "must_contain": "without using your own subscription"},
    {"question": "Can I share my certificate on LinkedIn?", "source": "certificates",
     "must_contain": "share on professional networks"},
]
docs, _ = load_folder(DATA / "help", "public")


def milestone5_chunks(docs):
    """Milestone 5's chunker: one chunk per '## ' section, text before the first heading dropped."""
    out = []
    for d in docs:
        for n, part in enumerate(re.split(r"^## ", d.text, flags=re.M)[1:], 1):
            heading, _, body = part.partition("\n")
            out.append({"id": f"{d.id}#{n}", "doc_id": d.id, "title": f"{d.title} > {heading}", "source": d.source,
                        "text": f"{d.title} > {heading}\n{body.strip()}", "audience": "public"})
    return out


def whole_documents(docs):
    return [{"id": d.id, "doc_id": d.id, "title": d.title, "text": d.text, "source": d.source, "audience": "public"}
            for d in docs]


STRATEGIES = {
    "whole articles": whole_documents(docs),
    "M5 sections (no intros)": milestone5_chunks(docs),
    "sections + intros, max 900": chunk_all(docs, max_chars=900),
    "sections + intros, max 200": chunk_all(docs, max_chars=200),
}
print(f"{'strategy':28} {'chunks':>6} {'hit@3 (20)':>11} {'intro (5)':>10} {'tokens sent':>12}")
for name, chunks in STRATEGIES.items():
    index, _ = KnowledgeIndex.build(chunks)
    scores, tokens = [], 0
    for questions in (QUESTIONS, INTRO_QUESTIONS):
        hits = 0
        for q in questions:
            top = index.search(q["question"], k=3)
            tokens += sum(count_tokens(h["text"]) for h in top)
            hits += any(h["doc_id"] == q["source"] and q["must_contain"] in h["text"] for h in top)
        scores.append(hits)
    asked = len(QUESTIONS) + len(INTRO_QUESTIONS)
    print(f"{name:28} {len(chunks):>6} {scores[0]:>8}/20 {scores[1]:>8}/5 {tokens / asked:>8.0f} avg")

  3. Think

    Read the table

    1. Milestone 5's chunks score 0/5 on intro questions. Why didn't Module 05's measurements show this?
    2. Whole articles score almost as well. Why not just retrieve whole articles?
    3. "Max 200" sends the fewest tokens. What could go wrong with even smaller chunks?
    Compare with my answers
    1. None of the 20 original questions had its answer in an introduction, so the gap was invisible. A metric is only as good as the questions behind it.
    2. Each question would send about 600 tokens instead of about 150: four times the input cost on every message, and the answer is buried in text about other topics, which makes the model more likely to miss it or mix rules. It also missed one intro answer: a whole article's vector is a blur.
    3. Facts get separated from their conditions ("$50 fee" in one chunk, "within 7 days of the start" in another), lists are split, and the model gets fragments. Keep "max 900" (sections stay whole on this help centre) unless measurements on harder questions say otherwise.

Stretch: add a sixth intro-style question of your own to INTRO_QUESTIONS (look for a fact in an article's first paragraph) and confirm the result pattern holds.

3

Check

Chunking for RAG.

1. How can a chunker lose text without any error, and how do you catch it?

By splitting on headings and keeping only what follows them (text before the first heading, or between unusual markup, is dropped). Catch it with a test that every word of a document appears in some chunk, and with questions whose answers sit in awkward places.

2. Why does a RAG chunk carry an id like refunds-and-cancellations#2?

So an answer's citation can point to exactly one passage, the UI can link to it, logs can show what was retrieved, and incremental re-indexing can tell which chunk changed.

3. Retrieving k = 4 chunks of about 150 tokens versus k = 4 whole articles of about 600: what's the difference in input tokens per question, before the system prompt?

About 600 versus about 2,400 tokens: four times the context cost on every question, for no gain in recall here.

Takeaway

RAG chunks must be findable, self-contained, complete and traceable. Measure recall and tokens together, on questions that probe the awkward corners.
