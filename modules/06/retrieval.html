Retrieval

Retrieval decides what the model is allowed to know for this question. Top k always returns k chunks, even for 'Can I bring my dog?'. Follow-ups like 'and after that, how much?' mean nothing to an index. You'll calibrate a relevance floor on real scores and fix follow-ups by rewriting them first.

1Learn→2Do→3CheckLearn 12 min · Do 30 min
1

Learn

The right few passages, for the right person, or none.

Definition

Retrieval is the query-time step that selects the chunks a model will see: it turns the user's message into a search query, searches the index (vector, keyword or hybrid) within what that user may see, keeps the top k results above a relevance threshold, and optionally reranks or diversifies them.

In plain words

Work out what's really being asked, search only what this person is allowed to read, keep the few best matches, and if nothing is good enough, return nothing rather than something.

Imagine this

A reference librarian. They turn "and the other one?" into the actual title from your earlier conversation, only fetch books from shelves you have a pass for, bring you three good books rather than the ten nearest on the shelf, and when the library has nothing on dog-friendly classrooms, they say so instead of handing you a book about payments.

The levers

LeverWhat it fixesCost
k (how many chunks)Answers needing two sections (k of 3 to 5 is typical)Tokens and noise grow with k
Relevance floorOff-topic questions retrieving unrelated chunksCalibrate per embedding model; too high drops real questions
Permission pre-filterUsers seeing documents they may not readNeeds audience or group metadata from ingestion
Hybrid searchCodes and names (LAB-503, AZ-104) plus paraphrasesNone worth mentioning (Module 05)
Query rewritingFollow-ups, typos, other languages, chatty messagesOne small model call (or free, when the model writes a tool query)
RerankingThe best chunk ranked fourth instead of firstA reranker call; Azure AI Search's semantic ranker does it on the service
Diversity (for example MMR)Three near-identical chunks crowding out a second topicA little extra computation
In the real world

Production RAG systems on Azure AI Search commonly run hybrid queries with the semantic ranker on top, filter by the user's group ids (security trimming), and keep a minimum reranker score below which the bot says it can't find an answer. Chat products also rewrite every follow-up into a standalone query, which is why their logs show search queries the user never typed.

Traditional developer view

"Search returns results sorted by score. Take the first few."

GenAI developer view

"Retrieval is the model's whole world for this question. I rewrite the query, filter by permission before ranking, accept zero results, and calibrate thresholds on labelled questions for each embedding model."

Common trap

Filtering by permission after retrieval ("get the top 5, then drop what the user can't see"). Sometimes nothing is left; worse, if someone forgets the post-filter in one code path, restricted text reaches the prompt. Filter inside the search, as kb_index.search(..., audience=...) does.

Interview cue

"I retrieve with hybrid search, pre-filtered by the user's permissions, keep the top k above a calibrated relevance threshold, rewrite conversational follow-ups into standalone queries, and add a reranker when the right chunk is retrieved but not ranked first."

Do

A floor from real scores, and follow-ups that find things.

llm.py
"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 06.6

Calibrate a relevance floor

~15 minAzure OpenAI embeddingsPython

Goal: compare the best similarity score for 20 answerable questions and 8 off-topic ones, then choose a floor for your embedding model.

  1. Run

    Scores for answerable and off-topic questions

    """Drill 06.6: calibrate a relevance floor. Top-k always returns k chunks, even for questions your
documents can't answer. Compare the best score for answerable and off-topic questions, then pick a
floor that keeps the first and drops the second."""
import json

from ingest import DATA
from kb_index import load_or_build

IN_SCOPE = [q["question"] for q in json.loads((DATA / "help_questions.json").read_text(encoding="utf-8"))]
OFF_TOPIC = [
    "What is the capital of France?",
    "Can you recommend a good laptop for programming?",
    "Write me a poem about the sea",
    "How do I reverse a list in Python?",
    "What's the weather like in Toronto tomorrow?",
    "Do you sell gift cards?",
    "Is TrainCrest hiring trainers?",
    "Can I bring my dog to a classroom course?",
]

index = load_or_build()


def best(question):
    return index.search(question, k=1)[0]


inside = sorted(((best(q)["score"], q) for q in IN_SCOPE))
outside = sorted(((best(q)["score"], q) for q in OFF_TOPIC), reverse=True)
print("Lowest in-scope scores:")
for score, q in inside[:4]:
    print(f"  {score:.3f}  {q}")
print("Highest off-topic scores:")
for score, q in outside[:4]:
    print(f"  {score:.3f}  {q}")

print(f"\n{'floor':>6} {'answerable kept':>16} {'off-topic dropped':>18}")
for floor in (0.40, 0.45, 0.50, 0.55, 0.60):
    kept = sum(s >= floor for s, _ in inside)
    dropped = sum(s < floor for s, _ in outside)
    print(f"{floor:>6.2f} {kept:>12}/{len(inside)} {dropped:>14}/{len(outside)}")

  2. Think

    Pick a floor

    1. The dog question (0.686) scores higher than a real question (0.638). What does that tell you about floors?
    2. Which floor would you choose for this model, and what catches the questions it lets through?
    3. Why must you re-run this when you change embedding model?
    Compare with my answers
    1. Similarity measures "about the same kind of thing", not "answerable". A question about bringing a dog to a classroom course is close to the classroom-format section. No floor separates every case; it removes the obvious misses cheaply.
    2. 0.55: it keeps all 20 answerable questions with margin (lowest 0.638) and drops 6 of 8 off-topic ones before any model call. The prompt's "reply NOT_FOUND" rule (topic 7) and the checks in topic 9 handle the rest. rag.py uses 0.55 for nomic-embed-text.
    3. Score ranges are model-specific. text-embedding-3-small puts related texts around 0.4 to 0.7 and unrelated ones around 0.1 to 0.3, so 0.55 would drop real questions there. Calibrate, then set RAG_MIN_SCORE in .env.
Drill 06.7

Rewrite follow-ups before searching

~15 minAzure OpenAIPython

Goal: see a follow-up message retrieve the wrong section, then fix it by asking the model for a standalone question first.

  1. Run

    Raw follow-up vs rewritten question

    """Drill 06.7: rewrite follow-up questions before retrieving.
'And how much is it after that?' means nothing to a search index. Ask the model to turn the last
message into a standalone question using the conversation, then retrieve with that."""
from kb_index import load_or_build
from llm import MODEL, get_client

CONVERSATIONS = [
    [("user", "How long do labs stay open after my course?"),
     ("assistant", "Labs stay open for 30 days after the course ends, and you can ask for one free 7-day extension."),
     ("user", "And after that, how much is it?")],
    [("user", "I want to cancel my AZ-104 course."),
     ("assistant", "I can help. How many days are left before it starts?"),
     ("user", "ten days. what do i get back?")],
    [("user", "My certificate came with my old surname."),
     ("assistant", "Sorry about that! When was it issued?"),
     ("user", "about two months ago, does it cost anything?")],
]

REWRITE = """Rewrite the user's last message as one standalone question that can be understood without
the conversation. Keep their meaning and details; add the missing subject from the conversation.
Return only the question.

Conversation:
{history}"""

index = load_or_build()
client = get_client()


def top(question):
    hits = index.search(question, k=2)
    return ", ".join(f"{h['title']} ({h['score']:.2f})" for h in hits)


for conversation in CONVERSATIONS:
    history = "\n".join(f"{role}: {text}" for role, text in conversation)
    last = conversation[-1][1]
    rewritten = client.chat.completions.create(
        model=MODEL, messages=[{"role": "user", "content": REWRITE.format(history=history)}]
    ).choices[0].message.content.strip()
    print(f"Follow-up : {last}\n  retrieves: {top(last)}")
    print(f"Rewritten : {rewritten}\n  retrieves: {top(rewritten)}\n")

3

Check

Retrieval.

1. Why is "zero results" a good outcome for some questions?

It lets the system say "I couldn't find that" without a model call, instead of handing the model unrelated chunks it may improvise from. Users trust a system that admits gaps.

2. In tool-based RAG, who does the query rewriting?

The model, when it writes the query argument of the search tool. That's why Milestone 6's prompt asks for "a complete question, including details from earlier in the conversation".

3. The right chunk is usually in the top 10 but rarely first. What do you add?

A reranker (a cross-encoder model, or Azure AI Search's semantic ranker) over the top 10 to 50, then keep the best 3 to 5. It improves ordering without changing the index.

Takeaway

Rewrite the question, filter by permission inside the search, keep only matches above a calibrated floor, and accept zero results. The model can only be as good as what it's given.
