What Is RAG, and Why Use It?

A model answers from what it learned in training. Ask it about your company's refund rules and it either admits it doesn't know or, worse, makes something up. RAG gives it the right page at the moment of the question. You'll see both behaviours side by side.

1

Learn

Look it up, then answer.

Definition

Retrieval-augmented generation (RAG) is a pattern in which an application retrieves relevant information from an external knowledge source at query time, adds it to the prompt, and has the model generate an answer grounded in that information. The model's weights don't change; only its input does.

In plain words

Before the model answers, your code searches your documents for the few passages that matter, pastes them into the prompt, and says "answer from these, and say which one you used".

Imagine this

A closed-book exam tests what you remember; a confident student who half-remembers writes a fluent wrong answer. An open-book exam lets you look up the right page first. RAG turns every question into an open-book exam, and your code chooses which pages the model may open.

Why teams use RAG

Problem without RAGWhat RAG does about it
Knowledge cut-off: the model stopped learning months agoRetrieves today's version of the document
Private knowledge: your policies and wiki were never in its training dataBrings them into the prompt for this one question, without sending them to anyone's training pipeline
Change: prices and rules change monthlyEdit the document and re-index the changed chunks; no model work
Hallucination: fluent guesses about specificsGrounds the answer in real text and allows "not found" as a valid answer
Trust: "where does it say that?"Citations link each fact to its source, so people and code can check it
Access control: staff and customers may see different thingsRetrieval filters by who is asking, so the model only sees what that person may see
Cost: pasting the whole handbook into every promptSends only the 3 to 5 passages that matter

RAG, long prompts, fine-tuning or tools?

ApproachGood forNot for
RAGKnowledge in documents: policies, manuals, wikis, FAQs, contractsLive records (a customer's enrolment) or calculations
Put everything in the promptSmall, stable knowledge (Milestone 3's five policy lines)Hundreds of pages; it's slow, costly, and details get missed in long contexts
Tools / function calling (Module 04)Live data and actions: enrolment status, refund quotes, ticketsReading and summarising long text
Fine-tuningStyle, format, tone, a narrow task done many timesTeaching facts that change; it's expensive to update and can't cite sources

Real assistants combine them. RR Finance Assist will use RAG for "what is the policy?", tools for "what about my enrolment?" and code for "how much exactly?".

In the real world
In finance

RAG is how banks keep assistants inside approved content: answers come from the current policy manual, the product terms or the research library, with a citation a reviewer can check. When the fee schedule changes on Monday, the index is updated and Monday's answers are right, with no retraining. It's also how internal tools for staff ("what's the approval limit for a fee exception?") stay consistent across thousands of employees.

Most enterprise AI assistants are RAG systems. Office-suite copilots answer from your files, mail and chats and show references to them. Customer-service bots answer from a company's help centre and hand over to a person when nothing matches. Internal "ask HR" or "ask IT" assistants search policy sites. On Azure, the usual building blocks are Azure AI Search for retrieval and an Azure OpenAI model for generation. A Foundry agent can also use an Azure AI Search index as its knowledge source. You'll build the same pipeline by hand first, so you know what those services do for you.

Traditional developer view

"The model is the brain. If it doesn't know something, we need a smarter model or to train it."

GenAI developer view

"The model is a reader and writer. Knowledge lives in documents I control. My job is to put the right passages in front of it and check that it used them."

Common trap

Believing RAG ends hallucination. It reduces it a lot, but the model can still misread a passage, mix two sources, add a "helpful" detail of its own, or answer from the wrong chunk if retrieval missed. In Drill 06.9 a small model cites a real source and still invents "1-2 billing cycles". RAG needs checks (topic 9) and evaluation (Module 09).

Interview cue

"RAG retrieves relevant passages at query time and grounds the model's answer in them. I'd choose it over fine-tuning for factual, changing or private knowledge, because updates are just re-indexing and answers can cite their sources. Fine-tuning is for behaviour and style; tools are for live data and actions."

llm.py
"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 06.1

Closed book vs open book

~15 minAzure OpenAIPython

Goal: see what a model does with company-specific questions on its own, and what changes when you paste in the right help-centre section by hand. That manual copy-paste is RAG; the rest of the module automates it.

  1. Run

    The same question, twice

    """Drill 06.1: closed book vs open book.
The same questions, first with only the model's own knowledge, then with the right help-centre
section pasted into the prompt by hand. That second version is RAG, done manually."""
import re
from pathlib import Path

from llm import MODEL, get_client

HELP = Path(__file__).parent / "data" / "help"
QUESTIONS = [
    ("What is RR Finance Bank's overdraft fee if I'm $80 overdrawn at the end of the day?",
     "fees-and-charges", "Overdrafts"),
    ("How long do I have to dispute a card payment at RR Finance Bank?", "card-disputes", "Deadlines"),
    ("How much does an international wire cost at RR Finance Bank?", "transfers-and-payments",
     "Limits and fees"),
]


def section(article: str, heading: str) -> str:
    """Copy one section of a help article, the way you'd paste it into a chat by hand."""
    text = (HELP / f"{article}.md").read_text(encoding="utf-8")
    body = re.search(rf"^## {re.escape(heading)}\n(.*?)(?=^## |\Z)", text, re.M | re.S).group(1)
    return f"{heading}\n{body.strip()}"


def ask(messages):
    r = get_client().chat.completions.create(model=MODEL, messages=messages)
    return r.choices[0].message.content.strip()


for question, article, heading in QUESTIONS:
    closed = ask([{"role": "system", "content": "You are RR Finance Bank's customer-support assistant. Answer briefly."},
                  {"role": "user", "content": question}])
    context = section(article, heading)
    open_book = ask([{"role": "system", "content": "You are RR Finance Bank's customer-support assistant. Answer briefly, "
                                                   "using only the help-centre text provided. If it doesn't say, say so."},
                     {"role": "user", "content": f"<help>\n{context}\n</help>\n\nQuestion: {question}"}])
    print(f"Q: {question}\n\n  CLOSED BOOK: {closed}\n\n  OPEN BOOK:   {open_book}\n\n" + "-" * 80)

  2. No-code

    Try it in any chat app

    Open Copilot, ChatGPT or Claude in a browser. Ask: "My RR Finance Bank lab shows error LAB-503. What should I do?" Then start a new chat, paste the whole of data/help/labs-and-sandboxes.md, and ask again. Many chat apps do this for you when you attach a file: that's RAG built into the product.

  3. Think

    Read the answers

    1. Two closed-book answers refused and one invented a meaning for LAB-503. Which is more dangerous in a support product, and why?
    2. The open-book answers are shorter and plainer. Is that a problem?
    3. In this script, a person chose the right section for each question. What has to happen automatically for this to work on any question?
    Compare with my answers
    1. The invention. A refusal sends the customer to support; a confident wrong instruction ("check for loose connections") wastes their time and erodes trust in every later answer. A good system prefers "I don't know" to a guess, and RAG makes "I know, here's where it says so" possible.
    2. No. They contain exactly what the source says, which is the point. Tone can be added by the system prompt; facts shouldn't be.
    3. Ingest the documents, chunk them, embed and index them, then for each question retrieve the best chunks, build the prompt, and check the answer. That's the rest of this module, topic by topic.

Stretch: paste the wrong section (for example "When the money arrives") for the refund question. Does the model say it can't find the answer, or does it improvise? That's why retrieval quality matters more than the prompt.

3

Check

What RAG is for.

1. RR Finance Bank changes its lab extension price from $49 to $59. What do you update in a RAG system, and what in a fine-tuned one?

RAG: edit the help article and re-index its changed chunk; the next answer uses $59. Fine-tuned: prepare new training data, run another fine-tuning job, evaluate and redeploy, and the model may still remember $49.

2. "What is the status of my voucher?" Should that be answered with RAG?

No. It's a live record for one customer, so it needs a tool that calls the voucher system (Module 04). RAG explains the voucher policy; tools fetch this customer's voucher.

3. Name two things RAG gives you that a long system prompt containing all policies doesn't.

Any two of: scale beyond what fits in a prompt; lower cost per message; per-user access control by filtering retrieval; citations to specific sections; updates without editing and redeploying the prompt.

Takeaway

RAG makes every question open book: retrieve the right passages, answer only from them, and allow "not found". Use it for document knowledge; use tools for live data.
