Citation and Source Attribution

A citation turns 'trust me' into 'check me'. But a model can cite a source that doesn't exist, or cite a real one for a number it made up. Cheap checks in code catch the most damaging cases before the customer reads the answer. You'll build them and run them on four answers, one honest and three with typical mistakes.

1Learn→2Do→3CheckLearn 10 min · Do 20 min
1

Learn

Every fact points somewhere, and code checks the pointer.

Definition

Citation and source attribution link each statement in a generated answer to the retrieved source that supports it, typically with inline markers such as [1] that map to a document, section or URL. Citation verification checks those links in code or with another model: that cited sources exist, that factual statements are cited, and that cited sources actually contain what's claimed.

In plain words

Make the model say where each fact came from, show those sources to the reader, and before you show anything, check the model isn't pointing at a source that doesn't exist or doesn't say that.

Imagine this

A journalist's article and the newspaper's fact-checker. The journalist marks every claim with its source; the fact-checker opens each source and confirms the number is really there. Readers see the sources; the fact-checker catches the "$75" that the source says is $50 before it goes to print.

Choices you make

ChoiceOptionsOur default
Marker format[1] numbers · section ids · quoted spans[n]: short, cheap in tokens, easy to check
GranularityDocument · section (chunk) · sentenceSection: precise enough to check, links to a heading
Where shownInline markers · footnote list · hover cards · "related articles"Inline markers plus a list of cited sources with links
VerificationRules in code · a second model judging support · human reviewRules in code on every answer; model-based groundedness in Module 09
When a check failsRemove the marker · warn · retry · fall back to "not found"Remove unknown markers, log it, warn on unsupported numbers
In the real world
In finance

Citations are what make a banking assistant auditable. A complaints handler, an auditor or a regulator can follow the link from "you have 60 days to dispute" to the policy section and its version. Checking citations in code (does the cited section exist, does it contain the number?) turns that from a nice feature into a control.

Citations are now expected in enterprise assistants: answers show numbered references to files or pages, and users click them, especially for HR, legal and policy questions. Legal and medical tools go further and verify quoted spans against the source text. On Azure, Azure AI Content Safety offers groundedness detection, a model-based check of whether an answer is supported by given sources; Module 09 compares that kind of evaluator with the free rule-based checks you build here.

Traditional developer view

"If the model includes a reference, the answer is sourced."

GenAI developer view

"A citation is a claim made by the model. I verify it against the exact list of sources I sent, show only verified sources, and log failures as quality data."

Common trap

Showing every retrieved source as if it were cited. The reader sees four authoritative links under an answer that used one of them, or none, and assumes all four support it. Show what the answer cites; if it cites nothing, label the list honestly ("related articles"), as Milestone 6 does.

Interview cue

"I number the sources in the prompt, require inline citations, and verify them in code: no unknown ids, no uncited factual claims, and numbers must appear in the cited source. The UI shows only verified sources, and failures feed the evaluation dataset."

        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource

Drill 06.10

Check citations before the customer sees them

~20 minPython · pytestoffline

Goal: implement three rule-based citation checks, run them on four answers to the same question, and render the verified sources for the customer.

  1. Run

    The checker

    """Module 06 helper: check citations before anyone reads the answer.
Three cheap checks, no extra model call:
- unknown:     the answer cites [n], but there was no source n (an invented citation);
- uncited:     a sentence states a number (price, percentage, days) but cites nothing;
- unsupported: a sentence cites sources, but one of its numbers appears in none of them.
Module 09 adds model-based groundedness checks; these catch the most damaging mistakes for free."""
import re

CITE = re.compile(r"\[(\d+)\]")
NUMBER = re.compile(r"\d[\d,]*(?:\.\d+)?")
IDS = re.compile(r"\b[A-Z]{1,3}-\d+\b")                 # codes like RR-10477 or FR-12 are names, not amounts


def sentences(answer: str):
    """Split into sentences, keeping citations that come after the full stop ('... refund. [1]')."""
    parts = re.split(r"(?<=[.!?])\s+", answer.strip())
    out = []
    for part in parts:
        lead = re.match(r"^((?:\[\d+\])+)\s*", part)
        if lead and out:                                    # citations at the start belong to the previous sentence
            out[-1] += " " + lead.group(1)
            part = part[lead.end():]
        if part:
            out.append(part)
    return out


def numbers(text: str) -> set[str]:
    text = IDS.sub(" ", CITE.sub(" ", text))
    return {n.replace(",", "").rstrip(".") for n in NUMBER.findall(text)}


def check(answer: str, sources, question: str = "") -> dict:
    """sources[n-1] is the chunk shown to the model as [n]. Numbers the customer wrote are allowed."""
    report = {"cited": [], "unknown": [], "uncited": [], "unsupported": []}
    for sentence in sentences(answer):
        cited = [int(n) for n in CITE.findall(sentence)]
        report["cited"] += [n for n in cited if 1 <= n <= len(sources) and n not in report["cited"]]
        report["unknown"] += [n for n in cited if not 1 <= n <= len(sources)]
        amounts = numbers(sentence) - numbers(question)
        valid = [n for n in cited if 1 <= n <= len(sources)]
        if amounts and not valid:
            report["uncited"].append(sentence)
        elif valid:
            found = set().union(*(numbers(sources[n - 1]["text"]) for n in valid))
            missing = sorted(amounts - found)
            if missing:
                report["unsupported"].append({"sentence": sentence, "numbers": missing})
    report["ok"] = not (report["unknown"] or report["uncited"] or report["unsupported"])
    return report


def render(answer: str, sources, report: dict) -> str:
    """The answer without invented citation numbers, followed by the sources it actually cites."""
    clean = CITE.sub(lambda m: m.group(0) if int(m.group(1)) in report["cited"] else "", answer)
    lines = [f"[{n}] {sources[n - 1]['title']} ({sources[n - 1]['source']})" for n in sorted(report["cited"])]
    return clean.strip() + ("\n\nSources:\n" + "\n".join(lines) if lines else "")

    Four answers, one question

    """Drill 06.10: check four answers to the same question against the sources the model was given.
Offline: the answers are written out here, so you can see exactly what each check catches."""

  3. Verify

    The tests

    """Drill 06.10: citation checks, offline.  Run:  pytest -q test_citations.py"""
from citations import check, render, sentences

SOURCES = [
    {"title": "Fees and charges > Overdrafts", "source": "fees-and-charges.md",
     "text": "If a payment takes your balance below zero, we charge an overdraft fee of $29, at most 3 times per day."},
    {"title": "Lost or stolen cards > Report it and get a replacement", "source": "lost-stolen-cards.md",
     "text": "Express delivery within 2 business days costs $15."},
]


def test_a_well_cited_answer_passes():
    question = "I was overdrawn by $80, what's the fee?"
    report = check("Being $80 overdrawn costs a $29 fee [1]. Express card delivery costs $15 [2].", SOURCES, question)
    assert report["ok"] and report["cited"] == [1, 2]
    assert check("Being $80 overdrawn costs a $29 fee [1].", SOURCES)["unsupported"]   # 80 is in no source


def test_invented_citation_numbers_are_caught():
    report = check("The overdraft fee is $29 [1][7].", SOURCES)
    assert report["unknown"] == [7] and not report["ok"]


def test_numbers_without_a_citation_are_caught():
    report = check("The overdraft fee is $29. A new card arrives in 5 days [1].", SOURCES)
    assert report["uncited"] == ["The overdraft fee is $29."]
    assert report["unsupported"] == [{"sentence": "A new card arrives in 5 days [1].", "numbers": ["5"]}]


def test_a_number_missing_from_the_cited_source_is_caught():
    report = check("Express delivery costs $25 [2].", SOURCES)
    assert report["unsupported"] == [{"sentence": "Express delivery costs $25 [2].", "numbers": ["25"]}]


def test_citation_after_the_full_stop_belongs_to_that_sentence():
    assert sentences("The fee is $29. [1] Thanks!") == ["The fee is $29. [1]", "Thanks!"]
    assert check("The fee is $29. [1] Thanks!", SOURCES)["ok"]


def test_codes_are_not_treated_as_amounts():
    assert check("For RR-10477, see the overdraft rules [1].", SOURCES)["ok"]


def test_render_drops_invented_citations_and_lists_real_sources():
    answer = "The overdraft fee is $29 [1][7]."
    text = render(answer, SOURCES, check(answer, SOURCES))
    assert text == ("The overdraft fee is $29 [1].\n\nSources:\n"
                    "[1] Fees and charges > Overdrafts (fees-and-charges.md)")

3

Check

Citations.

1. The answer says "a reissue costs $25 [1]" and source 1 says "After 30 days, a reissue costs $25." Do the checks prove the answer is right?

No. They prove the number appears in the cited source. The answer could still apply it to the wrong situation (for example, a correction requested within 30 days, which is free). That needs a model-based groundedness check or human review (Module 09).

2. Why does check() ignore codes like TC-10477 and LAB-503 when comparing numbers?

They're identifiers, often copied from the question or the customer's data, not amounts or durations claimed from a source. Treating them as numbers would flag correct answers.

3. A model often answers correctly but cites nothing. What do you show the customer?

The answer, without pretending it was sourced: list the top retrieved sections as "related articles", log the missing citations, and measure the citation rate per model. Small local models do this far more often than larger hosted ones.

Takeaway

Citations make answers checkable; code makes them trustworthy. Verify every marker against the sources you sent, show only what's cited, and log every failure.
