Routing, Caching and Batching

A faster or cheaper path is useful only when its output remains acceptable. Know whether you are using provider-managed prompt caching, an application cache or a batch API; each has different eligibility, freshness and privacy constraints.

Model routingCache semanticsBatch jobs
1Learn→2Do→3CheckLearn 15 min · Do 15 min
1

Learn

Know what is being reused and what freshness it promises.

Definition

Model routing selects an approved model or deployment for a task. Prompt caching reuses provider-side processing for eligible repeated prompt prefixes; it is not the same as returning a previous answer. An application response cache reuses a stored result and needs a safe key, freshness rules and access boundaries. Batch processing runs many requests asynchronously when the use case can wait.

In plain words

Routing chooses the worker. Prompt caching may save repeated input work. A response cache returns a previous answer. Batch processing lets you submit a group and collect results later.

Imagine this

A bank teller may reuse the same printed policy reference, but must not reuse one customer's account answer for another customer. A nightly report can wait in a queue; a fraud alert cannot.

TechniqueUseful whenCheck first
Model routingTasks have different quality, latency and cost needsEach route passes its task-specific evaluation
Prompt cachingEligible prompts share a stable prefixModel support, cache rules, privacy and actual hit metrics
Response cachingIdentical, stable, non-personal answers repeatTenant isolation, user-specific data and policy-version invalidation
Batch APIOffline evaluation or non-urgent bulk workAsync completion, supported models and current limits
In the real world

Azure OpenAI prompt caching applies to supported models and repeated prompt prefixes; it can reduce input processing cost and latency, but does not change response meaning or guarantee a hit. Batch processing is asynchronous and has its own supported models and service limits. Check the current prompt caching guide and batch guide.

In finance

A bank may cache a stable public help article lookup, but should not reuse a prior customer's transaction answer. A daily evaluation run can be batched; an incoming lost-card request needs an interactive path.

Traditional developer view

"Caching is a transparent performance optimization."

GenAI developer view

"Cached data can be stale or cross a privacy boundary; define the exact key, tenant scope, TTL and invalidation rule."

Common trap

Assuming a model's automatic prompt cache stores and replays the answer. It reuses eligible prompt processing; response caching is a separate application behavior with separate correctness and privacy risks.

Interview cue

"I select routes based on measured task quality, check provider cache support and cache-hit telemetry, avoid caching customer-specific responses without strict isolation, and use batch only where latency requirements allow."

Drill 11.1

Estimate token cost for one approved route

~15 minPython · pytestoffline

Goal: calculate the token cost for one candidate route with explicit input/output rates, then compare another route only after both pass the quality checks from Module 9.

  1. Run

    Calculate an illustrative monthly estimate

    """Cost estimates from an explicitly supplied, current rate card."""

from dataclasses import dataclass
from decimal import Decimal


@dataclass(frozen=True)
class RateCard:
    input_usd_per_million: Decimal
    output_usd_per_million: Decimal

    def __post_init__(self) -> None:
        rates = (self.input_usd_per_million, self.output_usd_per_million)
        if any(not isinstance(rate, Decimal) for rate in rates):
            raise TypeError("Token rates must use Decimal values")
        if any(not rate.is_finite() or rate < 0 for rate in rates):
            raise ValueError("Token rates cannot be negative")


def estimate_monthly_cost(
    input_tokens_per_request: int,
    output_tokens_per_request: int,
    requests_per_month: int,
    rate_card: RateCard,
) -> Decimal:
    values = (
        input_tokens_per_request,
        output_tokens_per_request,
        requests_per_month,
    )
    if any(value < 0 for value in values):
        raise ValueError("Token counts and request volume cannot be negative")

    input_cost = (
        Decimal(input_tokens_per_request * requests_per_month)
        * rate_card.input_usd_per_million
        / Decimal(1_000_000)
    )
    output_cost = (
        Decimal(output_tokens_per_request * requests_per_month)
        * rate_card.output_usd_per_million
        / Decimal(1_000_000)
    )
    return input_cost + output_cost
    from decimal import Decimal

import pytest

from app.costing import RateCard, estimate_monthly_cost


def test_monthly_cost_uses_separate_input_and_output_rates():
    rates = RateCard(
        input_usd_per_million=Decimal("0.40"),
        output_usd_per_million=Decimal("1.60"),
    )
    assert estimate_monthly_cost(1000, 250, 40000, rates) == Decimal("32.000")


def test_zero_requests_cost_nothing():
    rates = RateCard(Decimal("1.00"), Decimal("2.00"))
    assert estimate_monthly_cost(1000, 500, 0, rates) == Decimal(0)


def test_negative_rate_is_rejected():
    with pytest.raises(ValueError, match="cannot be negative"):
        RateCard(Decimal("-0.01"), Decimal("1.00"))


def test_negative_volume_is_rejected():
    rates = RateCard(Decimal("1.00"), Decimal("2.00"))
    with pytest.raises(ValueError, match="cannot be negative"):
        estimate_monthly_cost(1000, 500, -1, rates)

3

Check

Caching and batch choices.

1. Can an app response cache return one customer's balance to another?

It must never do so. Include tenant/user scope in authorization and cache design, or do not cache personal responses.

2. Which work is a better batch candidate: a nightly evaluation or a lost-card report?

The nightly evaluation can usually wait. A lost-card report is time-sensitive and needs an interactive, monitored path.

Takeaway

Distinguish model prompt caching, application response caching and batch processing. Each has different freshness, privacy and latency rules.
