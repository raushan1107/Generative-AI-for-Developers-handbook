Cost and Latency Budgets

A cost forecast is a workload model, not a price copied into source code. Count all model calls per request, estimate input and output separately, include retries and supporting services, then compare the result with a quality-qualified outcome.

Token economicsLatency percentilesRetriesCost per success
1Learn→2Do→3CheckLearn 15 min · Do 15 min
1

Learn

Budget the complete workflow, not one call.

Definition

A cost budget estimates workload volume multiplied by the number and size of model calls, current input/output rates and supporting service costs. A latency budget sets acceptable time for the whole user journey, often measured with percentiles such as p50 and p95. Cost per successful task includes failed or retried work and the quality threshold required for success.

In plain words

Count how many requests arrive, how much text goes in and out, how many times the model is called, and how often the work must be retried.

Imagine this

A bank branch does not budget only for the first teller interaction if complex cases require a supervisor, secure storage and follow-up work.

MeasureIncludeCommon blind spot
Model costInput and output tokens for every call and retryTool loop or repair call omitted
LatencyQueue wait, retrieval, model calls and approval delayReporting average instead of tail latency
Service costSearch, storage, network, logs and computeOnly comparing token prices
Successful outcomeTask passes quality and safety criteriaCheaper route misses critical cases
In the real world

Azure OpenAI quotas and limits depend on deployment type, model and configuration. Capacity and pricing can change, so use current service documentation and pricing tools instead of assuming a static value in code. See Microsoft Learn: quotas and limits.

In finance

At 40,000 messages each month, four turns per message imply roughly 160,000 turns before retries and escalations. Forecast tokens per turn and multi-step tool calls, then compare the estimated cost with the number of cases that meet accuracy, safety and response-time targets.

Traditional developer view

"The endpoint's average response time is 600 ms."

GenAI developer view

"The user journey's p95 includes retrieval, retries and tool steps, and the fastest route must still meet evaluation thresholds."

Common trap

Hard-coding a public model price as if it were the bank's actual rate. Deployment type, region, contract, cache eligibility and future price changes can alter the bill. Keep rate cards external and date-stamped.

Interview cue

"I measure tokens and calls per successful task, include retries and non-model services, track p50/p95 latency, and re-run quality evaluation before accepting a cheaper or faster route."

Drill 11.2

Estimate monthly model cost

~15 minPython · pytestoffline

Goal: turn monthly customer messages into model calls, calculate token cost, and identify costs the helper does not include.

  1. Run

    Estimate the RR Finance workload

    """Cost estimates from an explicitly supplied, current rate card."""

from dataclasses import dataclass
from decimal import Decimal


@dataclass(frozen=True)
class RateCard:
    input_usd_per_million: Decimal
    output_usd_per_million: Decimal

    def __post_init__(self) -> None:
        rates = (self.input_usd_per_million, self.output_usd_per_million)
        if any(not isinstance(rate, Decimal) for rate in rates):
            raise TypeError("Token rates must use Decimal values")
        if any(not rate.is_finite() or rate < 0 for rate in rates):
            raise ValueError("Token rates cannot be negative")


def estimate_monthly_cost(
    input_tokens_per_request: int,
    output_tokens_per_request: int,
    requests_per_month: int,
    rate_card: RateCard,
) -> Decimal:
    values = (
        input_tokens_per_request,
        output_tokens_per_request,
        requests_per_month,
    )
    if any(value < 0 for value in values):
        raise ValueError("Token counts and request volume cannot be negative")

    input_cost = (
        Decimal(input_tokens_per_request * requests_per_month)
        * rate_card.input_usd_per_million
        / Decimal(1_000_000)
    )
    output_cost = (
        Decimal(output_tokens_per_request * requests_per_month)
        * rate_card.output_usd_per_million
        / Decimal(1_000_000)
    )
    return input_cost + output_cost
    from decimal import Decimal

import pytest

from app.costing import RateCard, estimate_monthly_cost


def test_monthly_cost_uses_separate_input_and_output_rates():
    rates = RateCard(
        input_usd_per_million=Decimal("0.40"),
        output_usd_per_million=Decimal("1.60"),
    )
    assert estimate_monthly_cost(1000, 250, 40000, rates) == Decimal("32.000")


def test_zero_requests_cost_nothing():
    rates = RateCard(Decimal("1.00"), Decimal("2.00"))
    assert estimate_monthly_cost(1000, 500, 0, rates) == Decimal(0)


def test_negative_rate_is_rejected():
    with pytest.raises(ValueError, match="cannot be negative"):
        RateCard(Decimal("-0.01"), Decimal("1.00"))


def test_negative_volume_is_rejected():
    rates = RateCard(Decimal("1.00"), Decimal("2.00"))
    with pytest.raises(ValueError, match="cannot be negative"):
        estimate_monthly_cost(1000, 500, -1, rates)

  2. Verify
    • Include all model calls and retries when estimating volume.
    • Use current rates from the actual deployment and record the date.
    • Add search, storage, compute, observability and network costs separately.
3

Check

Budget assumptions.

1. Why include retries and tool calls in a cost estimate?

Each model call can consume tokens and time. A successful turn may involve multiple calls, and a failed call may still be billable.

2. Why compare cost per successful task instead of cost per request?

A very cheap answer that fails the quality or safety requirement is not a successful outcome and may create more support work.

Takeaway

Use current, deployment-specific rates and measure the entire user journey. Optimize cost only while preserving quality and safety.
