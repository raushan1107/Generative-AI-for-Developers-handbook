Module 11 · Overview

Performance and Cost Optimization

Optimization is a measured trade-off. This module separates provider prompt caching from application response caching, reserves batch processing for work that can wait, and estimates model cost from a rate card you can update.

RoutingCachingBatchingBudgets

1

Learn

Measure first, optimize without breaking the quality gates.

In the real world

Model service behavior, quotas, cache support and batch availability vary by model and deployment. Microsoft's documentation describes prompt caching, global batch processing and quotas separately; verify current eligibility and terms before designing around them. See prompt caching, batch processing and quotas and limits.

In finance

At 40,000 monthly customer messages, a small change in average input and output tokens can materially change the forecast. Route simple triage only to a deployment that meets its fraud-recall and safety thresholds; cheaper but worse fraud detection is not an optimization.

Traditional developer view

"Reduce CPU time and database calls."

GenAI developer view

"Also track token volume, model latency, retries and cost per successful, acceptable task."
