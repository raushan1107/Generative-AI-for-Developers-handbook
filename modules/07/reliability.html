Agent Reliability

A demo agent works once. A production agent works on the thousandth run, when the schedule service times out, the model calls the same tool four times, or a retry arrives after the first call succeeded. You can't make a model reliable, but you can make the system around it reliable. You'll prove the guard rails with offline tests, then break the services on purpose and check that nothing happens twice.

1

Learn

Unreliable parts, reliable system.

Definition

Agent reliability is the ability of an agent system to complete tasks correctly and fail safely when it can't: bounded in steps and cost, never repeating side effects, never acting outside its permissions, honest about what happened, and observable enough to debug. It comes mostly from controls in code around the model, verified with tests and evaluations.

In plain words

Assume the model and the services will sometimes get it wrong. Put limits, checks and logs around them so that "wrong" means "stopped and said so", never "did something twice" or "did something it shouldn't".

Imagine this

A lift. Its motor can fail and passengers press the wrong buttons, but the lift is safe: a load limit, door sensors, brakes that engage when power fails, a maximum speed, an emergency phone and an inspection log. Nobody makes the motor perfect; they make the system safe around it.

In the real world

Payment APIs pioneered idempotency keys for exactly this reason: networks drop replies, clients retry, and nobody wants to be charged twice. Agent platforms add the rest: per-run step and token limits, tool timeouts, traces of every model and tool call, and test suites where a scripted model replays known conversations so a code change can't silently break the approval flow. Teams then run evaluation sets of real requests against each new prompt or model before release (Module 09).

Traditional developer view

"If the code is correct, the feature is reliable."

GenAI developer view

"One component makes probabilistic choices, and services fail. Reliability comes from bounds, idempotent writes, permissions in code, traces and tests, and from evaluating behaviour over many runs, not one demo."

Common trap

Testing an agent only by chatting with it. A manual chat explores one path, once, with one model mood. Script the model (fake_llm.py) to test the loop's guard rails deterministically, and use evaluation sets to test the model's choices statistically.

Interview cue

"I make agents reliable with controls in code: step and token budgets, repeat detection, identity and permission checks in tools, actionable errors, idempotency keys on writes, approvals for risky actions, and tracing; I test the loop offline with a scripted model and the behaviour with evaluation sets."

Do

Prove the guard rails, then break the services.

Drill 07.8

Reliability: offline tests and a chaos run

~25 minAzure OpenAIPython · pytest

Goal: verify every guard rail of agent.py with a scripted model in milliseconds, then run the real agent five times against services that fail 30% of the time and check the systems end in a correct state.

  1. Verify

    A scripted model, and the tests it drives

    """Module 07: a scripted stand-in for the chat client, so agent tests run offline in milliseconds.
Each create() call returns the next scripted turn: text, or one or more tool calls."""
from types import SimpleNamespace as NS


def says(text):
    return {"text": text}


def calls(name, arguments="{}", call_id="call_1"):
    return {"tools": [(call_id, name, arguments)]}


class FakeLLM:
    def __init__(self, turns):
        self.turns, self.requests = list(turns), []
        self.chat = NS(completions=self)

    def create(self, **kwargs):
        self.requests.append(kwargs)
        turn = self.turns.pop(0) if self.turns else says("(script ended)")
        tool_calls = [NS(id=i, type="function", function=NS(name=n, arguments=a)) for i, n, a in turn.get("tools", [])]
        message = NS(content=turn.get("text"), tool_calls=tool_calls or None)
        return NS(choices=[NS(message=message, finish_reason="tool_calls" if tool_calls else "stop")],
                  usage=NS(total_tokens=100))
    """Drill 07.8: agent reliability, offline. A scripted fake model drives the real loop and the
real (stand-in) systems.  Run:  pytest -q test_agent.py"""
import json

import pytest

import desk
from agent import Agent
from desk_tools import WRITE_TOOLS, kit
from fake_llm import FakeLLM, calls, says

MEI = {"learner": "L-MEI"}
EXTEND = json.dumps({"enrolment_id": "TC-10293"})


@pytest.fixture(autouse=True)
def fresh_desk():
    desk.reset()


def agent(turns, approve=None, max_steps=8):
    return Agent(FakeLLM(turns), "fake", kit, "You are a test agent.", max_steps=max_steps,
                 write_tools=WRITE_TOOLS, approve=approve)


def test_read_then_answer():
    result = agent([calls("my_enrolments"), says("You have two enrolments.")]).run("What am I enrolled in?", MEI)
    assert result.answer == "You have two enrolments." and result.stopped is None
    assert [s.tool for s in result.steps] == ["my_enrolments"] and result.llm_calls == 2


def test_write_needs_approval_and_runs_once_when_approved():
    asked = []
    result = agent([calls("extend_lab", EXTEND), says("Done.")],
                   approve=lambda name, args, ctx: asked.append(name) or (True, "")).run("Extend my lab", MEI)
    assert asked == ["extend_lab"] and result.steps[0].status == "ok"
    assert [a["action"] for a in desk.ACTIONS] == ["extend_lab"]


def test_rejected_write_changes_nothing_and_the_model_is_told():
    a = agent([calls("extend_lab", EXTEND), says("OK, I won't extend it.")],
              approve=lambda name, args, ctx: (False, "learner said no"))
    result = a.run("Extend my lab", MEI)
    assert result.steps[0].status == "rejected" and desk.ACTIONS == []
    assert "did not approve" in a.client.requests[1]["messages"][-1]["content"]


def test_no_approver_means_writes_are_refused():
    result = agent([calls("extend_lab", EXTEND), says("I can't do that.")]).run("Extend my lab", MEI)
    assert result.steps[0].status == "rejected" and desk.ACTIONS == []


def test_tool_errors_are_observations_the_model_can_use():
    a = agent([calls("lab_status", json.dumps({"enrolment_id": "TC-20877"})), says("That isn't yours.")])
    result = a.run("Lab status of TC-20877?", MEI)                      # Diego's enrolment, not Mei's
    assert result.steps[0].status == "error"
    assert "not one of this learner's enrolments" in result.steps[0].result


def test_step_budget_stops_a_runaway_agent():
    turns = [calls("upcoming_sessions", json.dumps({"course_id": f"C1{i:02d}"}), f"c{i}") for i in range(10)]
    result = agent(turns, max_steps=3).run("Find every session", MEI)
    assert result.stopped == "max_steps" and result.llm_calls == 3


def test_repeating_the_same_call_is_detected_then_stopped():
    result = agent([calls("my_enrolments")] * 6).run("Loop forever", MEI)
    assert [s.status for s in result.steps] == ["ok", "ok", "repeated", "repeated"]
    assert result.stopped == "loop"


def test_idempotency_key_makes_a_retried_write_harmless():
    first = desk.extend_lab("L-MEI", "TC-10293", key="k1")
    again = desk.extend_lab("L-MEI", "TC-10293", key="k1")             # e.g. a retry after a timeout
    assert again["lab_until"] == first["lab_until"] and "already done" in again["note"]
    assert len(desk.ACTIONS) == 1


def test_flaky_services_raise_retryable_errors():
    desk.reset(flaky_rate=1.0)
    result = json.loads(kit.dispatch("my_enrolments", "{}", MEI))
    assert result["retryable"] is True and "timed out" in result["error"]

  3. Think

    Read the chaos table

    1. Is "finished" the right success measure? What matters more for the business?
    2. Which column must never be greater than 1, whatever the model does, and what guarantees it?
    3. Where would you add automatic retries for timeouts: in the model loop, or in code around the tool?
    Compare with my answers
    1. No. Look at seed 2: it "finished" and told Mei her lab was extended until October 16, but the extensions column is 0, and 16 October is the old date. Seed 4 didn't finish, yet it stopped cleanly and said so. For the business, a correct state and an honest answer matter more than "finished".
    2. Extensions. In five runs with 3 to 5 errors each, it was never more than 1: the "one free extension" rule in desk.py and the idempotency key per approved action guarantee it, whatever the model retries.
    3. In code, around read tools (a short retry with back-off, as in Module 02), so the model isn't spending steps on transient errors. For writes, retry only with the same idempotency key. Leave the model to handle errors that need a decision.
3

Check

Reliability.

1. Why test an agent with a scripted fake model?

To check the loop's guard rails (budgets, loop detection, approvals, error handling, idempotency) deterministically, in milliseconds, without cost, on every code change. The real model's choices are tested separately, with evaluation sets.

2. What is an idempotency key, and who creates it?

A unique id sent with a write so the receiving system performs it at most once; repeats with the same key return the first result. The application creates it once per approved action, never the model.

3. Name four controls that keep a misbehaving model from causing harm.

Any four: step budget; repeat detection; identity and ownership checks in tools; approvals for writes; idempotency keys; least-privilege tool set; output checks (for example tool calls written as text); audit logs.

Takeaway

You can't make the model reliable; you can make the system reliable. Bound it, check it, make writes idempotent, log everything, and test the guard rails offline.
