What Is an AI Agent? Agent vs Chatbot

Ask a chatbot to extend your lab and it may cheerfully say it has. Nothing changed: it has no hands. An agent has tools, and it uses them in a loop until the job is done. You'll send the same request to both and then look in RR Finance Bank's systems to see which one actually did something.

1

Learn

A model with hands, in a loop.

Definition

An AI agent is a system in which a language model pursues a goal by deciding its own next steps: it chooses tools to call, observes their results, keeps state about what it has learned, and repeats until it can give a final answer or a limit stops it. A chatbot produces one reply per message from what's in its prompt; it doesn't act on the world.

In plain words

A chatbot talks. An agent works: it looks things up, does things, checks how they went, and keeps going until the task is finished.

Imagine this

A phone help line versus a concierge. The help line tells you how to change your booking. The concierge takes your request, checks the system, finds the next free date, asks if $50 is OK, makes the change and hands you the confirmation.

The autonomy spectrum

LevelWho decides the stepsExample
ChatbotNo steps; one replyMilestone 2's chat
Tool-using assistantThe model picks a few tools for one turn, in a bounded loopMilestones 4 to 6: look-ups, quotes, help-centre search
WorkflowYour code fixes the steps; the model fills in some of themClassify → fetch → draft a reply (Drill 07.4)
AgentThe model chooses the steps towards a goal, including actions"Move me to the next date and tell me the fee"
Autonomous agentLong-running, many steps, little supervisionCoding agents that open pull requests; research agents

Move right only when you need to. Each step to the right adds flexibility and also cost, latency and ways to fail. RR Finance Assist becomes an agent for a few well-defined actions, with a person approving every change.

The parts of every agent

  • A model good at tool calling and instruction following (topic 3).
  • Tools: read tools that look things up, write tools that change things (topic 3).
  • A loop with a step budget and a stop condition (topics 6 and 8).
  • State: what's been found and done so far; sometimes long-term memory (topic 5).
  • Guard rails: identity from the app, approvals for writes, idempotency, traces (topics 7 and 8).
In the real world
In finance

Banks are adopting agents cautiously, because an agent that can act can also act wrongly. Typical first agents work on internal tasks with clear limits: preparing a dispute case for an agent to review, collecting documents for a loan application, or reconciling a set of transactions and flagging differences. Anything that moves money or changes a customer's account stays behind human approval.

Coding assistants in agent mode, such as GitHub Copilot, Claude Code and Codex, are the agents developers meet first: they read files, run commands and tests, see the failures and try again, and ask before running anything risky. Customer-service agents rebook flights and process returns within limits; IT agents reset passwords after verifying identity. On Azure, Microsoft Foundry Agent Service hosts agents with tools such as Azure AI Search, code interpreter and your own functions, while you keep control of identity and permissions.

Traditional developer view

"The program decides every step; users trigger flows."

GenAI developer view

"The model decides which step comes next; my code decides what's allowed: which tools exist, with whose identity, how many steps, and which steps need a human."

Common trap

Trusting what the model says it did. In Drill 07.1 the tool-less chatbot claims it extended the lab; the audit log says nothing changed. Report outcomes from tool results and logs, never from the model's prose.

Interview cue

"An agent is an LLM in a loop that chooses tools to reach a goal, observes results and keeps state. Compared with a chatbot it acts; compared with a workflow, the model chooses the path. I'd use the least autonomy that solves the problem, and wrap the loop in budgets, approvals and logging."

"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 07.1

Chatbot vs agent: who actually did it?

~15 minAzure OpenAIPython

Goal: meet the stand-in RR Finance Bank systems and the agent loop, send Mei's request to a model without tools and to an agent with tools, and check the audit log.

  1. Run

    Systems that can change, and the tools over them

    desk.py holds fictional enrolments, labs and course dates in memory, with dates relative to today. Every successful write lands in desk.ACTIONS, the audit log. Skim it, then read the tools:

    """Module 07: the agent's tools over desk.py. Read tools look things up; write tools change state.
The signed-in customer comes from `context`, set by the app, never from the model.
WRITE_TOOLS lists the tools that need a human's approval; preview() says, in plain words,
exactly what an approval would do, so the human approves an effect, not a function name."""
import functools
import json
from typing import Literal

from pydantic import BaseModel, Field

import desk
from toolkit import Toolkit

kit = Toolkit()
WRITE_TOOLS = {"freeze_card", "open_dispute"}


def actionable(func):
    """Errors are observations: return the system's message so the model can recover
    (pick another payment, offer a case, retry), instead of a generic "tool failed"."""
    @functools.wraps(func)
    def wrapper(args, context):
        try:
            return func(args, context)
        except desk.DeskError as e:
            return {"error": str(e)}
        except TimeoutError as e:
            return {"error": str(e), "retryable": True}
    return wrapper


class NoArgs(BaseModel):
    pass


class CardArgs(BaseModel):
    card_last4: str = Field(description="Last four digits of one of the customer's cards, like 4821, from my_cards")


class TransactionArgs(BaseModel):
    txn_id: str = Field(description="Transaction ID like TX-1002, from recent_transactions")


class DisputeArgs(BaseModel):
    txn_id: str = Field(description="Transaction ID like TX-1002, from recent_transactions")
    reason: Literal["charged_twice", "wrong_amount", "not_received", "not_recognised"]


class CaseArgs(BaseModel):
    category: Literal["card", "dispute", "fraud", "fees", "other"]
    summary: str = Field(description="One or two sentences for the support team")


@kit.register(NoArgs, needs_context=True)
@actionable
def my_cards(args, context):
    """List the signed-in customer's cards: card_last4, product and status (active or frozen)."""
    return desk.my_cards(context["customer"])


@kit.register(CardArgs, needs_context=True)
@actionable
def card_status(args, context):
    """Status of one card: active or frozen, and what that means for payments."""
    return desk.card_status(context["customer"], args.card_last4)


@kit.register(CardArgs, needs_context=True)
@actionable
def recent_transactions(args, context):
    """Payments on one card in the last 90 days: txn_id, date, merchant and amount, newest first."""
    return desk.recent_transactions(context["customer"], args.card_last4)


@kit.register(TransactionArgs, needs_context=True)
@actionable
def dispute_quote(args, context):
    """Whether a payment can be disputed today, and when a provisional credit would arrive. Call it before open_dispute."""
    return desk.dispute_quote(context["customer"], args.txn_id)


@kit.register(CardArgs, needs_context=True)
@actionable
def freeze_card(args, context):
    """Freeze one card so new payments are declined. Changes the account: needs the customer's approval."""
    return desk.freeze_card(context["customer"], args.card_last4, key=context.get("idempotency_key"))


@kit.register(DisputeArgs, needs_context=True)
@actionable
def open_dispute(args, context):
    """Open a dispute for one payment and start the provisional credit. Changes the account: needs the
    customer's approval. Call dispute_quote first."""
    return desk.open_dispute(context["customer"], args.txn_id, args.reason, key=context.get("idempotency_key"))


@kit.register(CaseArgs, needs_context=True)
@actionable
def create_case(args, context):
    """Create a case for the human support team, for anything you can't do yourself."""
    return desk.create_case(context["customer"], args.category, args.summary)


def preview(name: str, arguments: str, context: dict) -> str:
    """What an approval would do, in the customer's terms, computed by code (not described by the model)."""
    a = json.loads(arguments or "{}")
    customer = context["customer"]
    try:
        if name == "freeze_card":
            card = desk.card_status(customer, a["card_last4"])
            return (f"Freeze your {card['product']} ending {a['card_last4']}: new payments and cash withdrawals "
                    "will be declined until you unfreeze it; direct debits keep working.")
        if name == "open_dispute":
            quote = desk.dispute_quote(customer, a["txn_id"])
            txn = desk.STATE["transactions"][a["txn_id"].upper()]
            if not quote["allowed"]:
                return f"Dispute {a['txn_id']} (not possible: {quote['reason']})."
            return (f"Dispute ${txn['amount_usd']:.2f} to {txn['merchant']} on {txn['date']} ({a.get('reason')}); "
                    f"a provisional credit by {quote['provisional_credit_by']}.")
    except (desk.DeskError, KeyError) as e:
        return f"{name} with {arguments} (can't preview: {e})"
    return f"{name} with {arguments}"


SYSTEM = f"""You are RR Finance Assist, acting for the signed-in RR Finance Bank customer. Today is {desk.TODAY.isoformat()}.
- Use tools to look things up and to act. Never guess or invent card numbers, transaction IDs, dates or amounts.
- The customer can't see or call tools. Never ask them to; call the tools yourself.
- Never ask for a full card number, a PIN, a password or a one-time code.
- Start with my_cards whenever you need a card; use recent_transactions to find a payment's txn_id.
- Before open_dispute, call dispute_quote.
- freeze_card and open_dispute need the customer's approval; the system asks them. If they decline, don't try again.
- If a tool returns an error, use its message: correct the call, choose another option, or offer create_case.
- Finish with a short answer (at most 80 words) stating what was done, with dates and amounts."""
  2. Run

    The agent loop

    """Module 07: a small agent loop you can read in one sitting.
The model plans the next step by asking for a tool; our code decides whether and how it runs.
Built in: a step budget, loop detection, human approval for write tools, idempotency keys
for writes, and a trace of every step. Frameworks add more, but they all do these things."""
import json
import time
import uuid
from dataclasses import dataclass, field

from llm_tools import TOOL_EXTRAS


@dataclass
class Step:
    n: int
    tool: str
    arguments: str
    result: str
    ms: int
    status: str = "ok"            # ok | error | rejected | repeated


@dataclass
class RunResult:
    answer: str
    steps: list[Step] = field(default_factory=list)
    stopped: str | None = None    # None when the model finished; else why we stopped it
    llm_calls: int = 0
    tokens: int = 0


class Agent:
    def __init__(self, client, model, kit, system, max_steps=8, write_tools=(), approve=None, on_step=None):
        """approve(name, arguments, context) -> (ok, reason). Without it, write tools are refused."""
        self.client, self.model, self.kit, self.system = client, model, kit, system
        self.max_steps, self.write_tools, self.approve = max_steps, set(write_tools), approve
        self.on_step = on_step or (lambda step: None)

    def run(self, task: str, context: dict, history=None) -> RunResult:
        messages = [{"role": "system", "content": self.system}, *(history or []), {"role": "user", "content": task}]
        result, seen = RunResult(answer=""), {}
        for _ in range(self.max_steps):
            response = self.client.chat.completions.create(
                model=self.model, messages=messages, tools=self.kit.schemas(), parallel_tool_calls=False, **TOOL_EXTRAS)
            result.llm_calls += 1
            result.tokens += getattr(response.usage, "total_tokens", 0) or 0
            msg = response.choices[0].message
            if not msg.tool_calls:                               # the model has finished
                result.answer = (msg.content or "").strip()
                return result
            messages.append({"role": "assistant", "content": msg.content, "tool_calls": [
                {"id": c.id, "type": "function", "function": {"name": c.function.name, "arguments": c.function.arguments}}
                for c in msg.tool_calls]})
            for call in msg.tool_calls:
                step = self._execute(len(result.steps) + 1, call.function.name, call.function.arguments, context, seen)
                result.steps.append(step)
                self.on_step(step)
                messages.append({"role": "tool", "tool_call_id": call.id, "content": step.result})
                if step.status == "repeated" and seen[(step.tool, step.arguments)] > 3:
                    result.stopped = "loop"
                    result.answer = "Sorry, I got stuck repeating the same step. I've stopped; please contact support."
                    return result
        result.stopped = "max_steps"
        result.answer = "Sorry, that needed more steps than I'm allowed. Shall I raise a case for the support team?"
        return result

    def _execute(self, n, name, arguments, context, seen) -> Step:
        start = time.perf_counter()
        key = (name, arguments)
        seen[key] = seen.get(key, 0) + 1
        if seen[key] > 2:                                        # same call, same arguments, again
            result, status = json.dumps({"error": "you already made this exact call; use its result, "
                                                  "try something different, or answer"}), "repeated"
        elif name in self.write_tools:
            ok, reason = self.approve(name, arguments, context) if self.approve else (False, "no approver configured")
            if ok:
                # One idempotency key per approved action: if anything retries it, it runs once.
                result = self.kit.dispatch(name, arguments, context | {"idempotency_key": uuid.uuid4().hex})
                status = "error" if result.startswith('{"error"') else "ok"
            else:
                result, status = json.dumps({"error": f"the customer did not approve this action: {reason}"}), "rejected"
        else:
            result = self.kit.dispatch(name, arguments, context)
            status = "error" if result.startswith('{"error"') else "ok"
        return Step(n, name, arguments, result, int((time.perf_counter() - start) * 1000), status)


def print_step(step: Step):
    """A trace line per step: the agent's work, visible."""
    mark = {"ok": "✓", "error": "✗", "rejected": "⊘", "repeated": "↻"}[step.status]
    print(f"  {step.n}. {mark} {step.tool}({step.arguments}) -> {step.result[:110]}  [{step.ms} ms]")

    Read run() first: call the model with tools; no tool calls means done; otherwise execute each call and append the result; stop at the step budget. The rest is guard rails you'll meet in topics 7 and 8.

    Compare

    1. The tool-less chatbot claims it used extend_lab. Where did it get that name, and why is the claim worse than "I can't do that"?
    2. The 3B agent guessed an ID, got a clear error telling it what to do, and asked the customer instead. What does that tell you about choosing a model for agents?
    3. Why was the 3B agent's mistake harmless?
    4. The 7B agent recovered from its guessed ID and checked the lab. Now compare its last sentence with the "changes" line. What happened?
    Compare with my answers
    1. From the system prompt, which mentions the tool; the 7B chatbot even prints fake "tool output". A false claim of action is the worst outcome: the customer believes their lab is extended and loses access days later. Never report actions from model text.
    2. Agents need models that are good at multi-step tool use: reading an error and taking the suggested next step. Small models can follow single tool calls but give up or loop on multi-step tasks. Choose by measuring on your tasks (Module 09).
    3. Identity came from the app (context["customer"]), so the guessed ID was checked against Mei's enrolments and refused, and nothing was written. Guard rails in code make a weak model safe, just not useful.
    4. It said "I have extended your AI-102 lab… new end date 2026-10-23" without ever calling extend_lab: the date is its own arithmetic, and the audit log shows no change. In another run with the same model and prompt it did call extend_lab and the log showed the change. Agents are probabilistic, so the outcome you report must come from tool results and logs. Milestone 7 does exactly that: only code writes the confirmation.
3

Check

Agents.

1. What makes a system an agent rather than a tool-using chatbot?

The model chooses a sequence of steps towards a goal, observing results and deciding what to do next, usually including actions that change things, rather than answering one message with at most a fixed look-up.

2. Name three things code, not the model, must control in an agent.

Any three of: which tools exist; the identity and permissions tools run with; the step budget and stop conditions; which actions need human approval; idempotency of writes; logging and tracing.

3. When is an agent the wrong choice?

When the steps are always the same (use a workflow), when one look-up answers the question (use a tool call), or when errors are costly and can't be reviewed by a human. More autonomy means more cost, latency and failure modes.

Takeaway

Agents act through tools in a loop; chatbots only talk. Trust the audit log, not the prose, and give agents only the autonomy the task needs.
