State and Memory

A model remembers nothing between calls. Everything an agent 'knows' about the task so far, the conversation, or the learner is state your code keeps and sends back. Decide deliberately what that is, where it lives, how long it lasts and what it must never contain. You'll give the agent a memory tool, start a fresh session, and watch it use what it saved.

1

Learn

The model forgets; your code remembers on purpose.

Definition

State is everything an agent system keeps between model calls so it can continue a task: the working context of the current run (messages, tool results), task state (goal, facts found, steps done, pending approvals) that can be saved and resumed, and conversation history. Memory usually means long-term state about a user or domain that persists across sessions and is recalled into future prompts.

In plain words

Short-term: what's going on in this task. Long-term: a few things worth knowing next time. Both are data your code stores and puts back into the prompt; the model itself keeps nothing.

Imagine this

A hotel. The guest's current request is on the receptionist's notepad (working context); an open booking that's waiting for the guest's confirmation is in the system (task state); "prefers a quiet room, allergic to feathers" is in the guest profile (long-term memory), and the guest can see and change it. The receptionist doesn't remember you; the hotel does.

Design decisions

DecisionGood default
Who writes long-term memory?An explicit remember tool, used when the user states a lasting preference; not automatic extraction of everything
What may it contain?Preferences and stable facts; never payment details, passwords, health or other sensitive data; enforce it in code
How big?Small (tens of facts per user), oldest out first; memory is a prompt cost on every session
Can the user see and delete it?Yes; privacy law often requires it, and trust does too
Where does task state live?A store keyed by task id, so a pause for approval survives restarts (Module 08 moves it to a database)
Long conversations?Keep the last N turns, summarise older ones (Module 02 kept 6 pairs and dropped the rest)
In the real world

Chat assistants with memory let users view, edit and delete what's remembered, and many store facts only when the user asks or clearly states a preference, because unexpected memories feel creepy and can leak in shared contexts. Enterprise agents keep task state in durable storage so a request waiting for a manager's approval survives a deployment. On Azure, conversation threads and agent state can live in Azure Cosmos DB, a common choice for per-user documents.

Traditional developer view

"State is the database; the app reads what it needs."

GenAI developer view

"State is also what goes back into the prompt. I choose it per kind (working, task, history, memory), budget its tokens, protect it like personal data, and let users control long-term memory."

Common trap

"Remember everything" memory: the agent saves every detail a user ever mentioned, including a card number pasted by mistake, and recalls it into future prompts and logs. Store only explicit, useful facts, filter sensitive data in code, and cap the size.

Interview cue

"I separate working context, durable task state, session history with summarisation, and a small long-term memory per user that's explicit, filtered for sensitive data, recalled into the system prompt, and viewable and deletable by the user."

"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 07.5

State and long-term memory

~20 minAzure OpenAIPython · pytest

Goal: implement task state and a small, safe long-term memory, test them offline, then give the agent a remember tool and use the memory in a fresh session.

  1. Run

    Three kinds of state in one file

    """Module 07: state and memory for agents, three kinds:
- TaskState: short-term working state of one multi-step task (goal, facts, steps, a pending
  approval), saved as JSON so the task can pause, for example while a human decides, and resume.
- LearnerMemory: long-term memory, small facts a learner asked us to remember, recalled at the
  start of each session. Explicit, inspectable and deletable, and it refuses sensitive data.
- trim_history: keep a long conversation within budget by summarising its older turns."""
import json
import re
import time
from dataclasses import asdict, dataclass, field
from pathlib import Path

STATE_DIR = Path(__file__).parent / "data" / "agent_state"
SENSITIVE = re.compile(r"\b(?:\d[ -]?){13,19}\b|password|passcode|\bcvv\b|\bpin\b", re.I)


@dataclass
class TaskState:
    task_id: str
    goal: str
    facts: dict = field(default_factory=dict)         # what the agent has found out so far
    done: list = field(default_factory=list)          # steps completed, in order
    pending: dict | None = None                       # an action waiting for a human's decision
    status: str = "running"                           # running | waiting | finished | failed

    def save(self, folder=STATE_DIR):
        folder = Path(folder)
        folder.mkdir(parents=True, exist_ok=True)
        (folder / f"{self.task_id}.json").write_text(json.dumps(asdict(self), indent=1), encoding="utf-8")

    @classmethod
    def load(cls, task_id, folder=STATE_DIR):
        return cls(**json.loads((Path(folder) / f"{task_id}.json").read_text(encoding="utf-8")))


class LearnerMemory:
    MAX_FACTS = 20

    def __init__(self, path=STATE_DIR / "memory.json"):
        self.path = Path(path)
        self.data = json.loads(self.path.read_text(encoding="utf-8")) if self.path.exists() else {}

    def _save(self):
        self.path.parent.mkdir(parents=True, exist_ok=True)
        self.path.write_text(json.dumps(self.data, indent=1, ensure_ascii=False), encoding="utf-8")

    def remember(self, learner: str, fact: str) -> dict:
        fact = " ".join(fact.split())
        if SENSITIVE.search(fact):
            return {"error": "not stored: memory never keeps card numbers, passwords or PINs"}
        facts = self.data.setdefault(learner, [])
        if any(f["fact"].lower() == fact.lower() for f in facts):
            return {"status": "already remembered"}
        facts.append({"fact": fact, "saved": time.strftime("%Y-%m-%d")})
        del facts[:-self.MAX_FACTS]                   # oldest go first: memory is small on purpose
        self._save()
        return {"status": "remembered", "fact": fact}

    def forget(self, learner: str, containing: str) -> int:
        before = len(self.data.get(learner, []))
        self.data[learner] = [f for f in self.data.get(learner, []) if containing.lower() not in f["fact"].lower()]
        self._save()
        return before - len(self.data[learner])

    def recall(self, learner: str) -> list[str]:
        return [f["fact"] for f in self.data.get(learner, [])]

    def as_prompt(self, learner: str) -> str:
        facts = self.recall(learner)
        return "" if not facts else "Known about this learner from earlier sessions:\n" + "\n".join(f"- {f}" for f in facts)


def trim_history(messages, keep_last: int = 6, summarize=None):
    """Keep the last `keep_last` messages; replace older ones with one summary message.
    `summarize(text) -> str` is usually a cheap model call; without it, older turns are dropped."""
    if len(messages) <= keep_last:
        return list(messages)
    older, recent = messages[:-keep_last], messages[-keep_last:]
    if summarize is None:
        return list(recent)
    text = "\n".join(f"{m['role']}: {m['content']}" for m in older if m.get("content"))
    return [{"role": "system", "content": "Summary of the earlier conversation: " + summarize(text)}] + list(recent)
  2. Verify

    Offline tests

    """Drill 07.5: agent state and memory, offline.  Run:  pytest -q test_memory.py"""
from memory import LearnerMemory, TaskState, trim_history


def test_task_state_survives_a_restart(tmp_path):
    state = TaskState("t1", goal="move Diego's AZ-104 class", facts={"enrolment_id": "TC-20877"},
                      pending={"tool": "reschedule", "preview": "Move TC-20877 ($50)"}, status="waiting")
    state.save(tmp_path)
    again = TaskState.load("t1", tmp_path)
    assert again == state and again.status == "waiting" and again.pending["tool"] == "reschedule"


def test_memory_remembers_recalls_and_forgets(tmp_path):
    memory = LearnerMemory(tmp_path / "memory.json")
    assert memory.remember("L-MEI", "Prefers  weekend classes")["status"] == "remembered"
    assert memory.remember("L-MEI", "prefers weekend classes")["status"] == "already remembered"
    assert LearnerMemory(tmp_path / "memory.json").recall("L-MEI") == ["Prefers weekend classes"]   # persisted
    assert memory.recall("L-DIEGO") == []                                                          # per learner
    assert "weekend" in memory.as_prompt("L-MEI") and memory.as_prompt("L-DIEGO") == ""
    assert memory.forget("L-MEI", "weekend") == 1 and memory.recall("L-MEI") == []


def test_memory_refuses_sensitive_data(tmp_path):
    memory = LearnerMemory(tmp_path / "memory.json")
    assert "error" in memory.remember("L-MEI", "Card 4111 1111 1111 1111 for future payments")
    assert "error" in memory.remember("L-MEI", "My password is hunter2")
    assert memory.recall("L-MEI") == []


def test_memory_is_small_on_purpose(tmp_path):
    memory = LearnerMemory(tmp_path / "memory.json")
    for i in range(25):
        memory.remember("L-MEI", f"fact number {i}")
    facts = memory.recall("L-MEI")
    assert len(facts) == 20 and facts[0] == "fact number 5"


def test_trim_history_summarises_older_turns():
    messages = [{"role": "user" if i % 2 == 0 else "assistant", "content": f"m{i}"} for i in range(10)]
    trimmed = trim_history(messages, keep_last=4, summarize=lambda text: f"{text.count(chr(10)) + 1} older messages")
    assert trimmed[0] == {"role": "system", "content": "Summary of the earlier conversation: 6 older messages"}
    assert trimmed[1:] == messages[-4:]
    assert trim_history(messages, keep_last=4) == messages[-4:]
    assert trim_history(messages[:3], keep_last=4) == messages[:3]

  3. Run

    Two sessions, one memory

    """Drill 07.5: long-term memory as a tool. In session 1 the learner states preferences and the
agent stores them with `remember`; session 2 starts fresh (no chat history), recalls them,
and uses them to pick a date."""
from datetime import date

from pydantic import BaseModel, Field

import desk
from agent import Agent, print_step
from desk_tools import SYSTEM, WRITE_TOOLS, kit
from llm import MODEL, get_client
from memory import STATE_DIR, LearnerMemory

memory = LearnerMemory(STATE_DIR / "memory.json")
memory.forget("L-DIEGO", "")              # every fact contains "": start the drill with an empty memory


class FactArgs(BaseModel):
    fact: str = Field(description="A short, lasting preference or fact the learner asked you to remember")


@kit.register(FactArgs, needs_context=True)
def remember(args, context):
    """Save a lasting preference the learner states (for example preferred class days or contact channel),
    so future sessions know it. Never store payment details, passwords or health information."""
    return memory.remember(context["learner"], args.fact)


client = get_client()
context = {"learner": "L-DIEGO"}

print("SESSION 1")
agent = Agent(client, MODEL, kit, SYSTEM, write_tools=WRITE_TOOLS, on_step=print_step)
# A weekday that matches one later AZ-104 session (dates are relative to today in desk.py).
weekday = date.fromisoformat(desk.upcoming_sessions("C110")[1]).strftime("%A")
print(" ", agent.run(f"Please remember that I can only attend classes that start on a {weekday}, "
                     "and that I prefer email over phone calls.", context).answer)
print("  stored:", memory.recall("L-DIEGO"))

print("\nSESSION 2 (new conversation; memory goes into the system prompt)")
agent = Agent(client, MODEL, kit, SYSTEM + "\n\n" + memory.as_prompt("L-DIEGO"),
              write_tools=WRITE_TOOLS, on_step=print_step)
print(" ", agent.run("Which later AZ-104 date would suit me? Don't book anything yet.", context).answer)
print("  available:", [(d, date.fromisoformat(d).strftime("%A")) for d in desk.upcoming_sessions("C110")])

  4. Think

    Memory and its risks

    1. Session 2 had no chat history. How did the agent know Diego's preference?
    2. What should happen if Diego says "remember my card 4111 1111 1111 1111 for next time"?
    3. Where would a pending approval live, and why not in long-term memory?
    Compare with my answers
    1. memory.as_prompt() added "Known about this learner from earlier sessions" to the system prompt. The model didn't remember anything; the code did, and put it back in front of the model.
    2. LearnerMemory.remember refuses it in code (the SENSITIVE check), and the agent should explain that payment details are never stored. Don't rely on the prompt alone for this.
    3. In task state (TaskState.pending), keyed by task, with an expiry. It belongs to one task, not to the learner's lasting profile; Milestone 7 keeps pending actions in an ActionStore for the same reason.
3

Check

State and memory.

1. Does the model "learn" Diego's preference in Drill 07.5?

No. Its weights never change. The application stored a fact and inserted it into later prompts; delete the file and the "memory" is gone.

2. A conversation reaches 60 turns. What do you send to the model?

The system prompt, long-term memory, a summary of older turns, and the most recent turns in full, within a token budget; plus the current task state if a task is in progress.

3. Why cap long-term memory at a small number of facts?

It's sent with every session (cost and latency), old facts go stale, and more stored personal data means more privacy risk. A short list of explicit preferences is enough.

Takeaway

Models are stateless. Choose what your code keeps (working context, task state, history, memory), how long, and what it must never contain.
