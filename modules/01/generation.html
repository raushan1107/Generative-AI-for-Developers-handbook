How LLMs Generate Responses

The model writes one token at a time: score every candidate, pick one, append, repeat. That loop explains streaming, variety, temperature and hallucination. You'll implement the maths yourself in 25 lines, then look at your real model's probabilities.

1

Learn

A loop of educated guesses.

Definition

LLMs generate text autoregressively: at each step the model computes a probability distribution over its vocabulary for the next token, a decoding strategy selects one token from that distribution, the token is appended to the input, and the process repeats until a stop condition is reached.

In plain words

The model writes one token at a time. Each step, every possible next token gets a score ("Jupiter: 96%, Saturn: 2%…"); one is picked, added to the text, and the model goes again with the slightly longer text. That's why answers appear word by word: you're watching the loop run.

Temperature: how adventurous the pick is

The model produces raw scores (logits); softmax turns them into probabilities. Temperature divides the scores before softmax. Low temperature sharpens the distribution so the top choice almost always wins; high temperature flattens it so long shots get a real chance. It changes variety, never knowledge.

Imagine this

A cautious friend and an adventurous friend order from the same menu. The cautious one (low temperature) orders the bestseller every time. The adventurous one (high temperature) sometimes picks the weird special. Same menu, same kitchen. Neither knows more about food.

Why models hallucinate

The model is trained to produce likely text, not true text. Usually they overlap. When the model lacks the fact (TrainCrest's actual voucher policy, last week's price, a learner's enrolment), it still produces the most likely-sounding text, fluently and confidently.

Imagine this

A student in an oral exam who didn't study chapter 7 doesn't stay silent. They give a confident, well-structured answer built from everything that sounds related. Sometimes it's even right. The cure is the same as for the student: hand them the textbook page (grounding, Module 06) and let them say "I don't know" (prompting, Module 03).

In the real world

Press "regenerate" in ChatGPT or Claude.ai and you get a different answer: that's sampling. Watch the answer appear word by word: that's the loop, streamed. Products that must be consistent (extracting invoice fields, routing tickets) constrain the output format and validate it, rather than hoping sampling behaves.

Traditional developer view

"If the output is wrong, the model is buggy. Find a better model."

GenAI developer view

"Wrong-but-fluent is the expected failure mode of next-token prediction. I reduce it by design: give facts, constrain output, allow abstaining, and evaluate."

Interview cue

"Why do LLMs hallucinate?" "They're optimised to generate plausible continuations, not to verify facts. When the needed information isn't in the context or training data, the most plausible text can be false." Then name two mitigations: grounding with retrieved data, and allowing the model to abstain.

llm.py
"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 01.7

Temperature from scratch: softmax and sampling

~10 minPure Python · no API

Goal: see exactly what temperature does to probabilities and to 1,000 samples, with no black box.

  1. Run

    Create and run the script

    """Drill 01.7: temperature from scratch. Turn scores into probabilities, then sample."""
import math
import random
from collections import Counter

# Scores ("logits") a model might give five candidate words after:
#   "Your exam voucher will arrive ..."
LOGITS = {"soon": 4.0, "tomorrow": 3.2, "today": 2.5, "eventually": 1.0, "never": -1.0}


def softmax(logits, temperature):
    """Divide scores by the temperature, then normalise them into probabilities."""
    scaled = {w: s / temperature for w, s in logits.items()}
    top = max(scaled.values())
    exps = {w: math.exp(s - top) for w, s in scaled.items()}  # subtract the max for numerical safety
    total = sum(exps.values())
    return {w: e / total for w, e in exps.items()}


rng = random.Random(42)
for t in (0.2, 0.7, 1.0, 1.5, 3.0):
    probs = softmax(LOGITS, t)
    picks = Counter(rng.choices(list(probs), weights=list(probs.values()), k=1000))
    print(f"\ntemperature = {t}")
    for word, p in probs.items():
        print(f"  {word:11} {p:6.1%}  {'#' * round(p * 40):40} picked {picks[word]:4} / 1000")

  2. Think

    Translate the numbers into product decisions

    At temperature 3.0, "never" was picked 55 times out of 1,000. Imagine that word in a message to a learner waiting for a voucher. Which TrainCrest features would you run at low temperature, and which could tolerate high?

    Compare with my answer

    Low: ticket triage, data extraction, policy answers, anything a program parses or a customer relies on. Higher: brainstorming course names, marketing drafts, quiz question ideas, where variety is the point and a human reviews. And remember: many reasoning models fix temperature for you (Module 02).

Drill 01.8

Watch your model pick its next token

~10 minAzure OpenAIPython

Goal: read the real probability distribution behind one token from your deployment, and see sampling produce different answers to the same prompt.

Before you start: token probabilities (logprobs) are only returned by some models; many reasoning models refuse the parameter. The script tells you if yours does. If so, read the expected output, or try a deployment whose feature table lists logprobs.

  1. Run 
    """Drill 01.8: the real probability distribution behind one token, and sampling in action."""
import math

import openai

from llm import get_client, MODEL

client = get_client()

# Part A: what were the candidates for the first token?
try:
    response = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": "Complete with one word only: The largest planet in our solar system is"}],
        logprobs=True,     # return the log-probability of each generated token
        top_logprobs=5,    # ...and the top 5 alternatives at each position
    )
    lp = response.choices[0].logprobs
    if lp is None or not lp.content:
        raise ValueError("no logprobs returned")
    first = lp.content[0]
    print(f"Chosen first token: {first.token!r}\n")
    for cand in first.top_logprobs:
        pct = math.exp(cand.logprob) * 100
        print(f"  {cand.token!r:14} {pct:6.2f}%  {'#' * round(pct / 4)}")
except (openai.BadRequestError, ValueError) as err:
    print("This model doesn't return token probabilities:", err)

# Part B: the same open-ended prompt, three times
print("\nThree samples of the same prompt:")
for i in range(3):
    r = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": "Invent a 4-word slogan for an online tech training company. Slogan only."}],
    )
    print(f"  {i + 1}. {r.choices[0].message.content.strip()}")

3

Check

Explain it in one sentence each.

1. Does setting temperature to 0 make the model correct?

No. It makes the top choice win more consistently. If the top choice is a hallucination, you'll get the same wrong answer reliably.

2. Why can a model state a wrong refund policy so confidently?

Because it produces the most plausible continuation, and confidence is just fluent text. Without the real policy in its context, a common policy from training data looks most likely.

Takeaway

Generation is sampling from probabilities. Design so that the likely answer is also the right one: give facts, constrain, verify.
