What Is Generative AI?

Older AI judged things: spam or not spam, cat or dog. Generative AI makes things: a reply, a function, a summary, an image. Learn what that really means, then see it with your own eyes in two drills.

1Learn→2Do→3CheckLearn 10 min · Do 20 min
1

Learn

Generators vs judges, and why it matters to your code.

Definition

Generative AI is a class of AI models that create new content (text, code, images, audio or video) by learning the patterns of their training data and producing new outputs that follow those patterns, usually in response to a prompt.

In plain words

Older AI mostly judged: "is this email spam?", "is this a cat?". Generative AI makes: "write a reply to this email", "draw a cat riding a scooter". It learned what good text or images look like, and produces new ones on request.

Imagine this

A food critic tastes a pizza and says "good" or "bad". That's traditional, discriminative AI. A chef who has tasted ten thousand pizzas makes you a new one that has never existed, in the style you asked for. Same knowledge of food, completely different job.

WhatModels that produce new text, code, images or audio from a prompt.
WhyLanguage is the interface to most work: emails, documents, code, tickets, reports.
WhenTasks with many acceptable answers: drafting, summarising, explaining, extracting, conversing.
In the real world

You already use generative AI daily. A coding assistant completing your function, an email client drafting a reply, a meeting app writing minutes, a support widget answering in full sentences: all of these generate new text from a prompt the product builds for you. Behind each one is a developer who decided what goes into that prompt, which is what you're learning to do.

Traditional developer view

"My functions return values I can predict and test exactly."

GenAI developer view

"Generative output is open-ended. I test for properties (valid format, right facts, right tone) across many runs, not for one exact string."

Interview cue

Asked "what is generative AI?", say: "Models that generate new content by learning patterns from data, as opposed to models that only classify or predict a label." Then give one example of each. Interviewers like the contrast more than the definition.

Before you run this code

Run every drill from your genai-labs folder with its virtual environment active. Two files must be there: .env (settings) and llm.py (the shared helper every drill imports). By default they use a free local model with Ollama: install Ollama, then ollama pull llama3.2; no key is needed. To use Azure OpenAI or OpenAI instead, change LLM_PROVIDER in .env.

Easiest: download the genai-labs starter kit (every helper, data file and drill script), unzip it, copy .env.example to .env, and run pip install -r requirements.txt. Full walkthrough: Helpers and smoke test.

llm.py
"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 01.1

First conversation: notice the weirdness

~10 minFoundry playgroundor ChatGPT / Claude.ai

Goal: before any code, experience the four behaviours this module explains: variety, confident errors, frozen knowledge and no memory.

  1. No-code

    Open a chat window

    Use the chat playground in Microsoft Foundry with your chat deployment, or ChatGPT or Claude.ai.

  2. No-code

    Run five tiny experiments

    1. Variety: "Suggest a name for an online tech training company." Regenerate three times.
    2. Confident errors: "What is TrainCrest's refund policy if I cancel 10 days before my course?" (TrainCrest's policy here is fictional.)
    3. Arithmetic: "What is 48,739 × 6,218? Answer with the number only." (Correct: 303,059,102.)
    4. Frozen knowledge: "What's today's date, and what was the biggest tech news this week?"
    5. No memory: say "My name is Mei." Then start a new chat and ask "What's my name?"
  3. Think

    Explain each result before you read on

    Write one sentence per experiment: why did the model behave like that?

    Compare with my explanations
    • Different names each time: the model samples from probabilities (topic 5).
    • An invented policy or a polite deflection: without facts, it produces plausible text (topic 5). Newer models guess less often, but never rely on it.
    • Arithmetic may be slightly off: numbers are chopped into tokens (topic 4). Chat apps often run a hidden calculator tool; the raw API doesn't.
    • Date and news unknown or guessed: knowledge is frozen at a cutoff (topic 6). Apps that answer correctly add web search around the model.
    • The new chat forgot Mei: each request starts with an empty context (topic 4). Chat apps resend history for you; in Module 02 you'll do it yourself.

Remember: “Everything weird you just saw comes from one fact: it's predicting the next token from what's in front of it right now.”

Drill 01.2

One brief, three outputs, and test the generated code

~10 minAzure OpenAIPython · AI assistant

Goal: see one model generate marketing text, working code and structured data from the same brief, then treat generated code the way a professional does: test it.

  1. Run

    Create and run the script

    """Drill 01.2: one model, one brief, three very different kinds of output."""
from llm import get_client, MODEL

client = get_client()

BRIEF = ("TrainCrest is launching a 3-day online course, 'Generative AI for Developers', "
         "starting on 20 March 2027, priced at $1,200, with hands-on labs on Azure.")

TASKS = {
    "Marketing text": "Write a 40-word announcement for LinkedIn.",
    "Python code": "Write a Python function days_until_start(today: date) -> int for this course. Code only.",
    "JSON record": 'Return only JSON with keys "title", "start_date" (YYYY-MM-DD), "price_usd", "format".',
}

for label, task in TASKS.items():
    response = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": f"{BRIEF}\n\n{task}"}],
    )
    print(f"\n===== {label} =====")
    print(response.choices[0].message.content.strip())
    $ python lab01_02_one_brief.py
    Expected output (abridged; yours will differ) 
    ===== Marketing text =====
New course alert! 'Generative AI for Developers' starts 20 March 2027: 3 days of hands-on Azure labs...

===== Python code =====
from datetime import date
def days_until_start(today: date) -> int:
    return (date(2027, 3, 20) - today).days

===== JSON record =====
{"title": "Generative AI for Developers", "start_date": "2027-03-20", "price_usd": 1200, "format": "online"}
  2. Ask AI

    Turn the generated function into tested code

    Copy the generated function into a new file course_dates.py. Then ask your assistant:

    In #course_dates.py there is a function days_until_start(today). Write pytest tests in
test_course_dates.py covering: a date well before the start, the day before, the start day
itself (expect 0) and a date after the start (expect a negative number). Use fixed dates,
not date.today(). Then run pytest and show me the result. Don't modify course_dates.py.
    Why this prompt works: it names the file and function, lists the exact cases including edge cases, forbids flaky date.today(), and stops the assistant from "fixing" the code to fit its own tests.
  3. Verify 
    $ pytest -q test_course_dates.py
    • All four tests pass, or a failing test shows the generated code was wrong (it happens: that's the lesson).
    • The JSON output parses: save it as record.json and run python -m json.tool record.json. If the model wrapped it in ```json fences, it won't parse as-is (Module 03 fixes that).

Try this: change the brief's start date and run again. Does the generated code update the date? Generation follows the prompt, not a database.

3

Check

Two questions before you move on.

1. A spam filter and a reply-drafting assistant both use AI. Which is generative, and why?

The reply drafter: it creates new text. The spam filter is discriminative: it picks one of a fixed set of labels.

2. Why did Drill 01.2 ask you to test the generated function?

Generated code is plausible, not guaranteed correct. Tests turn "looks right" into "is right", the same habit you'll apply to every AI-generated artefact.

Takeaway

Generative AI writes new content from patterns. Your job as a developer is to decide what it should generate, and to check that it did.
