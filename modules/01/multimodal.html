Multimodal AI

Real-world input is messy: screenshots of errors, photos of receipts, scanned forms, voice notes. Multimodal models read them together with your text. You'll send a screenshot of a real error to your model and get a support-ready diagnosis back.

Text + imagesDocumentsAudioDrill 01.12
1Learn→2Do→3CheckLearn 8 min · Do 12 min
1

Learn

One model, several senses.

Definition

Multimodal models accept and/or produce more than one type of data (modality), such as text, images, audio and video, within a single model, for example answering a text question about an image.

In plain words

Early LLMs only read text. Many current models can also look at a screenshot or a scanned PDF, and some can listen and speak. For you, it means a learner can paste a screenshot of a lab error and the assistant can understand it, with no separate image system.

WhatOne model that understands text plus images, documents or audio.
WhyUsers send screenshots, photos, scans and voice notes, not tidy text.
WhenError screenshots, receipts and invoices, ID or form extraction, damage photos, voice assistants.

Facts worth remembering

  • Images are converted into tokens too, so a large image costs input tokens like text; apps often resize images first.
  • Not every model is multimodal. Check the model's input modalities in the catalogue before designing around images.
  • Image and speech generation usually need separate, specialised models.
In the real world

Support tools let customers attach screenshots and let the assistant read them; expense apps read receipt photos; insurers triage damage photos; coding assistants accept a screenshot of a UI bug or a whiteboard sketch. In each case the value is skipping a separate OCR or vision pipeline and reasoning over the image and the text together.

Interview cue

"Multimodal means several input or output types in one model. A learner pastes a screenshot of a lab error, and the same model that chats with them reads the error and suggests the fix."

2

Do

Diagnose a real error from a screenshot.

Drill 01.12

Read a screenshot: diagnose an error from an image

~12 minAzure OpenAIPython

Goal: send an image and a question in one request and get a useful, support-style answer.

Before you start: create a real error to photograph. In a terminal run python -c "import requests; requests.get('http://localhost:9')", take a screenshot of the error, and save it as screenshot.png in your lab folder. Check that your model lists images as an input modality.

  1. Run 
    """Drill 01.12: one request, two modalities: a screenshot plus a text question."""
import base64
import mimetypes
import sys
from pathlib import Path

from llm import get_client, MODEL

path = Path(sys.argv[1] if len(sys.argv) > 1 else "screenshot.png")
mime = mimetypes.guess_type(path.name)[0] or "image/png"
image_b64 = base64.b64encode(path.read_bytes()).decode()

client = get_client()
response = client.chat.completions.create(
    model=MODEL,
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": (
                "A learner sent this screenshot from a TrainCrest hands-on lab. "
                "1) What is the error? 2) What is the most likely cause? "
                "3) What should support tell the learner to try next? Be brief.")},
            {"type": "image_url", "image_url": {"url": f"data:{mime};base64,{image_b64}"}},
        ],
    }],
)
print(response.choices[0].message.content)
print("\ninput tokens (text + image):", response.usage.prompt_tokens)
    $ python lab01_12_vision.py screenshot.png
    Expected output (abridged) 
    1) The error is a requests ConnectionError: "Failed to establish a new connection... Connection refused".
2) Likely cause: nothing is listening on localhost port 9, the service isn't running or the port is wrong.
3) Next step: check the service is started and the URL/port matches its configuration.

    • The model read text from the image correctly (compare with your screen).
    • Note the input token count: the image cost far more tokens than your question.
    • Try a photo of something non-technical (a receipt, a whiteboard). Is the answer still sensible?
Open alternative · Claude or a local vision model
import base64
from claude_llm import client, CLAUDE_MODEL, FALLBACK, text_of

image_b64 = base64.b64encode(open("screenshot.png", "rb").read()).decode()
msg = client.beta.messages.create(
    model=CLAUDE_MODEL, max_tokens=4000,
    messages=[{"role": "user", "content": [
        {"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": image_b64}},
        {"type": "text", "text": "What is this error, the likely cause, and the next step? Be brief."},
    ]}],
    **FALLBACK,
)
print(text_of(msg))

3

Check

One question.

1. Your vision feature works but costs more than expected. Where would you look first?

Image input tokens: large images cost many tokens. Resize or crop images before sending, and send them only when they're needed.

Takeaway

Multimodal models remove whole pipelines (OCR, image classifiers), but images are paid for in tokens like everything else.
