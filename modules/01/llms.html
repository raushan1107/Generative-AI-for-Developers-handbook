Large Language Models: A Giant Autocomplete

An LLM is a giant autocomplete trained on a huge amount of text. That sounds too simple to explain code generation, until you build a tiny one yourself in 30 lines and watch it generate text. Then the leap to a real LLM is just scale and attention.

1

Learn

What's inside the model, without the maths.

Definition

A large language model is a deep neural network, usually based on the transformer architecture, trained on very large amounts of text to predict the next token in a sequence. Its learned parameters (often billions) let it understand and generate human language and code.

In plain words

Your phone keyboard suggests the next word from your last couple of words. An LLM does the same job, but it has learned from a large part of the internet, books and code, and it looks at thousands of previous words at once. That scale is what turns autocomplete into something that can write SQL and explain a refund policy.

The three words in the name

LargeBillions of parameters (numbers adjusted during training) and trillions of training tokens. Scale is where the surprising abilities come from.
LanguageIt works on text, and anything that can be written as text: code, JSON, SQL, tables, even descriptions of images.
ModelA mathematical function: tokens in, probabilities for the next token out. Nothing more, and that's worth remembering.

The transformer and attention

Almost every modern LLM is a transformer, an architecture introduced in the 2017 paper "Attention Is All You Need". Its key trick is attention: for every word, the model works out which other words in the text matter for understanding it.

Imagine this

Read: "The laptop didn't fit in the bag because it was too big." What is "it"? The laptop. Now: "…because it was too small." Now "it" is the bag. You resolved that instantly by paying attention to "big" or "small". Attention lets the model do the same, for every word against every other word, all at once.

Facts worth remembering

  • LLMs process tokens, not words or characters (next topic).
  • An LLM by itself has no memory between calls and no internet access. Chat apps add those around the model.
  • Bigger models are usually more capable but slower and pricier. Small models are often good enough for focused tasks.
  • The "chat" models you'll use were further trained to follow instructions and hold conversations (topic 6).
In the real world

Code completion in your editor is the clearest LLM-as-autocomplete you'll see: the assistant sends the code around your cursor as context and asks the model to continue it. The quality differences between coding tools come largely from what context they send (open files, related symbols, your recent edits), not just from the model.

Interview cue

"An LLM is a transformer trained to predict the next token; attention lets it use the whole context for that prediction." Three bold words, one sentence: a strong answer.

Do

Build the great-great-grandparent of an LLM from scratch.

Drill 01.4

Build a toy next-word predictor from scratch

~15 minPure Python · AI assistantno API needed

Goal: understand next-token prediction by building a "bigram" model that learns which word follows which, then generates text by sampling.

  1. Your prompt

    Ask your assistant to build it

    Goal:        a Python script lab01_04_bigram.py that …
Context:     a tiny corpus of sentences about …; no external libraries
Constraints: "training" = counting …; predict() returns …; generate() samples …;
             fixed random seed so runs are repeatable
Done when:   it prints the next-word probabilities after "the" and 3 generated sentences

    Hint: a bigram model counts, for each word, which words followed it in the corpus. The probability of the next word is its count divided by the total. Ask for collections.Counter and random.choices with weights.

    Compare with my prompt
    Write lab01_04_bigram.py, a tiny bigram language model in pure Python (standard library only).
- CORPUS: about 10 short lowercase sentences about an online course, its labs, exam vouchers
  and trainers, with "." as separate tokens.
- "Training": split on whitespace and count, for each word, which words follow it
  (defaultdict of Counter).
- predict(word) returns {next_word: probability} from those counts.
- generate(start, length=12, seed=None) repeatedly samples the next word with random.choices
  using the probabilities as weights; use random.Random(seed) so runs are repeatable.
- Print the probabilities after "the" and after "labs", then 3 generated sentences (seeds 0,1,2).
Keep it under 50 lines with short comments.
  2. Run

    Run it (or compare with the reference)

    Reference solution
    """Drill 01.4: a toy next-word predictor. The great-great-grandparent of an LLM."""
import random
from collections import Counter, defaultdict

CORPUS = """
the course starts on monday . the course includes hands-on labs .
the labs run on azure . the exam voucher arrives after the course .
the voucher is valid for twelve months . the labs are available for thirty days .
the course is online . the trainer explains the labs . the learner completes the labs .
"""

# "Training": count which word follows which.
words = CORPUS.split()
next_counts = defaultdict(Counter)
for current, following in zip(words, words[1:]):
    next_counts[current][following] += 1


def predict(word):
    """Probability of each possible next word, learned purely by counting."""
    counts = next_counts[word]
    total = sum(counts.values())
    return {w: c / total for w, c in counts.most_common()}


def generate(start, length=12, seed=None):
    """'Inference': repeatedly sample the next word from the predicted probabilities."""
    rng = random.Random(seed)
    out = [start]
    for _ in range(length):
        probs = predict(out[-1])
        if not probs:
            break
        out.append(rng.choices(list(probs), weights=list(probs.values()))[0])
    return " ".join(out)


print("After 'the': ", {w: f"{p:.0%}" for w, p in predict("the").items()})
print("After 'labs':", {w: f"{p:.0%}" for w, p in predict("labs").items()})
print()
for seed in range(3):
    print("Generated:", generate("the", seed=seed))

  3. Think

    From toy to LLM

    Your model generated fluent-looking fragments and nonsense like "the course is online . the labs run on monday" (nobody said that). Answer: what's missing compared with a real LLM?

    Compare with my answer
    • Context: yours looks at one previous word; an LLM looks at thousands of tokens, with attention deciding which ones matter.
    • Learned meaning: yours counts exact words; an LLM learns representations where "voucher" and "coupon" are related.
    • Scale: 100 words of corpus vs trillions of tokens, and a handful of counts vs billions of parameters.
    • The same job: both predict a probability for each next token and sample. That part you've now built yourself.

    Notice too that it produced plausible but invented combinations. Real LLMs do the same at a much more convincing level: that's hallucination's root.

3

Check

Two quick ones.

1. What does attention let a transformer do that your bigram model can't?

Use the whole context, weighting which earlier tokens matter for each prediction, instead of only the previous word.

2. Does an LLM look things up on the internet when you call the API?

No. It only uses its trained parameters and what's in your request. Web search, when you see it, is a tool the application adds around the model.

Takeaway

Strip away the scale and an LLM is your bigram model's descendant: predict the next token, sample, repeat. Everything else is how well it predicts.
