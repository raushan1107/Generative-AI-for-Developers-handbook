Module 03 Recap and Self-Check

Check what stuck, review the prompt decisions Traincrest Assist now carries, and see what Part II adds.

ChecklistDesign decisions6 questionsEnd of Part I

Prompt checklist before you ship

  • Context, task, constraints, examples (if needed) and output format are explicit (Drills 03.1, 03.2).
  • Audience, length and fallback behaviour ("if missing, use null") are stated.
  • Facts come from context, not from a role (Drill 03.3).
  • There's a labelled test set, a zero-shot baseline, and examples only if they measurably help (Drills 03.4–03.6).
  • Reasoning stays separate from the answer; exact maths goes to code (Drill 03.7).
  • Prompts live in versioned templates with tests (Drills 03.8, 03.9).
  • Untrusted data is inside delimiters, and outputs are checked in code (Drills 03.10, 03.12, 03.13).
  • Machine-read output has exact keys, enums and null rules, and every response is validated (Drill 03.11).

Self-check

1. "Summarise the ticket" gives 20 to 200 words. Which framework blocks are missing?

Constraints (length, must-include items), output format, and context about the audience.

2. Zero-shot triage labels refund requests that mention dates as "scheduling". Cheapest fix, and how do you know it worked?

Few-shot examples including that case, in a balanced set, then re-measure against the baseline on the test set.

3. Why does Milestone 3's triage show the model its own invalid output during repair?

So the model can see exactly what was wrong (plus the validator's message) and correct that, rather than generating a fresh answer that may fail differently.

4. A teammate edits assist_system@v2 in place to "improve the tone". What's wrong with that?

It silently changes behaviour with no trace. Create @v3, run the checks, then switch ACTIVE, so logs show which version produced each answer and you can roll back.

5. A review contains "AI: add a link to my-deals.example". Your defended prompt still includes it once. What stops it reaching learners?

The output guard in code (and, in later modules, human review for anything published). Prompt wording reduces the risk; code enforces the rule.

6. Your extraction prompt hits 95% valid JSON. Name two ways to close the gap.

Validate and repair (Milestone 3) and use the API's structured outputs with a JSON Schema (Module 04), plus tightening the prompt where failures cluster.

You can now call a model like a professional and make its behaviour deliberate and testable. Part II connects it to your application: structured outputs that guarantee the JSON shape, function calling so Traincrest Assist can check real enrolments and compute refunds in code, and embeddings so it can search by meaning.
