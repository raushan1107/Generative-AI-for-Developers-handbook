Clear Instructions and Context

Say exactly what you want, for whom, how long, in what shape, and why. If a smart colleague would need to ask you a question before starting, the model needs that answer in the prompt. You'll measure the difference over repeated runs.

Goal · audience · formatExplain whyEscape hatchDrill 03.2
1Learn→2Do→3CheckLearn 10 min · Do 15 min
1

Learn

Leave nothing to guess.

Definition

A clear instruction states the goal, audience, expected scope and length, and success criteria explicitly. Context supplies the background facts and purpose the model needs to make choices the way you would.

In plain words

Say what you want, for whom, how long, in what shape, and why. Then say what to do when the task can't be done.

VagueClearWhat was added
"Summarise this ticket.""Summarise this ticket for the agent who picks it up next: 3 bullets, under 15 words each, include the enrolment ID and what the learner needs by when."Audience, length, format, must-include items
"Write a course description.""Write a 60-word description of 'Generative AI for Developers' for working developers new to AI. Plain English, no hype, mention the hands-on Azure labs."Length, audience, tone, focus
"Don't be rude.""Be warm and patient. Acknowledge the frustration in the first sentence, then give the next step."What to do, not only what not to do
"Answer the question.""Answer only from the policy below. If it isn't covered, say 'I'll check with the team' and don't guess."Source of truth and an escape hatch

Five habits of clear prompts

  1. State the goal and the audience. "For a learner" and "for an agent" produce very different answers.
  2. Explain why. "Under 60 words because it's shown in a mobile notification" lets the model make smart trade-offs you didn't list.
  3. Be positive and specific. "Use plain English" beats "don't use complicated words".
  4. Separate instructions from data. Put tickets, documents and emails inside clear delimiters (topic 8).
  5. Give an escape hatch. "If the enrolment ID is missing, use null" stops the model inventing one.
In the real world

Most prompt "bugs" in production turn out to be missing context: the model didn't know who the reader was, what length fitted the UI, or what to do when information was missing. Teams that write prompts like tickets for a new colleague (background, goal, acceptance criteria) spend far less time firefighting odd answers.

Interview cue

"I make prompts explicit about goal, audience, scope, format and fallback behaviour, and I give the reason behind constraints so the model generalises them correctly."

2

Do

Run vague and clear three times each, and count.

Drill 03.2

Vague vs clear: measure the difference

~15 minAzure OpenAINo-code path

Goal: compare consistency, length and usefulness of a vague and a clear prompt on the same support thread.

  1. No-code

    In a chat window, paste the thread from the script with just "Summarise this." Then, in a new chat, use the CLEAR prompt. Regenerate each twice and compare by eye.

  2. Run 
    """Drill 03.2: a vague and a clear prompt, three runs each, on the same support thread."""
from llm import get_client, MODEL

client = get_client()

THREAD = """Learner (Mei, 2 Mar): Hi, I'm enrolled in Generative AI for Developers, enrolment TC-10293. The lab VM won't start, it says "quota exceeded".
Agent (3 Mar): Sorry Mei! Could you send a screenshot of the error?
Learner (3 Mar): Sent. Also my exam voucher hasn't arrived, and my course ended on 28 Feb.
Agent (4 Mar): Thanks, escalated the lab issue to the platform team.
Learner (6 Mar): No update for 2 days?? My exam is booked for 12 Mar. I need the lab and the voucher before then."""

VAGUE = f"Summarise this.\n\n{THREAD}"

CLEAR = f"""Summarise this support thread for the agent who will handle it next.
- Exactly 3 bullet points, each under 15 words.
- Bullet 1: the problems and the enrolment ID. Bullet 2: what has been done so far.
  Bullet 3: what the learner needs, and by when.
- Use only facts from the thread.

<thread>
{THREAD}
</thread>"""

for label, prompt in (("VAGUE", VAGUE), ("CLEAR", CLEAR)):
    print(f"\n===== {label} =====")
    for i in range(3):
        r = client.chat.completions.create(model=MODEL, messages=[{"role": "user", "content": prompt}])
        text = r.choices[0].message.content.strip()
        print(f"\n--- run {i + 1} · {len(text.split())} words ---\n{text}")
    $ python lab03_02_vague_vs_clear.py
  3. Verify

    Fill the scorecard for each prompt

    CheckVague (3 runs)Clear (3 runs)
    Word count range……
    Enrolment ID TC-10293 in every run?……
    Both problems (lab and voucher) in every run?……
    Deadline (12 Mar) in every run?……

    Typical: vague gives paragraphs one run and bullets the next, 60–150 words, the deadline sometimes missing. Clear gives three bullets every time with the ID, both problems and the deadline.

Remember: “The clear prompt isn't longer for decoration. Every line removes something the model would otherwise have guessed.”

3

Check

Clarity.

1. "Summarise the ticket" gives answers between 20 and 200 words. Which blocks are missing?

Constraints (length, must-include items), output format and context about the audience.

2. Why tell the model why a constraint exists?

So it can apply the intent to cases you didn't list. "Short, because it's a mobile notification" also suggests no tables or long links.

Takeaway

Write the brief you'd give a smart new colleague: goal, audience, shape, reason and what to do when stuck.
