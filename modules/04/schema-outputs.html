Schema-Based Generation: Structured Outputs

Structured outputs take the next rung: you hand the API a JSON Schema, and the model's tokens are constrained so the reply always matches it. Every key present, every enum respected, every type right. You'll define the schema once as a Python class, get typed objects back, and learn the few rules strict mode insists on.

1

Learn

Don't ask for the shape. Enforce it.

Definition

Structured outputs make the model's response conform to a JSON Schema you supply (response_format={"type": "json_schema", "json_schema": {..., "strict": true}}). The service uses constrained decoding: at each step, tokens that would break the schema can't be chosen. In Python you usually write the schema as a Pydantic model and let the SDK convert it.

In plain words

JSON mode was "please use these boxes". Structured outputs is a form where the model physically can't write outside the boxes, can't skip one, and can only tick the options you printed.

Imagine this

A paper form versus an online form. On paper, people write "N/A", skip boxes and add notes in the margin. An online form has required fields, drop-down lists and a date picker, so every submission arrives in the same shape. It still can't stop someone choosing the wrong option from the list.

The rules strict mode insists on

  • Every field is required. "Optional" means may be null: write Optional[str] and the schema becomes "anyOf": [string, null]. The SDK marks every property required for you.
  • No extra keys: every object gets "additionalProperties": false.
  • Root is an object, not a list or anyOf. Wrap lists: {"items": [...]}.
  • Supported types: string, number, integer, boolean, object, array, enum, anyOf; nested models and $defs work, recursion too.
  • Limits on Azure OpenAI: up to 100 properties in total and 5 levels of nesting.

Support differs by provider and changes over time (OpenAI's own API accepts more keywords than Azure documents). Design for the strictest target and check the Azure structured outputs documentation for your model.

Descriptions are prompts

Field descriptions travel inside the schema and the model reads them. Field(description="Like TC-12345. Null if not given. Never invent one.") is an instruction exactly where it's needed. Write them as carefully as your system prompt.

In the real world

Extraction services (invoices, insurance claims, CVs, support tickets) define one Pydantic model per document type and share it between the model call, the API response and the database layer. When the business adds a field, one class changes and the schema, the docs and the validation all follow.

Traditional developer view

"I'll describe the JSON in the prompt and write a validator for the replies."

GenAI developer view

"I'll define the shape once as a type. The API enforces the shape, and my validators only deal with business rules the schema can't express."

Common trap

Believing a schema makes answers correct. It guarantees enrolment_id is a string or null; it can't stop the model inventing "TC-12345". Shape is enforced; truth is not. That's topic 6.

Interview cue

"Structured outputs use constrained decoding against a strict JSON Schema: required fields, no extra properties, enums enforced. I define it with Pydantic, handle refusal, keep unsupported keywords like pattern out of the schema and enforce them in validators."

Drill 04.3

Strict schema with Pydantic and parse()

~15 minAzure OpenAIPython · Pydantic

Goal: see the schema the API actually receives, then get typed objects back for the five messages from Drill 04.2.

  1. Run

    First, look at the schema (offline)

    """Drill 04.3: structured outputs. A Pydantic model becomes a strict JSON Schema,
the model is constrained to it, and the SDK hands back a typed object.
Run:  python lab04_03_schema.py --show-schema   (offline: print the schema the API receives)
      python lab04_03_schema.py                 (live: triage the same five messages)"""
import json
import sys
from typing import Literal, Optional

import openai
from pydantic import BaseModel, Field

from lab04_02_json_mode import MESSAGES


class Triage(BaseModel):
    learner_name: Optional[str] = Field(description="First name if given, else null")
    enrolment_id: Optional[str] = Field(description="Like TC-12345. Null if not given. Never invent one.")
    category: Literal["scheduling", "billing", "exam_voucher", "certificate", "lab_access", "account", "other"]
    urgent: bool = Field(description="True if a deadline is within 3 days or the learner is blocked")
    summary: str = Field(description="One English sentence, at most 20 words")


SYSTEM = ("You triage TrainCrest learner-support messages. A refund request is billing even if it mentions dates; "
          "asking for more lab time is lab_access.")


def show_schema():
    # pydantic_function_tool builds the same strict schema that .parse() sends.
    schema = openai.pydantic_function_tool(Triage)["function"]["parameters"]
    print(json.dumps(schema, indent=2))


def main():
    from llm import MODEL, get_client
    client = get_client()
    for text in MESSAGES:
        completion = client.chat.completions.parse(
            model=MODEL,
            messages=[{"role": "system", "content": SYSTEM}, {"role": "user", "content": text}],
            response_format=Triage,              # the SDK converts the class to a strict json_schema
        )
        message = completion.choices[0].message
        if message.refusal:                      # safety refusals come back here, not as JSON
            print("REFUSED:", message.refusal)
            continue
        t: Triage = message.parsed               # a real Triage object, already validated
        print(f"{t.category:<13} urgent={t.urgent!s:<5} id={t.enrolment_id}  {t.summary}")


if __name__ == "__main__":
    show_schema() if "--show-schema" in sys.argv else main()

  3. Verify

    What the schema fixed, and what it couldn't

    • Fixed: every reply has all five keys, every category is one of the seven, urgent is a real boolean. No key drift, no "null" strings, and your code got Triage objects, not dicts.
    • Not fixed: the small model still invented 12345 and 2019-01-19-B01C3, wrote a "John Doe" who doesn't exist, ignored "20 words", and filed Asha's reschedule as a certificate issue. Shape is guaranteed; truth and rules aren't.
    • Run against your Azure deployment and compare. Expect correct categories and IDs most of the time, which is exactly why you still need validators (topic 6) for the rest.
Open alternative · a schema-shaped answer from Claude

A dependable way to get schema-shaped data from Claude is to define a tool whose input_schema is your schema and require Claude to use it. The "tool call" is your structured answer; you never run anything.

import openai
from claude_llm import client, CLAUDE_MODEL, FALLBACK
from lab04_03_schema import SYSTEM, Triage
from lab04_02_json_mode import MESSAGES

record = {"name": "record_triage", "description": "Record the triage result.",
          "input_schema": openai.pydantic_function_tool(Triage)["function"]["parameters"]}

for text in MESSAGES:
    msg = client.beta.messages.create(
        model=CLAUDE_MODEL, max_tokens=1000, system=SYSTEM, tools=[record],
        tool_choice={"type": "tool", "name": "record_triage"},      # must answer through the tool
        messages=[{"role": "user", "content": text}], **FALLBACK)
    data = next(b.input for b in msg.content if b.type == "tool_use")
    t = Triage.model_validate(data)                                 # validate anyway
    print(f"{t.category:<13} urgent={t.urgent!s:<5} id={t.enrolment_id}  {t.summary}")
Drill 04.4

Design a schema with your AI assistant, then lint it

~15 minOffline · no API keyCopilot · Claude Code · Codex

Goal: have your assistant design a nested schema for company course enquiries, and check it against strict-mode rules before any model sees it.

  1. Ask AI

    Design course_enquiry.py

    Create course_enquiry.py with Pydantic v2 models for extracting a company's training enquiry
from an email, for use with OpenAI/Azure strict structured outputs.

Models:
- Contact: name, company, email (each may be null)
- CourseRequest: topic (str), learners (int or null), preferred_format
  (one of "live-online", "classroom", "self-paced", "any")
- CourseEnquiry (root): contact, requests (list of CourseRequest), budget_usd (int or null),
  wants_private_class (bool), deadline (string YYYY-MM-DD or null)

Rules:
- Every field is required; use Optional[...] for "may be null". Give each field a description.
- Do NOT use pattern, max_length, ge/le, EmailStr or date types: Azure strict mode rejects them.
  Enforce these with @field_validator instead: email looks like an address, learners between
  1 and 500, deadline matches YYYY-MM-DD.
- Don't create or change any other file.
    Why this prompt works: it names every field and type, states the strict-mode rules (required fields, nullable via Optional), lists the keywords to avoid and where those rules should go instead, and fences the change to one file. Without the middle rule, assistants reach straight for EmailStr and Field(ge=1).
    Reference solution
    """Drill 04.4 reference solution: a schema for course enquiries from companies.
Shape rules live in the schema; business rules (formats, ranges) live in validators."""
import re
from typing import Literal, Optional

from pydantic import BaseModel, Field, field_validator

Format = Literal["live-online", "classroom", "self-paced", "any"]


class Contact(BaseModel):
    name: Optional[str] = Field(description="Person who wrote the enquiry, or null")
    company: Optional[str] = Field(description="Company name, or null")
    email: Optional[str] = Field(description="Email address exactly as written, or null")

    @field_validator("email")
    @classmethod
    def email_looks_valid(cls, v):
        if v is not None and not re.fullmatch(r"[^@\s]+@[^@\s]+\.[^@\s]+", v):
            raise ValueError("email is not a valid address")
        return v


class CourseRequest(BaseModel):
    topic: str = Field(description="Course or topic requested, in a few words")
    learners: Optional[int] = Field(description="Number of people, or null if not stated")
    preferred_format: Format

    @field_validator("learners")
    @classmethod
    def learners_in_range(cls, v):
        if v is not None and not 1 <= v <= 500:
            raise ValueError("learners must be between 1 and 500")
        return v


class CourseEnquiry(BaseModel):
    contact: Contact
    requests: list[CourseRequest] = Field(description="One entry per course or topic asked about")
    budget_usd: Optional[int] = Field(description="Total budget in US dollars, or null")
    wants_private_class: bool
    deadline: Optional[str] = Field(description="Date training must finish by, as YYYY-MM-DD, or null")

    @field_validator("deadline")
    @classmethod
    def deadline_is_iso_date(cls, v):
        if v is not None and not re.fullmatch(r"\d{4}-\d{2}-\d{2}", v):
            raise ValueError("deadline must be YYYY-MM-DD")
        return v
  2. Run

    Lint it like a compiler would

    schema_lint.py builds the exact schema the SDK would send and checks it against Azure's rules: unsupported keywords, required fields, extra properties, nesting depth and property count.

    """Drill 04.4: check a Pydantic model against the rules of strict structured outputs
before you send it to the model.
Run:  python schema_lint.py course_enquiry:CourseEnquiry"""
import importlib
import sys

import openai

# Keywords Azure OpenAI structured outputs does not support (check the docs for your model).
UNSUPPORTED = {
    "minLength", "maxLength", "pattern", "format",
    "minimum", "maximum", "exclusiveMinimum", "exclusiveMaximum", "multipleOf",
    "minItems", "maxItems", "uniqueItems", "contains",
    "patternProperties", "unevaluatedProperties", "propertyNames",
    "minProperties", "maxProperties", "unevaluatedItems",
}
MAX_PROPERTIES = 100
MAX_DEPTH = 5


def strict_schema(model):
    """The schema the SDK sends for this model (same as .parse() and pydantic_function_tool)."""
    return openai.pydantic_function_tool(model)["function"]["parameters"]


def lint(schema):
    problems, count = [], 0
    if "anyOf" in schema:
        problems.append("root: the root must be an object, not anyOf")

    defs = schema.get("$defs", {})

    def walk(node, path, depth, seen=()):
        nonlocal count
        if isinstance(node, list):
            for i, item in enumerate(node):
                walk(item, f"{path}[{i}]", depth, seen)
            return
        if not isinstance(node, dict):
            return
        ref = node.get("$ref", "")
        if ref.startswith("#/$defs/"):                 # nested models are stored in $defs
            name = ref.rsplit("/", 1)[1]
            if name not in seen:                       # recursion is allowed; don't loop forever
                walk(defs.get(name, {}), path, depth, seen + (name,))
            return
        for key in sorted(UNSUPPORTED & node.keys()):
            problems.append(f"{path}: '{key}' is not supported; enforce it in a validator instead")
        if node.get("type") == "object" or "properties" in node:
            props = node.get("properties", {})
            count += len(props)
            if depth > MAX_DEPTH:
                problems.append(f"{path}: nested {depth} levels deep (max {MAX_DEPTH})")
            if node.get("additionalProperties") is not False:
                problems.append(f"{path}: additionalProperties must be false")
            missing = set(props) - set(node.get("required", []))
            if missing:
                problems.append(f"{path}: every field must be required (use Optional for 'may be null'): {sorted(missing)}")
            for name, sub in props.items():
                walk(sub, f"{path}.{name}", depth + 1, seen)
        for key in ("items", "anyOf"):
            if key in node:
                walk(node[key], f"{path}.{key}", depth, seen)

    walk(schema, "root", 1)
    if count > MAX_PROPERTIES:
        problems.append(f"root: {count} properties in total (max {MAX_PROPERTIES})")
    return problems


if __name__ == "__main__":
    target = sys.argv[1] if len(sys.argv) > 1 else "course_enquiry:CourseEnquiry"
    module_name, class_name = target.split(":")
    model = getattr(importlib.import_module(module_name), class_name)
    found = lint(strict_schema(model))
    for p in found:
        print("PROBLEM", p)
    print(f"{class_name}: {'OK, ready for strict structured outputs' if not found else str(len(found)) + ' problem(s)'}")
    sys.exit(1 if found else 0)

  3. Verify 
    """Tests for schema_lint.py and the course enquiry schema. Run:  pytest -q test_schema_lint.py"""
from typing import Optional

import pytest
from pydantic import BaseModel, Field, ValidationError

from course_enquiry import CourseEnquiry
from schema_lint import lint, strict_schema


class TooClever(BaseModel):
    enrolment_id: str = Field(pattern=r"^TC-\d{5}$")       # pattern: not supported
    summary: str = Field(max_length=200)                    # maxLength: not supported
    learners: int = Field(ge=1, le=500)                     # minimum/maximum: not supported


class Level5(BaseModel):
    x: int


class Level4(BaseModel):
    d: Level5


class Level3(BaseModel):
    c: Level4


class Level2(BaseModel):
    b: Level3


class Level1(BaseModel):
    a: Level2


class TooDeep(BaseModel):
    root: Level1
    note: Optional[str]


def test_reference_schema_is_clean():
    assert lint(strict_schema(CourseEnquiry)) == []


def test_unsupported_keywords_are_reported():
    problems = " ".join(lint(strict_schema(TooClever)))
    for keyword in ("pattern", "maxLength", "minimum", "maximum"):
        assert keyword in problems


def test_deep_nesting_is_reported():
    assert any("nested" in p for p in lint(strict_schema(TooDeep)))


def test_business_rules_live_in_validators():
    good = {"contact": {"name": "Priya", "company": "Northwind", "email": "priya@northwind.example"},
            "requests": [{"topic": "AZ-104", "learners": 12, "preferred_format": "live-online"}],
            "budget_usd": 15000, "wants_private_class": True, "deadline": "2026-12-15"}
    assert CourseEnquiry.model_validate(good).requests[0].learners == 12
    bad = {**good, "deadline": "15/12/2026"}
    with pytest.raises(ValidationError):
        CourseEnquiry.model_validate(bad)
    $ pytest -q test_schema_lint.py
    • 4 passed. If your assistant's version fails the lint, paste the PROBLEM lines back to it: they say exactly what to change.

Remember: “A schema is code. Lint it and test it before a model ever sees it.”

3

Check

Schemas.

1. In strict mode, how do you express "this field may be missing"?

You don't make it missing; you make it nullable. The field stays required and its type is anyOf [type, null] (in Pydantic, Optional[...]).

2. Your Pydantic model has Field(pattern=r"^TC-\d{5}$") and Azure rejects the request. Fix?

Remove pattern from the schema and enforce the format in a @field_validator. Put the format in the field's description so the model knows it too.

3. message.parsed is None. What happened?

Most likely a refusal: check message.refusal. (A cut-off reply raises LengthFinishReasonError instead; topic 7.)

Takeaway

Let the API enforce the shape; keep the schema to what strict mode supports; push every other rule into validators.
