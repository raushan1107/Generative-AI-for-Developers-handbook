Function Calling: Letting the Model Ask Your Code

Function calling is how a model gets things it can't know (today's price, Diego's booking) and asks for things it can't do (create a ticket). The model never runs your code. It replies with a request: 'please call find_courses with these arguments'. Your code runs it and sends the result back. You'll do every step by hand once, so nothing about it is magic.

1

Learn

The model asks; your code answers.

Definition

Function calling (also tool calling) lets you describe functions to the model as JSON Schemas (tools=[...]). When the model decides one is needed, it returns tool_calls (a function name plus JSON arguments) instead of, or before, a text answer. Your application executes the function and returns the result in a tool message, and the model continues with that information.

In plain words

You give the model a menu of things your app can do. It can't press the buttons itself; it can only say "I'd like this one, with these settings". You check the request, press the button, and tell it what happened.

Imagine this

A new call-centre agent on day one has no system access. When a customer asks about their order, the agent writes a request slip, "look up order status for order 4471", and passes it to a supervisor who has the access. The supervisor checks the customer is allowed to see it, looks it up, and hands back the answer. The agent then explains it to the customer in friendly words. The model is the agent; your code is the supervisor.

The parts you control

SettingWhat it doesUse it when
tools=[...]Names, descriptions and JSON Schemas of your functionsAlways. Descriptions decide when the model picks a tool.
"strict": trueArguments must match the schema exactly (same rules as structured outputs)Default for production tools. openai.pydantic_function_tool() sets it.
tool_choice="auto"The model decides: a tool, or a text answerNormal chat (the default)
tool_choice="none"Never call a tool this turnSumming up, or after a tool limit is reached
tool_choice="required" or a named functionMust call some tool, or that toolPipelines where a step must happen (e.g. always classify)
parallel_tool_callsAllow several calls in one replyIndependent lookups. Azure doesn't support it together with strict tools, so set it to False when strict is on.

Facts worth remembering

  • function.arguments is a JSON string, not a dict. Parse and validate it (Pydantic does both).
  • When the model wants tools, finish_reason is "tool_calls" and content is often empty.
  • Send back the assistant message with its tool_calls, then one tool message per call, in the same order, with the matching tool_call_id. Missing one is a 400 error.
  • Tool definitions count as input tokens on every call. Ten verbose tools can cost more than the question.
  • Reasoning models: on Azure, Chat Completions with tools may require reasoning_effort="none"; Microsoft recommends the Responses API for tools plus reasoning. The drills' llm_tools.TOOL_EXTRAS handles this from .env.
In the real world

Booking assistants call availability and pricing APIs, banking assistants call balance and transaction lookups, and IT help desks call "reset password" or "open incident" functions. Behind every one is the same loop you'll build here, plus a rule that the model only proposes and the backend decides.

Traditional developer view

"My functions are called by my code, with arguments I constructed."

GenAI developer view

"Some of my functions are now requested by a model, with arguments it made up from a conversation. Each one is a public endpoint: validate everything, check permissions, and keep the menu short."

Common trap

Thinking "the model called delete_account" means the model did something. It didn't: your code did, because your loop executed whatever was requested. Never expose a function you wouldn't want an anonymous user to trigger with arguments of their choosing.

Interview cue

"With function calling the model returns a structured request: function name and JSON arguments. The application validates and executes it, returns the result as a tool message linked by tool_call_id, and the model uses it in its answer. The model never executes code."

Drill 04.5

Your first function call, step by step

~15 minAzure OpenAIPython · Pydantic

Goal: perform the five steps of the diagram yourself, with nothing hidden in a framework.

  1. Run

    The catalogue your app already has

    A plain Python function over data/courses.json. No AI in here: this is "your existing business logic".

    """The TrainCrest course catalogue (fictional), used by Module 04 and 05 drills."""
import json
from pathlib import Path

COURSES = json.loads((Path(__file__).parent / "data" / "courses.json").read_text(encoding="utf-8"))


def find_courses(level=None, max_price_usd=None, course_format=None, text=None):
    """Plain keyword filter over the catalogue: the kind of function your app already has."""
    hits = []
    for c in COURSES:
        if level and c["level"] != level:
            continue
        if max_price_usd is not None and c["price_usd"] > max_price_usd:
            continue
        if course_format and c["format"] != course_format:
            continue
        if text and text.lower() not in (c["title"] + " " + c["description"]).lower():
            continue
        hits.append({k: c[k] for k in ("id", "title", "level", "format", "price_usd")})
    return hits


def get_course(course_id):
    return next((c for c in COURSES if c["id"] == course_id.upper()), None)
  2. Run

    Expose it as a tool and complete one round trip

    """Drill 04.5: your first function call, one step at a time.
The model never runs code. It asks YOU to run a function; you send back the result."""
import json
from typing import Literal, Optional

import openai
from pydantic import BaseModel, Field

from catalogue import find_courses
from llm import MODEL, get_client
from llm_tools import TOOL_EXTRAS


class FindCourses(BaseModel):
    """Search the TrainCrest catalogue. Use it for any question about courses, levels or prices."""
    level: Optional[Literal["beginner", "intermediate", "advanced"]] = None
    max_price_usd: Optional[int] = Field(default=None, description="Highest price the learner will pay, in USD")
    text: Optional[str] = Field(default=None, description="One keyword to look for in titles and descriptions, e.g. 'python'")


TOOLS = [openai.pydantic_function_tool(FindCourses, name="find_courses")]


def main():
    client = get_client()
    messages = [
        {"role": "system", "content": "You are Traincrest Assist. Use tools for catalogue facts; never guess prices."},
        {"role": "user", "content": "Is there a beginner Python course under $300?"},
    ]

    # Step 1: send the question AND the tool descriptions.
    first = client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS, **TOOL_EXTRAS)
    msg = first.choices[0].message
    print("1) finish_reason:", first.choices[0].finish_reason)
    if not msg.tool_calls:
        print("The model answered without a tool:", msg.content)
        return

    # Step 2: the model asked for a call. Run it ourselves.
    messages.append(msg)                          # the assistant turn that contains tool_calls
    for call in msg.tool_calls:
        print(f"2) model asks: {call.function.name}({call.function.arguments})")
        # Validate before you call: strict mode guarantees the shape on Azure/OpenAI, but not every
        # provider enforces it, and a model can still send values your function can't use.
        args = FindCourses.model_validate_json(call.function.arguments)
        result = find_courses(**args.model_dump())
        print(f"   we ran it:  {len(result)} result(s)")
        messages.append({"role": "tool", "tool_call_id": call.id, "content": json.dumps(result)})

    # Step 3: send the results back; the model writes the final answer.
    final = client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS, **TOOL_EXTRAS)
    print("3) answer:", final.choices[0].message.content)


if __name__ == "__main__":
    main()

  3. Verify
    • The price in the answer ($290) came from your data via the tool, not from the model's memory.
    • Print messages before step 3: you'll see the assistant turn with tool_calls and the tool turn with the same tool_call_id.
    • Why validate with FindCourses.model_validate_json before calling? On my first local run the model sent an extra argument, catalog_type, and a plain find_courses(**args) crashed. Strict mode prevents that on Azure; validation protects you everywhere.
Open alternative · the same round trip with Claude

Same idea, different message shapes: Claude returns tool_use content blocks, and you reply with a tool_result block in a user message.

import json
import openai
from claude_llm import client, CLAUDE_MODEL, FALLBACK, text_of
from catalogue import find_courses
from lab04_05_first_tool import FindCourses        # the __main__ guard stops its own run

tool = {"name": "find_courses", "description": FindCourses.__doc__,
        "input_schema": openai.pydantic_function_tool(FindCourses)["function"]["parameters"]}
messages = [{"role": "user", "content": "Is there a beginner Python course under $300?"}]
msg = client.beta.messages.create(model=CLAUDE_MODEL, max_tokens=2000, tools=[tool],
                                  messages=messages, **FALLBACK)
if msg.stop_reason == "tool_use":
    messages.append({"role": "assistant", "content": msg.content})
    results = [{"type": "tool_result", "tool_use_id": b.id,
                "content": json.dumps(find_courses(**FindCourses.model_validate(b.input).model_dump()))}
               for b in msg.content if b.type == "tool_use"]
    messages.append({"role": "user", "content": results})
    msg = client.beta.messages.create(model=CLAUDE_MODEL, max_tokens=2000, tools=[tool],
                                      messages=messages, **FALLBACK)
print(text_of(msg))
Drill 04.6

Steer the choice: tool_choice and parallel calls

~10 minAzure OpenAIPython

Goal: see how descriptions and tool_choice decide which tool runs, and when parallel calls help.

  1. Run

    Four questions, three tools, several settings

    """Drill 04.6: which tool does the model pick, and how do you steer it?
Run:  python lab04_06_tool_choice.py                 (tool_choice="auto")
      python lab04_06_tool_choice.py none            (never call a tool)
      python lab04_06_tool_choice.py required        (must call some tool)
      python lab04_06_tool_choice.py get_course      (must call this one)
      python lab04_06_tool_choice.py auto --parallel (allow several calls in one turn)"""
import json
import sys
from typing import Literal, Optional

import openai
from pydantic import BaseModel, Field

from llm import MODEL, get_client
from llm_tools import TOOL_EXTRAS


class FindCourses(BaseModel):
    """Search the catalogue by level, budget or keyword."""
    level: Optional[Literal["beginner", "intermediate", "advanced"]] = None
    max_price_usd: Optional[int] = None
    text: Optional[str] = None


class GetCourse(BaseModel):
    """Full details of one course by its ID, like C104."""
    course_id: str = Field(description="Course ID such as C104")


class GetVoucherStatus(BaseModel):
    """Exam voucher status for the signed-in learner's enrolment."""
    enrolment_id: str = Field(description="Like TC-12345")


QUESTIONS = [
    "What does C104 cover?",
    "Has my voucher for TC-10293 been issued?",
    "Compare C110 and C111 for me.",
    "Thanks, that's all!",
]

choice = sys.argv[1] if len(sys.argv) > 1 and not sys.argv[1].startswith("--") else "auto"
parallel = "--parallel" in sys.argv
tools = [openai.pydantic_function_tool(FindCourses, name="find_courses"),
         openai.pydantic_function_tool(GetCourse, name="get_course"),
         openai.pydantic_function_tool(GetVoucherStatus, name="get_voucher_status")]
if parallel:
    for t in tools:                    # strict tools can't be combined with parallel calls
        t["function"]["strict"] = False
tool_choice = choice if choice in ("auto", "none", "required") else {"type": "function", "function": {"name": choice}}

client = get_client()
print(f"tool_choice={choice}  parallel_tool_calls={parallel}\n")
for q in QUESTIONS:
    r = client.chat.completions.create(
        model=MODEL, messages=[{"role": "user", "content": q}], tools=tools,
        tool_choice=tool_choice, parallel_tool_calls=parallel, **TOOL_EXTRAS)
    calls = r.choices[0].message.tool_calls or []
    picked = ", ".join(f"{c.function.name}({json.loads(c.function.arguments)})" for c in calls) or "no tool (text answer)"
    print(f"{q:<42} -> {picked}")

  2. Think

    Read your results

    1. With none, what did the model say about the voucher? Is that safe?
    2. With get_course forced, what happened to "Thanks, that's all!"?
    3. Without parallel calls, how does the model still compare two courses?
    Compare with my answers
    1. With no tools allowed, a good model says it can't check; a weaker one invents a status. That's why the system prompt must say "never guess a status" and your loop should keep tools available when facts are needed.
    2. A forced tool is called even when it makes no sense (often with a made-up ID). Force a tool only for pipeline steps that must always happen.
    3. It asks for C110, gets the result, then asks for C111 in the next round. That's why real assistants run a loop (next topic). Parallel calls save a round trip for independent lookups, but on Azure they can't be combined with strict tools.

    Local servers may ignore tool_choice: the small Ollama model I tested still answered in text when required was set. Test the settings you rely on with the model you'll ship.

3

Check

Function calling.

1. The model returned a tool call. Has anything happened in your system yet?

No. A tool call is a request. Nothing happens until your code chooses to execute it.

2. You get a 400 error on the second call: "tool_call_id ... not found". Likely cause?

You sent a tool message without first appending the assistant message that contains the matching tool_calls, or the IDs don't match.

3. The model keeps picking find_courses when users ask about a specific course ID. What do you change first?

The tool descriptions: say clearly when to use each one ("Full details of one course by its ID, like C104"). Descriptions are how the model chooses.

Takeaway

The model writes the request; your code is the only thing that ever acts.
