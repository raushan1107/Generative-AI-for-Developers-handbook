Why Structured Outputs Matter

A reply can be perfect for a human and useless for a program. The moment your code reads what the model wrote (to show a price, route a ticket or fill a form), you need the answer in a shape your code can trust. This page shows, with a parser you'll watch fail, why that shape can't be left to chance.

1

Learn

Two readers, two very different needs.

Definition

Structured output is model output in a predefined, machine-readable format (usually JSON with known keys, types and allowed values) so application code can parse and use it directly, instead of interpreting free-form text.

In plain words

People are forgiving readers: "290 USD", "$290" and "two hundred and ninety dollars" all mean the same to you. Code isn't. It needs the price in one box, as a number, every single time.

Imagine this

A customer writes a letter to their bank: "Please move about three hundred from my everyday account to savings, maybe Tuesday." A clerk understands it. The bank's computer can't. That's why banks give you a transfer form with boxes: amount, from, to, date. The form doesn't make the customer smarter; it makes the request processable.

Where structured output is the whole point

TaskWhat the code needs back
Ticket triage (Milestone 3)category, urgency, enrolment_id to route it
Extraction from emails, invoices, formsNamed fields to save in a database
Classification and moderationOne label from a fixed list, maybe a score
UI generationTitle, bullet points, button labels in known slots
Calling your functions (topic 4)A function name and arguments that match its parameters
In the real world

Most production GenAI features are not chat. They're pipelines where a model reads something messy (an email, a contract, a call transcript) and returns a record that the rest of the system processes like any other data: stored, searched, routed, reported on. The chat window is the demo; the structured record is the product.

Traditional developer view

"The API returns text. I'll parse it with a regex and fix the edge cases as they come in."

GenAI developer view

"There's no finite list of edge cases: the model can phrase the same fact a thousand ways. I ask for structure, so there's nothing to parse."

Common trap

Testing a parser on three replies, seeing it work, and shipping it. The fourth reply mentions two prices, or writes "USD 290", and your code shows the wrong number without raising any error.

Interview cue

"When code consumes model output, I don't parse prose. I request structured output against a schema and validate it, because free text has unbounded variation and parsing failures are often silent."

Before you run this code

Run every drill from your genai-labs folder with its virtual environment active. Two files must be there: .env (settings) and llm.py (the shared helper every drill imports). By default they use a free local model with Ollama: install Ollama, then ollama pull llama3.2; no key is needed. To use Azure OpenAI or OpenAI instead, change LLM_PROVIDER in .env.

Easiest: download the genai-labs starter kit (every helper, data file and drill script), unzip it, copy .env.example to .env, and run pip install -r requirements.txt. Full walkthrough: Helpers and smoke test.

llm.py
"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 04.1

Parse the unparseable: free text vs your code

~10 minOffline first · then Azure OpenAI

Goal: see why "just parse the reply" fails, using three replies that any person would call correct.

  1. Run

    Three good answers, one quick parser

    """Drill 04.1: why free text breaks your code.
We ask for a course recommendation and try to pull the price out with a regex,
the way a quick prototype would. Run with --offline to use three saved replies."""
import re
import sys

QUESTION = """A learner wants a beginner Python course under $300.
Recommend one course from this list and say its price.
- C101 Python Foundations, beginner, $290
- C114 Docker Quick Start, beginner, $190
- C103 Machine Learning Essentials, intermediate, $1190"""

# Three real-looking replies to the same question. All are fine for a human reader.
SAVED_REPLIES = [
    "I recommend Python Foundations (C101). It costs $290 and is designed for complete beginners.",
    "Python Foundations is the best fit. If budget is tight, Docker Quick Start is only $190, "
    "but Python Foundations at $290 teaches programming from zero.",
    "Go for **Python Foundations**: beginner level, 290 USD, five days.",
]


def parse_price(reply: str):
    """The 'quick prototype' parser: first dollar amount in the text."""
    match = re.search(r"\$(\d+)", reply)
    return int(match.group(1)) if match else None


def get_replies():
    if "--offline" in sys.argv:
        return SAVED_REPLIES
    from llm import MODEL, get_client
    client = get_client()
    replies = []
    for _ in range(3):
        r = client.chat.completions.create(model=MODEL, messages=[{"role": "user", "content": QUESTION}])
        replies.append(r.choices[0].message.content or "")
    return replies


if __name__ == "__main__":
    for i, reply in enumerate(get_replies(), 1):
        price = parse_price(reply)
        verdict = "OK" if price == 290 else ("WRONG" if price else "FAILED")
        print(f"Reply {i}: {reply[:70]}{'...' if len(reply) > 70 else ''}")
        print(f"  parsed price -> {price}   {verdict}\n")

    Output (exact, offline)

  parsed price -> 290   OK

Reply 2: Python Foundations is the best fit. If budget is tight, Docker Quick S...
  parsed price -> 190   WRONG

Reply 3: Go for **Python Foundations**: beginner level, 290 USD, five days.
  parsed price -> None   FAILED

    Now run it without --offline to ask your own deployment three times. Different wording, same problem.

    $ python lab04_01_free_text.py
    From a small local model (Ollama); yours will differ 
    Reply 1: Based on your criteria, a suitable Python course for a beginner is "C1...
  parsed price -> 290   OK
Reply 2: Based on your requirements, I would recommend the Python Foundations c...
  parsed price -> 290   OK
Reply 3: For a beginner Python course that costs under $300, I recommend the fo...
  parsed price -> 300   WRONG
  2. Think

    Which failure is worse?

    Reply 2 parsed as 190; reply 3 parsed as None. In production, which one hurts more, and why?

    Compare with my answer

    The wrong one (190). None fails loudly: you can catch it, log it and retry. A wrong number flows silently into the UI or an invoice. Notice the live run: the model's "under $300" echoed the question, and the parser grabbed it. Fixing the regex just moves the problem; the fix is to stop parsing prose. The next three topics do exactly that.

Remember: “If code reads it, don't ask for prose and hope. Ask for a shape.”

3

Check

Why structure.

1. A feature shows a model-written summary to a support agent. Does it need structured output?

Not necessarily: a person reads it, so free text is fine (with length and tone constraints). If the same feature also needs a category to route on, that part should be structured.

2. Why is a parser that "usually works" dangerous?

Because failures can be silent: it returns a plausible but wrong value instead of an error, and at 25,000 messages a month, rare cases happen daily.

Takeaway

Prose is for people. When a program is the reader, ask for a shape, not a sentence.
