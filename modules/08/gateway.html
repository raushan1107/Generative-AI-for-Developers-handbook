Gateways and Model Routing

A gateway can standardize how services reach model endpoints. It is not the place to hide authorization or product rules. You'll see an allowlisted route table and test what happens when a task has no configured deployment.

Gateway boundaryAllowlistRouting
1Learn→2Do→3CheckLearn 12 min · Do 15 min
1

Learn

Put shared endpoint controls at the boundary, business decisions in the app.

Definition

An AI gateway is a shared service between applications and model endpoints. Depending on the product, it can centralize endpoint authentication, routing, quotas, logging and policy enforcement. Model routing selects a configured deployment for a task; the route should come from trusted application configuration, not an unvalidated model or user string.

In plain words

The gateway is the controlled entrance to model services. The app still decides what a customer is allowed to do and what data can be sent.

Imagine this

A bank's network gateway checks which systems may connect. It does not approve a customer's loan; that decision belongs to the loan workflow.

In the real world

Azure API Management documents AI gateway capabilities for routing, quotas, token metrics and shared access controls. Exact capabilities depend on the product and configuration; a gateway does not replace the application's authorization logic. See Microsoft Learn: AI gateway capabilities in API Management.

In finance

RR Finance Bank can route low-risk message classification to a smaller approved deployment and policy drafting to another approved deployment. The app must still use its verified identity context, check the policy result and require approval before changing an account.

Traditional developer view

"A proxy forwards requests."

GenAI developer view

"A shared AI gateway can govern access, but the model route and business authority remain explicit and testable."

Common trap

Assuming a gateway makes a model call safe. It cannot infer whether a customer is authorized to dispute a transaction or whether a generated answer follows a bank policy.

Interview cue

"I use a gateway for shared endpoint controls and quotas, and keep identity, business rules and tool authorization in the application. Model routing uses an allowlist and fails closed for unknown task names."

Reject routes that aren't configured.

Drill 08.1

Route only configured tasks

~15 minPython · pytestoffline

Goal: use a trusted route map and reject unconfigured tasks instead of accepting arbitrary deployment names.

  1. Run

    The route resolver

    """Small, offline examples of explicit routing and expiring session storage."""

import json
import sqlite3
import time
import uuid
from pathlib import Path
from typing import Mapping, Sequence


def select_deployment(task: str, routes: Mapping[str, str]) -> str:
    """Resolve a task through an explicit allowlist; never accept a model name from a user."""
    if task not in routes:
        raise ValueError(f"Unconfigured task: {task}")
    deployment = routes[task].strip()
    if not deployment:
        raise ValueError(f"Empty deployment for task: {task}")
    return deployment


def new_trace_id() -> str:
    return uuid.uuid4().hex


class SessionStore:
    def __init__(self, path: str | Path):
        self.path = Path(path)
        if str(self.path) != ":memory:":
            self.path.parent.mkdir(parents=True, exist_ok=True)
        with sqlite3.connect(self.path) as connection:
            connection.execute(
                """CREATE TABLE IF NOT EXISTS sessions (
                    session_id TEXT PRIMARY KEY,
                    messages_json TEXT NOT NULL,
                    expires_at INTEGER NOT NULL
                )"""
            )

    def save(
        self,
        session_id: str,
        messages: Sequence[Mapping[str, str]],
        expires_at: int,
    ) -> None:
        if not session_id or expires_at <= 0:
            raise ValueError("A session ID and positive expiry are required")
        serialized = json.dumps(list(messages), separators=(",", ":"))
        with sqlite3.connect(self.path) as connection:
            connection.execute(
                """INSERT INTO sessions(session_id, messages_json, expires_at)
                   VALUES (?, ?, ?)
                   ON CONFLICT(session_id) DO UPDATE SET
                       messages_json = excluded.messages_json,
                       expires_at = excluded.expires_at""",
                (session_id, serialized, expires_at),
            )

    def delete(self, session_id: str) -> None:
        with sqlite3.connect(self.path) as connection:
            connection.execute(
                "DELETE FROM sessions WHERE session_id = ?", (session_id,)
            )

    def load(
        self, session_id: str, now: int | None = None
    ) -> list[dict[str, str]] | None:
        current_time = int(time.time()) if now is None else now
        with sqlite3.connect(self.path) as connection:
            row = connection.execute(
                "SELECT messages_json, expires_at FROM sessions WHERE session_id = ?",
                (session_id,),
            ).fetchone()
            if row is None:
                return None
            if row[1] <= current_time:
                connection.execute(
                    "DELETE FROM sessions WHERE session_id = ?", (session_id,)
                )
                return None
        messages = json.loads(row[0])
        if not isinstance(messages, list):
            raise ValueError("Stored session must contain a message list")
        return messages

  2. Verify
    • An unknown task raises an explicit ValueError.
    • A blank deployment is rejected.
    • Production route names come from deployment configuration, not from user input.
3

Check

Gateway boundaries.

1. A gateway returns HTTP 200. Does that prove the user may freeze a card?

No. The app must authorize the requested action against trusted customer identity and bank rules.

2. Who should choose the deployment for a task?

Trusted routing configuration or a tested application policy—not an arbitrary name supplied by the user or generated by the model.

Takeaway

Gateways govern shared model access. Application code still owns authorization, validation and business outcomes.
