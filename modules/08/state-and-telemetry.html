Sessions, Queues and Traces

A process restart should not silently erase every conversation, and a trace should help debug a request without becoming a copy of the customer's message. You'll connect the M08 chat service to an expiring local session store.

Session stateQueuesTrace contextRetention
1Learn→2Do→3CheckLearn 15 min · Do 20 min
1

Learn

Persist only what the workflow needs, for only as long as it needs it.

Definition

Session state stores conversation messages or task progress so a service can resume after a process restart. A queue holds work for asynchronous processing; workers must tolerate retries because most queues provide at-least-once delivery. A trace links spans from one request across services using a correlation context, without requiring full prompts or responses in telemetry.

In plain words

A database remembers the conversation; a queue remembers work waiting to be done; a trace ID helps find the related operations. They solve different problems.

Imagine this

A bank case has a case record, an inbox for the next worker and a tracking number. The case record is not the inbox, and the tracking number should not expose the case details.

ComponentUse it forDesign check
Session storeConversation history and task checkpointsAccess control, expiry, deletion and encryption
QueueLong-running or retryable workIdempotent handlers and dead-letter handling
TraceRequest path, latency and dependency failuresUse correlation IDs; avoid secrets and raw PII
In the real world

Microsoft Foundry observability describes evaluation, monitoring and distributed tracing, with tracing built on OpenTelemetry standards and Azure Monitor Application Insights integration. Trace content and retention still need privacy controls. See Microsoft Learn: Observability in generative AI.

In finance

A dispute workflow may pause while a customer reviews a proposal. Persist the workflow state and approval expiry, but keep the approval bound to the exact action and customer. Trace IDs can connect the API request, retrieval and approval without logging the customer's full message or account details.

Traditional developer view

"Store the session object in a dictionary."

GenAI developer view

"Choose what to persist, set a retention window and treat prompts, outputs and tool results as potentially sensitive data."

Common trap

Assuming a database is production-ready because it survives a restart. The M08 SQLite example is a local synthetic-data exercise; production storage needs managed access control, encryption, backups, retention and deletion behavior.

Interview cue

"I persist only the state needed to resume a workflow, enforce a TTL, make queue handlers idempotent, and correlate operations with trace IDs while excluding secrets and raw customer content from logs."

import json
import sqlite3
import time
import uuid
from pathlib import Path
from typing import Mapping, Sequence


def select_deployment(task: str, routes: Mapping[str, str]) -> str:
    """Resolve a task through an explicit allowlist; never accept a model name from a user."""
    if task not in routes:
        raise ValueError(f"Unconfigured task: {task}")
    deployment = routes[task].strip()
    if not deployment:
        raise ValueError(f"Empty deployment for task: {task}")
    return deployment


def new_trace_id() -> str:
    return uuid.uuid4().hex


class SessionStore:
    def __init__(self, path: str | Path):
        self.path = Path(path)
        if str(self.path) != ":memory:":
            self.path.parent.mkdir(parents=True, exist_ok=True)
        with sqlite3.connect(self.path) as connection:
            connection.execute(
                """CREATE TABLE IF NOT EXISTS sessions (
                    session_id TEXT PRIMARY KEY,
                    messages_json TEXT NOT NULL,
                    expires_at INTEGER NOT NULL
                )"""
            )

    def save(
        self,
        session_id: str,
        messages: Sequence[Mapping[str, str]],
        expires_at: int,
    ) -> None:
        if not session_id or expires_at <= 0:
            raise ValueError("A session ID and positive expiry are required")
        serialized = json.dumps(list(messages), separators=(",", ":"))
        with sqlite3.connect(self.path) as connection:
            connection.execute(
                """INSERT INTO sessions(session_id, messages_json, expires_at)
                   VALUES (?, ?, ?)
                   ON CONFLICT(session_id) DO UPDATE SET
                       messages_json = excluded.messages_json,
                       expires_at = excluded.expires_at""",
                (session_id, serialized, expires_at),
            )

    def delete(self, session_id: str) -> None:
        with sqlite3.connect(self.path) as connection:
            connection.execute(
                "DELETE FROM sessions WHERE session_id = ?", (session_id,)
            )

    def load(
        self, session_id: str, now: int | None = None
    ) -> list[dict[str, str]] | None:
        current_time = int(time.time()) if now is None else now
        with sqlite3.connect(self.path) as connection:
            row = connection.execute(
                "SELECT messages_json, expires_at FROM sessions WHERE session_id = ?",
                (session_id,),
            ).fetchone()
            if row is None:
                return None
            if row[1] <= current_time:
                connection.execute(
                    "DELETE FROM sessions WHERE session_id = ?", (session_id,)
                )
                return None
        messages = json.loads(row[0])
        if not isinstance(messages, list):
            raise ValueError("Stored session must contain a message list")
        return messages

from app.architecture import SessionStore, new_trace_id, select_deployment
from app.chat import ChatService
from tests.fakes import FakeClient


def test_routes_only_configured_tasks():
    assert select_deployment("triage", {"triage": "chat-small"}) == "chat-small"
    with pytest.raises(ValueError, match="Unconfigured task"):
        select_deployment("customer supplied name", {"triage": "chat-small"})


def test_empty_deployment_is_rejected():
    with pytest.raises(ValueError, match="Empty deployment"):
        select_deployment("draft", {"draft": " "})


def test_trace_ids_are_unique_and_safe_for_logs():
    first, second = new_trace_id(), new_trace_id()
    assert first != second
    assert len(first) == 32 and all(char in "0123456789abcdef" for char in first)


def test_session_round_trips_and_updates(tmp_path):
    store = SessionStore(tmp_path / "sessions.sqlite")
    store.save("s-1", [{"role": "user", "content": "Help with a dispute"}], 500)
    assert store.load("s-1", now=100) == [
        {"role": "user", "content": "Help with a dispute"}
    ]
    store.save("s-1", [{"role": "assistant", "content": "I can help"}], 600)
    assert store.load("s-1", now=100) == [
        {"role": "assistant", "content": "I can help"}
    ]


def test_expired_session_is_deleted(tmp_path):
    store = SessionStore(tmp_path / "sessions.sqlite")
    store.save("s-expired", [], expires_at=100)
    assert store.load("s-expired", now=100) is None
    assert store.load("s-expired", now=50) is None


def test_invalid_session_is_rejected(tmp_path):
    store = SessionStore(tmp_path / "sessions.sqlite")
    with pytest.raises(ValueError, match="session ID"):
        store.save("", [], expires_at=100)


def test_chat_service_persists_completed_turns(tmp_path):
    store = SessionStore(tmp_path / "sessions.sqlite")
    service = ChatService(
        client=FakeClient(rounds=[{"text": "I can help with the dispute."}]),
        session_store=store,
    )
    list(service.stream("session-1234", "I recognize a duplicate charge."))
    assert store.load("session-1234") == [
        {"role": "user", "content": "I recognize a duplicate charge."},
        {"role": "assistant", "content": "I can help with the dispute. "},
    ]


def test_reset_deletes_persisted_history(tmp_path):
    store = SessionStore(tmp_path / "sessions.sqlite")
    store.save("session-1234", [{"role": "user", "content": "question"}], 9999999999)
    service = ChatService(client=FakeClient(), session_store=store)
    service.reset("session-1234")
    assert store.load("session-1234") is None

Check

State and telemetry.

1. Why should a queue consumer be idempotent?

A message can be delivered again after a timeout or worker crash. Reprocessing must not duplicate a payment, dispute or other write.

2. Should every trace include the full prompt?

No. Correlation IDs and timing are useful; full prompts and outputs can contain sensitive data and need a separate, controlled diagnostic policy.

Takeaway

State, queues and traces are distinct architecture components. Set retention and access controls before persisting customer conversations.
