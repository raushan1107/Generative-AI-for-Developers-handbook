Module 05 · Overview

Embeddings and Semantic Search: Finding by Meaning

Learners don't use your words. They ask for 'a cheap intro to containers' when your catalogue says 'Docker Quick Start', and 'money back if the trainer is ill' when your help centre says 'If TrainCrest cancels'. In this module you'll turn text into vectors, so software can find things by what they mean, not by which letters they share.

8 topics9 drillsMilestone 5≈ 5 hours hands-on

The mental map: two pipelines

Every semantic search system, from a help-centre search box to the retrieval step of a RAG chatbot, is two pipelines that share one embedding model. The module walks through both.

Takeaway

An embedding turns meaning into a position in space. Similar meanings land close together, so "find similar" becomes "find nearby", which computers do very fast.

Why this module matters

Milestone 4 gave Traincrest Assist a search_courses tool, but it only matches exact words. Ask for "a cheap intro to containers" and the keyword containers finds Kubernetes for Developers ($1,190), not Docker Quick Start ($190), whose description says "container images". And the ten help-centre articles, with the answers to most learner questions, are invisible to it. Embeddings fix both, and they are the foundation of Module 06 (RAG).

Imagine this

A library shelves books by meaning: cookery near nutrition, travel guides near maps. A librarian asked for "something about eating well on a budget" walks to the right corner even though no title contains those words. Embeddings give your software that kind of map, built from text, with thousands of directions instead of a few shelves.

Traditional developer view

"Search means LIKE '%word%', or a full-text index with keywords."

GenAI developer view

"Search means meaning first: embed, find the nearest, filter by metadata, and still mix in keywords for exact codes and names. Then measure hit rates, because 'looks good' isn't a metric."

Lab kit for Module 05

  • Azure: deploy an embedding model in your Foundry project (deployment name embed, for example text-embedding-3-small), and in Drill 05.5 create an Azure AI Search service (the Free tier is enough for these labs; one per subscription).
  • Free, local alternative: ollama pull nomic-embed-text and set LLM_PROVIDER=ollama. Many real outputs on these pages come from it, so you can compare.
  • Install: pip install numpy rank_bm25 azure-search-documents chromadb.
  • Add to your .env: 
    # Module 05: embedding model (on Azure, the deployment name)
AZURE_OPENAI_EMBED_DEPLOYMENT=embed
OPENAI_EMBED_MODEL=text-embedding-3-small
OLLAMA_EMBED_MODEL=nomic-embed-text
# Drill 05.5: Azure AI Search (endpoint and admin key from the portal)
AZURE_SEARCH_ENDPOINT=https://<search-service-name>.search.windows.net
AZURE_SEARCH_API_KEY=<admin key>
AZURE_SEARCH_INDEX=courses
  • New files in genai-labs/: embed.py (batched embeddings with a small disk cache), data/help/ (ten fictional help-centre articles), data/help_questions.json (20 questions with known answers). Module 06 reuses all of them.
  • Cost: embeddings are cheap (a few cents for everything in this module), and the cache means re-runs cost nothing.
  • Build: Milestone 5 gives Traincrest Assist a search index over courses and help sections, hybrid search with filters, a /api/search endpoint and a semantic search_courses tool.
