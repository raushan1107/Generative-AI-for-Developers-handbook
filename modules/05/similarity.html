Vector Similarity: Cosine, Dot Product and Distance

Once texts are vectors, 'how similar are these?' is arithmetic. There are three common ways to do it, and on the normalised vectors embedding models produce, they rank results the same way. The harder lesson is reading the numbers: a 0.67 can be a strong match for one model and a weak one for another.

1

Learn

Same direction, similar meaning.

Definition

Vector similarity measures how close two embeddings are. Cosine similarity is the cosine of the angle between them (1 = same direction, 0 = unrelated, −1 = opposite). The dot product multiplies matching dimensions and adds them up. Euclidean distance is the straight-line distance (0 = identical). For vectors normalised to length 1, cosine equals the dot product, and all three produce the same ranking.

In plain words

Picture each embedding as an arrow from the centre. Similar texts point in nearly the same direction. Cosine asks "how aligned are the arrows?", ignoring how long they are.

Imagine this

Two hikers set off from the same car park. One walks 2 km north-east, the other 5 km north-east. They're far apart in distance, but they're heading the same way. Cosine cares about the heading, not how far each walked, which is why it's the usual choice for comparing meaning.

MeasureRangeHigher meansWhere you'll meet it
Cosine similarity−1 to 1More similarThe default for text embeddings; Chroma's cosine space, Azure AI Search's cosine metric
Dot productAnyMore similarFastest; equals cosine when vectors are normalised
Euclidean (L2) distance0 to ∞Less similarSome vector databases' default; Chroma reports distance = 1 − cosine in cosine space
Scores are relative, not absolute

Every model spreads its scores differently. With one model, a paraphrase might score 0.67 and an unrelated sentence 0.35; with another, 0.85 and 0.20. So don't hard-code "0.8 means a match". Compare rankings, and if you need a cut-off, set it per model from measurements on your own data.

In the real world

Duplicate-ticket detectors and "related articles" widgets are built on exactly this: embed, compute cosine against recent items, show the top few above a threshold tuned on labelled examples. Teams re-tune that threshold whenever they change embedding model, because the score distribution moves.

Traditional developer view

"Similarity is string distance: shared characters, edit distance."

GenAI developer view

"Similarity is the angle between meaning vectors. 'Refund' and 'money back' share no letters and still point the same way. I read scores as rankings, and calibrate any threshold per model."

Common trap

Mixing up similarity and distance. Chroma returns distances (smaller is better); Azure AI Search returns scores (bigger is better). Sorting the wrong way round gives you the least relevant results first, and the code runs without complaint.

Interview cue

"Cosine similarity measures the angle between vectors, ignoring magnitude. On normalised embeddings it equals the dot product, and ranks the same as Euclidean distance. Scores are model-specific, so I compare rankings and calibrate thresholds on labelled data."

Do

By hand first, then on real vectors.

Drill 05.2

Similarity by hand, then across languages

~15 minAzure OpenAIPython · numpy

Goal: implement the three measures, prove cosine ignores length, then read a real similarity matrix that includes a Spanish sentence.

  1. Run

    The three measures in a few lines

    """Drill 05.2: the three ways to compare vectors, written out by hand."""
import numpy as np


def dot(a, b) -> float:
    return float(np.dot(a, b))


def cosine(a, b) -> float:
    """Angle-based: 1.0 = same direction, 0 = unrelated, -1 = opposite. Ignores length."""
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))


def euclidean(a, b) -> float:
    """Straight-line distance: 0 = identical. Smaller is more similar."""
    return float(np.linalg.norm(np.asarray(a) - np.asarray(b)))


def cosine_matrix(vectors) -> np.ndarray:
    """Every pair at once: normalise rows to length 1, then one matrix multiply."""
    v = np.asarray(vectors, dtype=np.float32)
    v = v / np.linalg.norm(v, axis=1, keepdims=True)
    return v @ v.T
    """Drill 05.2: similarity by hand, then on real embeddings.
Run:  python lab05_02_similarity.py --toy   (offline, tiny 2-D vectors)
      python lab05_02_similarity.py         (real embeddings)"""

3

Check

Similarity.

1. Your vectors are normalised. Which is cheapest to compute and gives the same ranking as cosine?

The dot product: on unit vectors it is cosine.

2. A colleague sets "show related articles if cosine > 0.8" and nothing ever shows. Likely reason?

That model's scores rarely reach 0.8. Thresholds are model-specific: measure the score distribution on labelled pairs and pick the cut-off from data.

Takeaway

Normalise, use cosine (a dot product), trust rankings over raw scores, and calibrate thresholds per model.
