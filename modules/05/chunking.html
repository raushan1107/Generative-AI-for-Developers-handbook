Chunking Strategies

You don't embed a whole manual as one vector; its meaning would blur into 'something about everything'. You cut it into chunks, and how you cut decides what can be found. Too small and a chunk loses its context; too big and the answer drowns. You'll measure four strategies on TrainCrest's help centre and let the hit rate decide.

1

Learn

How you cut decides what you find.

Definition

Chunking splits documents into smaller passages that are embedded and indexed separately. Common strategies are fixed-size (a number of characters or tokens, often with overlap), sentence or paragraph based, and structure-based (by headings, sections, pages or code functions). Each chunk keeps a link to its source document.

In plain words

One vector per whole article means one blurry summary. One vector per section means a sharp vector for "how much do I get back?" and another for "when does the money arrive?", so a question can land on exactly the right one.

Imagine this

Index cards for a cookbook. One card per book ("Italian food") won't help you find the risotto. One card per word is useless too. One card per recipe, with the book title on top, is just right: specific enough to find, complete enough to cook from.

The trade-offs

ChoiceSmallerLarger
Chunk sizePrecise matches, but may lose context ("it costs $49" — what does?)More context, but the vector blurs and the answer is diluted
OverlapLess duplication, but a rule split at a boundary can be lostSafer boundaries, more chunks to store and embed
Context headerShorter chunks"Labs › How long labs stay open" makes the chunk understandable alone
  • Structure first: markdown headings, HTML sections, PDF pages, code functions, FAQ question-answer pairs. Fixed-size windows are for walls of text.
  • Add context to each chunk: the document and section title (and maybe a date or product) at the top. It helps both retrieval and the model that reads it later.
  • Keep the source: store source (file, URL, page) with every chunk. Module 06 uses it for citations.
  • Re-chunking means re-embedding: treat the chunking strategy like the embedding model: versioned, measured, rebuilt deliberately.
In the real world

Teams building "chat with our documentation" bots typically spend more time on chunking and cleaning than on prompts: stripping navigation menus from web pages, keeping tables intact, splitting PDFs by section rather than by page, and adding titles to every chunk. Azure AI Search can chunk for you with built-in skills during indexing, but you still choose the strategy and measure it.

Traditional developer view

"Split the text every 1,000 characters and index it."

GenAI developer view

"Chunks are the units of retrieval. I cut along the document's meaning, give each chunk its context, keep its source, and pick size and overlap by measuring hit rate on real questions."

Common trap

Judging chunking by eye ("these chunks look reasonable") instead of by retrieval. Drill 05.7's fixed 800-character chunks look tidy, put the right chunk in the top 3 every time, and still put it first only 15 times out of 20.

Interview cue

"I chunk by the document's structure where possible, add document and section titles to each chunk, use fixed-size windows with overlap as a fallback, store the source for citations, and choose size and overlap by measuring retrieval hit rate on labelled questions."

Drill 05.7

Chunkers compared: let the hit rate decide

~25 minAzure OpenAIPython · pytest

Goal: implement three chunkers, test them, then measure which one most often retrieves the chunk that actually contains the answer.

  1. Run

    Three chunkers

    """Drill 05.7: three ways to cut documents into chunks before embedding them."""
import re
from pathlib import Path

HELP_DIR = Path(__file__).parent / "data" / "help"


def load_articles():
    """{"card-disputes": "# Disputing a card transaction\n...", ...}"""
    return {p.stem: p.read_text(encoding="utf-8") for p in sorted(HELP_DIR.glob("*.md"))}


def fixed_size(text, size=300, overlap=50):
    """Windows of about `size` characters, cut at word boundaries, overlapping by about `overlap`."""
    words, chunks, start = text.split(), [], 0
    while start < len(words):
        end, length = start, 0
        while end < len(words) and length + len(words[end]) + 1 <= size:
            length += len(words[end]) + 1
            end += 1
        end = max(end, start + 1)
        chunks.append(" ".join(words[start:end]))
        if end >= len(words):
            break
        back, kept = end, 0                       # step back far enough to repeat ~overlap characters
        while back > start + 1 and kept < overlap:
            back -= 1
            kept += len(words[back]) + 1
        start = back
    return chunks


def by_sentences(text, max_chars=400):
    """Whole sentences, packed together until the next one would pass max_chars."""
    sentences = re.split(r"(?<=[.!?])\s+|\n+", text)
    chunks, current = [], ""
    for s in (s.strip() for s in sentences):
        if not s:
            continue
        if current and len(current) + len(s) + 1 > max_chars:
            chunks.append(current)
            current = s
        else:
            current = f"{current} {s}".strip()
    if current:
        chunks.append(current)
    return chunks


def by_headings(markdown):
    """One chunk per '## ' section, each starting with 'Article title > Section title'
    so the chunk still makes sense on its own."""
    title = re.search(r"^# (.+)$", markdown, re.M)
    title = title.group(1).strip() if title else ""
    parts = re.split(r"^## ", markdown, flags=re.M)
    intro = re.sub(r"^# .+$", "", parts[0], flags=re.M).strip()
    chunks = [f"{title}\n{intro}"] if intro else []
    for part in parts[1:]:
        heading, _, body = part.partition("\n")
        chunks.append(f"{title} > {heading.strip()}\n{body.strip()}")
    return chunks


STRATEGIES = {
    "fixed 300 chars": lambda t: fixed_size(t, 300, 50),
    "fixed 800 chars": lambda t: fixed_size(t, 800, 100),
    "sentences 400": lambda t: by_sentences(t, 400),
    "by headings": by_headings,
}
  2. Verify

    Test them offline

    """Tests for chunkers.py (offline). Run:  pytest -q test_chunkers.py"""
from chunkers import by_headings, by_sentences, fixed_size, load_articles

MD = "# Cards\n\nIntro line.\n\n## Freeze it first\nFreeze it in the app. It takes effect instantly.\n\n## Replacement\n5 to 7 business days.\n"


def test_fixed_size_respects_size_and_overlaps():
    text = " ".join(f"word{i}" for i in range(200))
    chunks = fixed_size(text, size=100, overlap=20)
    assert all(len(c) <= 100 for c in chunks)
    assert chunks[0].split()[-1] in chunks[1]                 # the end of one chunk starts the next
    assert chunks[-1].endswith("word199")


def test_sentences_are_never_cut():
    chunks = by_sentences("One. Two two. Three three three.", max_chars=15)
    assert chunks == ["One. Two two.", "Three three three."]


def test_headings_keep_their_context():
    chunks = by_headings(MD)
    assert chunks[0] == "Cards\nIntro line."
    assert chunks[1].startswith("Cards > Freeze it first\n") and "instantly" in chunks[1]
    assert len(chunks) == 3


def test_every_article_has_a_title_and_sections():
    for name, md in load_articles().items():
        assert md.startswith("# "), name
        assert len(by_headings(md)) >= 3, name

  3. Run

    Measure: 20 questions with known answers

    Each question in data/help_questions.json names its article and a phrase the retrieved chunk must contain, for example "How much do I get back if I cancel 10 days before the class?" → refunds-and-cancellations, must contain 50% refund. A hit means the right article and the phrase.

    """Drill 05.7: which chunking strategy finds the answer most often?
For each question we know the article and a phrase the retrieved chunk must contain."""
import json
from pathlib import Path

import numpy as np

from chunkers import STRATEGIES, load_articles
from embed import embed

QUESTIONS = json.loads((Path(__file__).parent / "data" / "help_questions.json").read_text(encoding="utf-8"))
articles = load_articles()
q_vectors = embed([q["question"] for q in QUESTIONS])
q_vectors /= np.linalg.norm(q_vectors, axis=1, keepdims=True)

print(f"{'strategy':<17}{'chunks':>7}{'avg chars':>10}{'hit@1':>7}{'hit@3':>7}")
for name, chunker in STRATEGIES.items():
    chunks = [(source, text) for source, md in articles.items() for text in chunker(md)]
    vectors = embed([text for _, text in chunks])
    vectors /= np.linalg.norm(vectors, axis=1, keepdims=True)
    hit1 = hit3 = 0
    misses = []
    for q, row in zip(QUESTIONS, q_vectors @ vectors.T):
        top = np.argsort(-row)[:3]
        found = [chunks[i][0] == q["source"] and q["must_contain"] in chunks[i][1] for i in top]
        hit1 += found[0]
        hit3 += any(found)
        if not any(found):
            misses.append(q["question"])
    avg = sum(len(t) for _, t in chunks) / len(chunks)
    print(f"{name:<17}{len(chunks):>7}{avg:>10.0f}{hit1:>4}/{len(QUESTIONS)}{hit3:>4}/{len(QUESTIONS)}")
    for m in misses:
        print(f"{'':<6}missed: {m}")

  4. Think

    Read the table

    1. Why does "fixed 800" have the best top-3 score but the worst top-1?
    2. "By headings" has the most chunks and the shortest ones. Why does it still win?
    3. Which strategy would you choose for TrainCrest, and what would you check before trusting this table?
    Compare with my answers
    1. Big chunks almost always contain the answer, but each covers several topics, so its vector is a blend and the most relevant one doesn't always rank first. Fine if you send 3 chunks to a model; poor for a search page that shows the first result.
    2. Each chunk is one idea with its title on top ("Payments and invoices › Paying in instalments"), so its vector is sharp and matches the question directly.
    3. By headings, because the help centre is well structured markdown. Before trusting it: more and harder questions (real learner wording, other languages), the production embedding model, and re-running after content changes. Twenty questions is a good start, not a final verdict.

Stretch: ask your assistant to add a fifth strategy, "by headings, but split any section longer than 500 characters into sentence chunks that keep the heading", add it to STRATEGIES, and see if it changes the table.

3

Check

Chunking.

1. A chunk reads "It costs $49 for 14 more days." Why is that a retrieval problem, and how do you fix it?

Out of context, nothing says what costs $49, so questions about lab extensions may not match it. Add the context header ("Labs and cloud sandboxes › How long labs stay open") or chunk by section so the subject travels with the fact.

2. Why use overlap with fixed-size chunking?

So a sentence or rule that straddles a boundary appears whole in at least one chunk. The cost is some duplication in storage and embeddings.

3. You change from 300- to 500-character chunks. What else must happen?

Re-chunk and re-embed the whole corpus, rebuild the index, and re-measure the hit rate to confirm the change helped.

Takeaway

Cut along the document's structure, give every chunk its context and source, and choose the strategy by hit rate, not by eye.
