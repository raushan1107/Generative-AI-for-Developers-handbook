What Are Embeddings?

An embedding is a list of numbers that describes what a piece of text means. Texts with similar meanings get similar numbers, even when they share no words. That one idea powers semantic search, recommendations, duplicate detection and the retrieval half of RAG. You'll deploy an embedding model and look at real vectors.

1

Learn

Meaning, as coordinates.

Definition

An embedding is a fixed-length vector of numbers (for example 1,536 of them) produced by an embedding model from a piece of text, such that texts with similar meaning have vectors that are close together. The model is trained so that distance in this vector space reflects difference in meaning.

In plain words

Each text gets an address in a "meaning space". "Can I have my money back?" and "How do I get a refund?" get addresses on the same street. "My lab says quota exceeded" lives in another part of town.

Imagine this

A map gives every place two numbers: latitude and longitude. Two cafés on the same street have almost the same numbers, so "find cafés near me" is just arithmetic. An embedding does the same for meaning, except it uses hundreds or thousands of directions instead of two: one might loosely track "about money", another "urgent", another "about software".

Facts worth remembering

  • Fixed length: a word and a page both become the same number of dimensions (1,536 for text-embedding-3-small, 3,072 for text-embedding-3-large, 768 for the local nomic-embed-text).
  • Usually normalised to length 1, so similarity is a simple dot product (topic 2).
  • Input limit: text-embedding-3 models accept up to 8,191 tokens per input. Longer documents must be chunked (topic 6), and shorter chunks usually retrieve better anyway.
  • Cheap and fast: one request can embed a batch of texts; embedding a 20-course catalogue costs a fraction of a cent.
  • Not reversible text: you can't read an embedding, and you can't compare embeddings from two different models.
  • Embedding models are not chat models. You deploy them separately and call client.embeddings.create(), not chat completions.
WhatA vector that represents the meaning of a text.
Why"Similar meaning" becomes "nearby numbers", which computers can search fast.
WhenSearch by meaning, recommendations, duplicates, clustering, and retrieval for RAG.
In the real world

Online shops embed product descriptions so "shoes for wet weather" finds waterproof boots. Help centres embed articles so "money back" finds the refunds page. Support teams embed tickets to spot duplicates and trending problems. And almost every "chat with your documents" product embeds document chunks so it can retrieve the right ones before the model answers (Module 06).

Traditional developer view

"Text is a string. Two strings are equal or they aren't."

GenAI developer view

"Text also has a position in meaning space. I store that vector next to the string, and 'how similar are these?' becomes a number I can sort by."

Common trap

Building an index with one embedding model, then switching models (or deployments with different dimensions) for queries. The vectors live in different spaces; similarity scores become meaningless, often without any error. Store the model name with the index and rebuild when it changes (Milestone 5 checks this).

Interview cue

"An embedding is a dense vector representation of text where semantic similarity corresponds to vector closeness. You embed documents and queries with the same model, then compare vectors, typically with cosine similarity."

llm.py
"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 05.1

Your first embeddings

~15 minAzure OpenAIPython · numpy

Goal: deploy an embedding model, embed three sentences in one call, and see dimensions, length and the numbers themselves.

  1. Portal

    Deploy an embedding model

    1. In the Foundry portal, open your project proj-genai-labs.
    2. Go to Models + endpoints (or the model catalog), choose Deploy model and pick text-embedding-3-small.
    3. Name the deployment embed. Standard or Global Standard is fine.
    4. Add AZURE_OPENAI_EMBED_DEPLOYMENT=embed to your .env. The endpoint and key are the same as for your chat deployment.

    No Azure? Run ollama pull nomic-embed-text and set LLM_PROVIDER=ollama. The outputs below come from it.

  2. Run

    Three sentences, one call

    """Drill 05.1: your first embeddings. Text in, a long list of numbers out."""
import numpy as np

from embed import EMBED_MODEL
from llm import get_client

texts = [
    "How do I get a refund for my course?",
    "Can I have my money back?",
    "My lab says quota exceeded.",
]

client = get_client()
response = client.embeddings.create(model=EMBED_MODEL, input=texts)   # one call, a batch of texts

print("model:", EMBED_MODEL, "| tokens used:", response.usage.prompt_tokens)
for text, item in zip(texts, response.data):
    v = np.array(item.embedding)
    print(f"\n{text}")
    print(f"  dimensions: {len(v)}   length (norm): {np.linalg.norm(v):.3f}")
    print(f"  first 5 numbers: {np.round(v[:5], 4).tolist()}")

    The embedding model setting lives in embed.py, the helper you'll use in every Module 05 drill. It batches requests and caches vectors on disk, so re-running a drill costs nothing:

    """Module 05 helper: turn texts into embedding vectors, in batches, with a small disk cache
so re-running a drill doesn't pay for the same embeddings twice."""
import hashlib
import json
import os
from pathlib import Path

import numpy as np

from llm import PROVIDER, get_client

# The embedding model. On Azure, the DEPLOYMENT name of an embedding model (add it to .env).
EMBED_MODEL = {
    "azure": os.getenv("AZURE_OPENAI_EMBED_DEPLOYMENT", "embed"),
    "openai": os.getenv("OPENAI_EMBED_MODEL", "text-embedding-3-small"),
    "ollama": os.getenv("OLLAMA_EMBED_MODEL", "nomic-embed-text"),
}.get(PROVIDER, "")

CACHE_FILE = Path(__file__).parent / "data" / ".embed_cache.json"
BATCH = 64
_cache = json.loads(CACHE_FILE.read_text(encoding="utf-8")) if CACHE_FILE.exists() else {}
_client = None


def _key(model, dimensions, text):
    return hashlib.sha1(f"{model}|{dimensions}|{text}".encode("utf-8")).hexdigest()


def embed(texts, model=EMBED_MODEL, dimensions=None) -> np.ndarray:
    """Return an array of shape (len(texts), dims). `dimensions` works with text-embedding-3 models."""
    global _client
    keys = [_key(model, dimensions, t) for t in texts]
    todo = [(k, t) for k, t in zip(keys, texts) if k not in _cache]
    if todo:
        _client = _client or get_client()
        extra = {"dimensions": dimensions} if dimensions else {}
        for i in range(0, len(todo), BATCH):
            batch = todo[i:i + BATCH]
            response = _client.embeddings.create(model=model, input=[t for _, t in batch], **extra)
            for (k, _), item in zip(batch, response.data):
                _cache[k] = item.embedding
        CACHE_FILE.write_text(json.dumps(_cache), encoding="utf-8")
    return np.array([_cache[k] for k in keys], dtype=np.float32)

  3. Verify
    • On Azure with text-embedding-3-small you'll see dimensions: 1536 and length 1.000.
    • Every sentence, short or long, gives the same number of dimensions.
    • The raw numbers mean nothing to you on their own. The meaning is in how vectors compare, which is the next topic.
    • Look at tokens used: embeddings are billed on input tokens only; there's no output.
3

Check

Embeddings.

1. You embed a one-word query and a 300-word article. Do their vectors have different lengths?

No. Both have the model's fixed number of dimensions. That's what makes them comparable.

2. Can you compare a vector from text-embedding-3-small with one from nomic-embed-text?

No. They're different spaces (and even different sizes). Embed documents and queries with the same model.

Takeaway

An embedding is a text's address in meaning space. Same model for everything, and closeness means similarity.
