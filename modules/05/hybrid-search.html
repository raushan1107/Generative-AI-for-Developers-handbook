Hybrid Search: Keywords and Vectors Together

Vector search understands paraphrases and misses exact details; keyword search nails exact words and misses paraphrases. Hybrid search runs both and merges the rankings, so each covers the other's blind spots. You'll build it from scratch with BM25 and Reciprocal Rank Fusion, measure it honestly, and see why the keyword side needs a proper analyzer.

1

Learn

Two imperfect searches, one good one.

Definition

Hybrid search runs a keyword (full-text) search and a vector search for the same query and merges the two ranked lists into one, commonly with Reciprocal Rank Fusion (RRF): each document scores 1 / (k + rank) in each list (k is usually 60), and the scores are added. Azure AI Search runs hybrid queries this way when you send both search_text and a vector query.

In plain words

Ask two experts: a librarian who matches exact words and a friend who gets what you mean. Anything both of them suggest goes to the top; anything only one suggests still makes the list, lower down.

Imagine this

Two judges score a talent show on different scales: one out of 10, one out of 100. You can't add their scores. But you can add their placings: first place from both judges beats first from one and fifth from the other. RRF combines rankings, not scores, which is exactly why it works for BM25 and cosine, whose numbers aren't comparable.

The pieces

  • BM25 is the classic keyword ranking: a word counts more when it's frequent in the document, rare across the collection, and the document is short. Exact codes (LAB-503), names and numbers ($49) are its strength.
  • Analyzers prepare text for keyword search: lower-casing, splitting words, removing filler words, and stemming ("discounts" → "discount"). Azure AI Search has language analyzers such as en.microsoft. A poor analyzer makes the keyword side noisy, and hybrid inherits the noise (the drill shows this).
  • RRF merges any number of ranked lists with Σ 1/(k + rank). Some services let you weight the vector side more or less heavily.
  • Rerankers (Azure's semantic ranker, or a cross-encoder model) read the query and each of the top results together and reorder them. They improve precision at extra cost and latency; availability depends on the service tier, so check before you rely on it.
In the real world

Hybrid retrieval, often followed by a reranker, is the common default for production RAG systems, because real questions mix both kinds: "error LAB-503 after the 7-day extension" has an exact code and a concept. Search teams tune it with a test set exactly like the one in this drill, and look at the misses one by one.

Traditional developer view

"Keyword search is old; vector search replaces it."

GenAI developer view

"They fail on different queries. I run both, merge by rank, give the keyword side a proper analyzer, and decide with measured hit rates, including the queries where hybrid loses."

Common trap

Adding raw scores: 0.7 × cosine + 0.3 × bm25. BM25 scores can be 0 or 25; cosine sits between about 0.2 and 0.9 depending on the model. The bigger scale silently dominates. Merge by rank (RRF) or normalise carefully, and test.

Interview cue

"Hybrid search combines BM25 keyword and vector retrieval and fuses the rankings with Reciprocal Rank Fusion, so exact terms and paraphrases are both covered. A semantic reranker can then reorder the top results. I validate it on a labelled query set."

  1. Run

    Hybrid in about 40 lines

    """Drill 05.9: hybrid search = keyword ranking (BM25) + vector ranking, merged with
Reciprocal Rank Fusion (RRF), the same merge Azure AI Search uses for hybrid queries."""
import re

import numpy as np
from rank_bm25 import BM25Okapi


STOP = set("a an and are as at be by can do does for from how i if in is it me my of on or our the there "
           "this to use we what when where which will with you your".split())


def tokenize(text):
    """A tiny analyzer: lowercase, keep codes like az-104 together, drop filler words,
    and fold simple plurals (discounts -> discount). Search engines do this, and more, for you."""
    words = re.findall(r"[a-z0-9]+(?:-[a-z0-9]+)*", text.lower())
    return [w[:-1] if len(w) > 3 and w.endswith("s") and not w.endswith("ss") else w
            for w in words if w not in STOP]


def bm25_ranking(query, documents):
    """Document indexes, best keyword match first (documents with no matching word are left out)."""
    bm25 = BM25Okapi([tokenize(d) for d in documents])
    scores = bm25.get_scores(tokenize(query))
    return [int(i) for i in np.argsort(-scores) if scores[i] > 0]


def vector_ranking(query_vector, doc_vectors):
    q = query_vector / np.linalg.norm(query_vector)
    d = doc_vectors / np.linalg.norm(doc_vectors, axis=1, keepdims=True)
    return [int(i) for i in np.argsort(-(d @ q))]


def rrf(rankings, k=60):
    """Each list gives a document 1/(k + rank). Add them up; highest total wins.
    Uses only positions, so BM25 scores and cosine scores never need to be comparable."""
    totals = {}
    for ranking in rankings:
        for rank, doc in enumerate(ranking, start=1):
            totals[doc] = totals.get(doc, 0.0) + 1.0 / (k + rank)
    return sorted(totals, key=lambda doc: -totals[doc])
    """Tests for hybrid.py (offline). Run:  pytest -q test_hybrid.py"""
import numpy as np

from hybrid import bm25_ranking, rrf, tokenize, vector_ranking

DOCS = ["AZ-104 Azure Administrator exam prep", "Python for beginners", "Azure fundamentals AZ-900",
        "Kubernetes for developers"]


def test_tokenize_keeps_codes_and_drops_filler():
    assert tokenize("Prep for AZ-104!") == ["prep", "az-104"]
    assert tokenize("Is there a discount for teams?") == ["discount", "team"]


def test_bm25_finds_exact_codes():
    assert bm25_ranking("AZ-104", DOCS) == [0]


def test_vector_ranking_orders_by_cosine():
    vectors = np.array([[1, 0], [0, 1], [0.7, 0.7]])
    assert vector_ranking(np.array([1, 0.1]), vectors) == [0, 2, 1]


def test_rrf_rewards_agreement():
    keyword, vector = [0, 2, 1], [2, 3, 0]
    fused = rrf([keyword, vector])
    assert fused[:2] == [2, 0]               # 2 and 0 are high in both lists
    assert set(fused) == {0, 1, 2, 3}        # a document in only one list still counts

    """Drill 05.9: keyword vs vector vs hybrid on the help-centre sections.
Each query has the section that should come first. Which method gets it?"""
from chunkers import by_headings, load_articles
from embed import embed
from hybrid import bm25_ranking, rrf, vector_ranking

TESTS = {                                   # query -> heading of the section that answers it
    "LAB-503": "Common problems",
    "what costs $49?": "How long labs stay open",
    "breakout rooms": "Live online",
    "one billing cycle": "When the money arrives",
    "Is there a discount for a team of 12?": "Group discounts",
    "can I use a screen reader?": "Adjustments",
    "money back if the trainer is ill": "If TrainCrest cancels",
    "Docker": None,                         # nothing in the help centre answers this
}

sections = [text for md in load_articles().values() for text in by_headings(md)]
headings = [s.split("\n")[0].split(" > ")[-1] for s in sections]
vectors = embed(sections)
top1 = {"keyword": 0, "vector": 0, "hybrid": 0}
top3 = dict(top1)

for query, expected in TESTS.items():
    rankings = {"keyword": bm25_ranking(query, sections), "vector": vector_ranking(embed([query])[0], vectors)}
    rankings["hybrid"] = rrf([rankings["keyword"], rankings["vector"]])
    print(f"\n{query!r}  (want: {expected or 'no match'})")
    for method, ranking in rankings.items():
        first3 = [headings[i] for i in ranking[:3]]
        top = first3[0] if first3 else None
        ok1 = top == expected
        ok3 = expected in first3 if expected else not first3
        top1[method] += ok1
        top3[method] += ok3
        print(f"  {method:<8} {'OK  ' if ok1 else 'MISS'} {top or '(no match)':<26} in top 3: {'yes' if ok3 else 'no'}")

print("\nRight section first: ", ", ".join(f"{m} {n}/{len(TESTS)}" for m, n in top1.items()))
print("Right section in top 3:", ", ".join(f"{m} {n}/{len(TESTS)}" for m, n in top3.items()))

  3. Verify

    Read it like a search engineer

    • Keyword wins on exact details ("$49", "breakout rooms", "one billing cycle"); vector wins on paraphrases ("screen reader" vs "screen-reader friendly", "trainer is ill" vs "If TrainCrest cancels").
    • Hybrid gets the right section first in 7 of 8, more than either alone, because each list rescues the other.
    • Even the small local model found LAB-503 by vector here: on a tiny corpus, codes often still work. With thousands of similar error codes, vectors blur them; that's where keyword search earns its place.
    • Optional, Azure: python lab05_05_azure_search.py query "certification for cloud admins" --mode hybrid. Hybrid scores are small numbers (RRF sums like 0.03), not similarities.
  4. Think

    Two lessons from the losses

    1. "Docker": nothing in the help centre is about Docker. Keyword search correctly found nothing; vector and hybrid returned Ways to pay. What should Traincrest Assist do with that result?
    2. The analyzer: in hybrid.py, replace the body of tokenize() with just return re.findall(r"[a-z0-9]+(?:-[a-z0-9]+)*", text.lower()) (no stop words, no plural folding) and run the drill again. What happens to hybrid?
    Compare with my answers
    1. Treat it as "no good match": when keyword search finds nothing and the best vector score is low for this model, say the help centre doesn't cover it (or search the catalogue instead). Never pass a weak match to a model as if it were the answer; Module 06 builds this into the RAG prompt and the retrieval code.
    2. On my run, without the analyzer, filler words like "is", "a" and "can" matched random sections: keyword search lost "team of 12" and "screen reader", and hybrid fell to 5/8 first and 5/8 in the top 3, worse than vector alone. With the analyzer: 7/8. The keyword half of hybrid is only as good as its text processing, which is why Milestone 5's Azure index uses the en.microsoft analyzer.

Remember: “Hybrid isn't magic. It's two searches that fail differently, merged by rank, and proven on your own questions.”

3

Check

Hybrid search.

1. Why does RRF use ranks instead of the raw scores?

BM25 scores and cosine similarities are on different, query-dependent scales. Ranks are comparable across both, so no list dominates just because its numbers are bigger.

2. A query is "LAB-409 after my free extension". Which side finds what?

Keyword search matches the exact code LAB-409; vector search matches the idea of lab extensions. Hybrid puts sections that match both at the top.

3. When would you add a reranker?

When the right result is usually in the top 10 but not first, and precision at the top matters (a search page or a RAG prompt with few slots), and you can afford the extra latency and cost. Measure before and after.

Takeaway

Run keyword and vector search, merge them by rank, give the keyword side a real analyzer, and measure wins and losses on your own questions.
