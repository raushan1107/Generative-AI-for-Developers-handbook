Privacy, Safety and Human Review

Sensitive data should not be sent, stored or logged without a clear need. A small masker can demonstrate one narrow pattern, but real privacy protection needs an approved data-handling design and controls at every layer.

Data minimizationMasking limitsFairnessEscalation
1Learn→2Do→3CheckLearn 15 min · Do 15 min
1

Learn

Collect less, retain less, and route high-impact decisions to people.

Definition

Data minimization means using only the personal data needed for a defined purpose. Masking replaces recognized sensitive values before a later step, but coverage depends on the detector. Responsible AI evaluation checks the system for safety, reliability and impact across intended users; human review is a workflow control, not a substitute for testing.

In plain words

Do not send or keep a customer's secrets just because the system can. If the software cannot confidently handle a high-impact request, provide a safe human path.

Imagine this

A bank statement used for a training exercise has the account number replaced with a label. The label helps, but someone still checks that no personal details remain in the file.

In the real world

Azure AI Content Safety provides services for detecting and filtering certain harmful content; it is one component in a broader safety design. For Azure-sold models, Microsoft documents data processing and storage behavior separately. Review the current Content Safety overview and model data and privacy documentation for the service actually used.

In finance

RR Finance Assist should not give personalized investment, credit or legal advice. A disclaimer is not enough: constrain the feature scope, test requests across languages, avoid unsupported recommendations and transfer sensitive or ambiguous cases to an authorized human.

Traditional developer view

"Mask the obvious number before logging it."

GenAI developer view

"Minimize at collection, protect every downstream copy and test safety and quality by risk group and language."

Common trap

Calling a regex masker "PII protection." It may miss unlabelled identifiers, names, addresses, images, misspellings or new formats. Use it only as a narrow example, not a compliance control.

Interview cue

"I minimize data before model calls, mask only with a documented detector and known limitations, define retention and deletion across stores, and evaluate safety and fairness with a human escalation path."

    """Narrow privacy and injection indicators; these are not security boundaries."""

import re


_LABELLED_IDENTIFIER = re.compile(
    r"(?P<label>\b(?:card|account|national\s+ID)\s*(?:number|no\.?|#)"
    r"\s*(?:is|:|=)?\s*)(?P<value>(?:\d[ -]?){8,19}\d)",
    re.IGNORECASE,
)
_INJECTION_PATTERNS = {
    "override_instructions": re.compile(
        r"\bignore\s+(?:all\s+)?previous\s+instructions\b", re.IGNORECASE
    ),
    "reveal_prompt": re.compile(
        r"\breveal\s+(?:the\s+)?(?:system|developer)\s+prompt\b", re.IGNORECASE
    ),
    "request_secret": re.compile(
        r"\bask\s+the\s+customer\s+for\s+(?:their\s+)?"
        r"(?:pin|password|one[- ]time code)\b",
        re.IGNORECASE,
    ),
}


def mask_labeled_identifiers(text: str) -> str:
    """Mask digit sequences only when they follow a supported identifier label."""
    return _LABELLED_IDENTIFIER.sub(
        lambda match: f"{match.group('label')}[REDACTED]", text
    )


def injection_indicators(text: str) -> list[str]:
    """Return matched heuristic labels; absence of a match does not mean safe."""
    return [
        label for label, pattern in _INJECTION_PATTERNS.items() if pattern.search(text)
    ]

Check

Privacy and safety.

1. Does a safety disclaimer make personalized investment advice safe?

No. The system needs a defined feature boundary, validation, evaluation and escalation. A disclaimer cannot repair unsafe behavior.

2. Why should test results be sliced by language?

Aggregate scores can hide uneven behavior for customers who use different languages or communication styles.

Takeaway

Minimize and govern data end to end. Masking and moderation are useful controls with explicit limits—not proof of privacy, safety or fairness.
