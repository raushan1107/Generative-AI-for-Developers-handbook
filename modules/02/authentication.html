Authentication and API Keys

A key is a password that never expires; a token is a temporary pass tied to an identity. You'll see both on the wire: first a raw HTTP call with a key, then the same call with no key at all, after your AI assistant writes the role assignment for you.

1

Learn

House keys vs hotel key cards.

Definition

LLM APIs authenticate each request either with a static API key sent in a header, or with a short-lived access token issued by an identity provider (for Azure, a Microsoft Entra ID token checked against role-based access control).

In plain words

A key is a long password: whoever has it can spend your money, forever, until you regenerate it. A token is a temporary pass your app gets by proving who it is; it expires in about an hour and access can be removed centrally. Keys are fine for learning. Tokens are what you want in production.

Imagine this

An API key is a house key: copy it once and the copy works forever, and you'll never know who has one. A token is a hotel key card: issued at the front desk after checking your ID, it stops working at checkout, and the desk can deactivate it at any time.

Key hygiene

  • Never in code, never in the client. .env locally; Azure Key Vault or managed identity in the cloud.
  • Rotate without downtime. Azure gives each resource two keys: move apps to key 2, regenerate key 1, repeat next time.
  • One key per app and environment where possible, so a leak has a small blast radius.
  • Prefer keyless: a managed identity plus an RBAC role means there's no secret to leak at all.
In the real world

Leaked AI keys are a constant problem: bots scrape public repositories for them within minutes, and platforms such as GitHub run secret scanning that detects many provider key formats and alerts the owner. Enterprises on Azure typically disable key authentication on their AI resources altogether and use managed identities, so there is nothing to leak.

Interview cue

"In production on Azure I'd disable key auth and use managed identity with RBAC, so there's no secret to rotate or leak. Keys are for local development, in environment variables, never in the repo."

Before you run this code

Run every drill from your genai-labs folder with its virtual environment active. Two files must be there: .env (settings) and llm.py (the shared helper every drill imports). By default they use a free local model with Ollama: install Ollama, then ollama pull llama3.2; no key is needed. To use Azure OpenAI or OpenAI instead, change LLM_PROVIDER in .env.

Easiest: download the genai-labs starter kit (every helper, data file and drill script), unzip it, copy .env.example to .env, and run pip install -r requirements.txt. Full walkthrough: Helpers and smoke test.

llm.py
"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 02.2

See the wire: one call with raw HTTP and a key

~10 minAzure OpenAIPython · requests

Goal: make one chat call without any SDK, see the exact headers and JSON, and save the response for Drill 02.4.

  1. Run 
    """Drill 02.2: one chat call with plain HTTP, to see exactly what the SDK hides."""
import json
import os
import time
from pathlib import Path

import requests
from dotenv import load_dotenv

load_dotenv()

url = os.environ["AZURE_OPENAI_BASE_URL"].rstrip("/") + "/chat/completions"
headers = {
    "api-key": os.environ["AZURE_OPENAI_API_KEY"],  # Azure's key header
    "Content-Type": "application/json",
}
body = {
    "model": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "messages": [
        {"role": "system", "content": "You are Traincrest Assist, TrainCrest's learner-support assistant. Be brief."},
        {"role": "user", "content": "What does 'batch confirmed' mean on my enrolment?"},
    ],
}

start = time.perf_counter()
resp = requests.post(url, headers=headers, json=body, timeout=60)
print(f"HTTP {resp.status_code} in {time.perf_counter() - start:.2f}s\n")

for name in ("x-request-id", "apim-request-id", "x-ratelimit-remaining-requests", "x-ratelimit-remaining-tokens"):
    if name in resp.headers:
        print(f"{name}: {resp.headers[name]}")

data = resp.json()
print("\n" + json.dumps(data, indent=2, ensure_ascii=False))
Path("response.json").write_text(json.dumps(data, indent=2, ensure_ascii=False), encoding="utf-8")
print("\nSaved the response body to response.json")

Drill 02.3

Go keyless: role assignment by prompt, then call with your identity

~15 minAzure CLI · Entra IDAI assistant

Goal: call your deployment with no API key: Azure checks who you are and what role you have.

Before you start: Azure CLI installed and az login done. You need permission to assign roles on the resource group (Owner or User Access Administrator); on a company subscription, ask your admin.

  1. Your prompt

    Ask your assistant for the role assignment commands

    Goal:        Azure CLI commands to give … the role … on …
Context:     resource group …, Foundry resource …, I'm signed in with az login; shell is …
Constraints: look up my object ID and the resource ID with az commands, don't hard-code them;
             least privilege (only what's needed to call deployments)
Done when:   a command lists my role assignment on that resource

    Hint: the role is Cognitive Services OpenAI User, the assignee is the signed-in user (az ad signed-in-user show), and the scope is the Foundry resource's ID (az cognitiveservices account show … --query id).

    Compare with my prompt and the expected commands
    Give me PowerShell Azure CLI commands to assign the "Cognitive Services OpenAI User" role to
the user I'm signed in as (az login), scoped to the Foundry resource aif-genai-rr in resource
group rg-genai-labs. Look up my object ID and the resource ID with az commands instead of
hard-coding them. Then give me a command that lists my role assignments on that resource.
Explain in one line why this role is enough to call deployments but not to manage them.
    PS> $me = az ad signed-in-user show --query id -o tsv
PS> $scope = az cognitiveservices account show -n aif-genai-rr -g rg-genai-labs --query id -o tsv
PS> az role assignment create --assignee $me --role "Cognitive Services OpenAI User" --scope $scope
PS> az role assignment list --assignee $me --scope $scope -o table
  2. Run

    Call the model with your identity

    """Drill 02.3: call Azure OpenAI with your Microsoft Entra ID identity. No API key at all."""
import os

from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

# DefaultAzureCredential tries, in order: environment variables, managed identity,
# Azure CLI login (az login), VS Code sign-in, and more. Locally, az login is enough.
token_provider = get_bearer_token_provider(
    DefaultAzureCredential(), "https://cognitiveservices.azure.com/.default"
)
client = OpenAI(base_url=os.environ["AZURE_OPENAI_BASE_URL"], api_key=token_provider)

r = client.chat.completions.create(
    model=os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    messages=[{"role": "user", "content": "Say 'keyless works' and nothing else."}],
)
print(r.choices[0].message.content)
    $ python lab02_03_keyless.py

    Role assignments can take a few minutes to apply. A 401 or 403 right after assigning usually just means "wait and retry".

    • The script prints "keyless works" without using AZURE_OPENAI_API_KEY (comment it out in .env to prove it).
    • az role assignment list shows your role on the resource.

3

Check

Credentials.

1. Your key leaked in a public repo an hour ago and you deleted the commit. Are you safe?

No. Assume it's been copied. Regenerate the key now (Azure's two keys let you do it without downtime), then check usage for abuse.

2. Why is "Cognitive Services OpenAI User" better for an app than Contributor on the resource?

Least privilege: it can call deployments but not create, delete or reconfigure them, or read keys.

Takeaway

Keys for learning, identities for production. The safest secret is the one that doesn't exist.
