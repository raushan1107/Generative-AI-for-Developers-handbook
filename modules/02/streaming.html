Streaming Responses

Without streaming, users stare at a spinner. With streaming, words appear as soon as the model produces them. Total time barely changes; what changes is how long people wait before seeing something. You'll measure both, then look at the raw events on the wire.

1

Learn

Same kitchen, very different guests.

Definition

Streaming returns the response incrementally as it's generated, typically using server-sent events (SSE): the server sends a series of small JSON chunks, each with the next piece of text (a delta), followed by an end marker.

In plain words

The model writes one token at a time anyway (Module 01). Streaming just sends each piece the moment it exists, instead of waiting for the whole answer. The user starts reading in under a second.

Imagine this

At a buffet, food arrives dish by dish and you start eating. At a dinner where the kitchen waits until all eight courses are ready, you sit hungry for forty minutes. Same food, same kitchen time. Very different guests.

What it looks like on the wire 
data: {"choices":[{"delta":{"role":"assistant","content":""}}], …}
data: {"choices":[{"delta":{"content":"It"}}], …}
data: {"choices":[{"delta":{"content":" means"}}], …}
…
data: {"choices":[{"delta":{},"finish_reason":"stop"}], …}
data: [DONE]

Facts worth remembering

  • In the OpenAI SDK pass stream=True and read chunk.choices[0].delta.content.
  • Some chunks have no choices (Azure sends content-filter results this way; the final usage chunk is empty too). Always check before indexing.
  • Usage isn't in streamed chunks by default: ask with stream_options={"include_usage": True}; it arrives last.
  • You can't validate a whole JSON object until the stream ends. Stream text to humans; collect structured output before using it.
  • Proxies that buffer responses silently break streaming end-to-end. Test through the full path (Milestone 2 sets a header for this).
In the real world

Every major chat product streams, and teams track TTFT as a headline metric alongside total latency. Voice assistants go further: they start speaking the first sentence while the rest is still being generated. Back-end jobs (summarising 10,000 tickets overnight) don't stream at all: nobody is watching, so they use batch processing instead (Module 11).

Interview cue

"Streaming uses server-sent events to send deltas as tokens are generated. It doesn't make generation faster; it cuts time to first token, which is what users perceive as speed."

Do

Measure the difference, then look under the hood.

Drill 02.8

Streaming vs waiting: measure time to first token

~10 minAzure OpenAIPython

Goal: measure the same answer with and without streaming, and handle chunks safely.

  1. Run 
    """Drill 02.8: streaming. Time to first token vs total time."""
import time

from llm import get_client, MODEL

client = get_client()
messages = [{"role": "user", "content": "Write a 150-word guide to preparing for a cloud certification exam."}]

# A) Wait for the whole answer
start = time.perf_counter()
client.chat.completions.create(model=MODEL, messages=messages)
print(f"Without streaming: blank screen for {time.perf_counter() - start:.1f}s, then everything at once.\n")

# B) Stream it
start, ttft, chunks, usage = time.perf_counter(), None, 0, None
stream = client.chat.completions.create(
    model=MODEL, messages=messages,
    stream=True, stream_options={"include_usage": True},
)
for chunk in stream:
    if chunk.usage:                 # the last chunk carries token usage
        usage = chunk.usage
    if not chunk.choices:           # some chunks carry no text (filter results, usage)
        continue
    delta = chunk.choices[0].delta.content
    if delta:
        if ttft is None:
            ttft = time.perf_counter() - start
        chunks += 1
        print(delta, end="", flush=True)

total = time.perf_counter() - start
print(f"\n\nWith streaming: first words after {ttft:.1f}s, done after {total:.1f}s, {chunks} chunks.")
if usage:
    print(f"Usage: {usage.prompt_tokens} in / {usage.completion_tokens} out")
    $ python lab02_08_streaming.py
    Expected (end of run) 
    Without streaming: blank screen for 5.8s, then everything at once.

  2. Verify
    • TTFT is a fraction of total time.
    • Remove the if not chunk.choices: continue line and run again. On Azure you'll likely get an IndexError: that guard matters. Put it back.
Open alternative · streaming with Claude
import time
from claude_llm import client, CLAUDE_MODEL, FALLBACK

start, ttft = time.perf_counter(), None
with client.beta.messages.stream(
    model=CLAUDE_MODEL, max_tokens=4000,
    messages=[{"role": "user", "content": "Write a 150-word guide to preparing for a cloud certification exam."}],
    **FALLBACK,
) as stream:
    for text in stream.text_stream:
        ttft = ttft or time.perf_counter() - start
        print(text, end="", flush=True)
    final = stream.get_final_message()
print(f"\n\nTTFT {ttft:.1f}s · total {time.perf_counter() - start:.1f}s · {final.usage.output_tokens} tokens out")

The SDK's text_stream hides the event plumbing; Claude's underlying events (message_start, content_block_delta, message_stop) differ from OpenAI's, but the idea is identical.

Drill 02.9

Look at the raw server-sent events

~10 minAzure OpenAIPython · requests

Goal: see the SSE format you'll produce yourself in Milestone 2, where your backend streams to a browser.

  1. Run 
    """Drill 02.9: look at the raw server-sent events (SSE) behind streaming."""
import os

import requests
from dotenv import load_dotenv

load_dotenv()

url = os.environ["AZURE_OPENAI_BASE_URL"].rstrip("/") + "/chat/completions"
headers = {"api-key": os.environ["AZURE_OPENAI_API_KEY"], "Content-Type": "application/json"}
body = {
    "model": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "messages": [{"role": "user", "content": "Name three cloud providers, comma separated."}],
    "stream": True,
}

with requests.post(url, headers=headers, json=body, stream=True, timeout=60) as resp:
    print("HTTP", resp.status_code, "·", resp.headers.get("content-type"), "\n")
    for line in resp.iter_lines(decode_unicode=True):
        if line:                      # events are separated by blank lines
            print(line[:140])
    $ python lab02_09_raw_sse.py
  2. Think

    Design question for Milestone 2

    Your FastAPI backend will receive these chunks from Azure and forward text to the browser. Should it forward Azure's raw events, or send its own simpler events? Why?

    Compare with my answer

    Send your own events (for example {"type": "delta", "text": …} and a final {"type": "done", …}). The browser shouldn't depend on one provider's format, you can add your own fields (cost, prompt version), and you can switch providers without touching the front end. That's exactly what Milestone 2 does.

3

Check

Streaming.

1. Does streaming reduce the cost or total time of a response?

No. Same tokens, roughly the same total time. It reduces time to first token, the perceived wait.

2. Your API returns JSON for a mobile app to parse. Should you stream it to the app token by token?

Usually not: the app can't parse partial JSON. Collect the full response on the backend, validate it, then return it.

Takeaway

Stream to humans, buffer for machines, and always measure TTFT.
