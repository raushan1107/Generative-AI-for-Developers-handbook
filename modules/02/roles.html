System, User and Assistant Messages

The model remembers nothing between calls. Chat 'memory' is your app resending the conversation every single time, with a system message on top that sets the rules. You'll prove it, then write the tested trimming function that keeps memory affordable.

1

Learn

Memory is just resending.

Definition

Chat APIs take a list of messages, each with a role. The system (or developer) message sets the model's behaviour and rules; user messages carry the end user's input; assistant messages are the model's previous replies. The API is stateless, so the relevant conversation must be sent with every request.

In plain words

The system message is the job description, written by you. User messages are what the learner says. Assistant messages are what the model said earlier. The model remembers nothing between calls, so your app keeps the transcript and sends it back every time. That's the whole "memory" of a chatbot.

Imagine this

A call centre where every agent has total amnesia. Each time the customer speaks, a new agent picks up. To make it work, the supervisor hands each one a sheet: the role card on top ("You're a TrainCrest support agent; be kind; never promise refunds"), then the transcript so far, then the newest sentence. The agent reads it all, replies once, and is gone. The sheet gets longer every turn.

Facts worth remembering

  • The system message has the strongest influence on behaviour: rules, persona, tone and boundaries go there.
  • Newer OpenAI reasoning models also accept a developer role that works like system. Don't send both in one request.
  • Claude's API takes the system prompt as a separate system parameter, and its messages list starts with a user turn.
  • You can write assistant messages yourself to show the model an example exchange: few-shot prompting (Module 03).
  • A user can write anything, including "ignore your instructions". User content is never trusted (Modules 03 and 10).
In the real world

When ChatGPT or Claude.ai "remember" a long conversation, the application is managing history for you: resending recent turns, and for very long chats summarising or dropping older ones. Some products also keep separate long-term "memories" (facts about you) that they insert into the system context. Under the hood it's always the same thing: deciding what goes into the next request.

Traditional developer view

"Chat apps have sessions. The server remembers the conversation."

GenAI developer view

"The model is stateless. I own conversation state: where it's stored, how much I resend, what I trim, and that the system message always comes first."

Interview cue

"How does a chatbot remember context?" "It doesn't; the app resends conversation history in the messages array on each call, trimmed or summarised to fit the context window and control cost."

Drill 02.5

Roles and memory by hand

~10 minAzure OpenAIPython

Goal: prove the API is stateless, build memory yourself, watch input tokens grow, and see how strongly the system message and example turns steer the model.

  1. Run 
    """Drill 02.5: the API is stateless. You build the memory."""
from llm import get_client, MODEL

client = get_client()
SYSTEM = {"role": "system", "content": "You are Traincrest Assist, TrainCrest's learner-support assistant. One short sentence per reply."}


def chat(messages):
    r = client.chat.completions.create(model=MODEL, messages=messages)
    return r.choices[0].message.content.strip(), r.usage.prompt_tokens


# 1) Two independent calls: the second knows nothing about the first
print("1) No memory")
print("   ", chat([SYSTEM, {"role": "user", "content": "Hi, I'm Diego. I'm enrolled in the AZ-305 course."}])[0])
print("   ", chat([SYSTEM, {"role": "user", "content": "Which course am I enrolled in?"}])[0])

# 2) Same questions, but we keep and resend the history ourselves
print("\n2) Memory = resending history")
history = [SYSTEM]
for turn in ["Hi, I'm Diego. I'm enrolled in the AZ-305 course.", "Which course am I enrolled in?", "And what's my name?"]:
    history.append({"role": "user", "content": turn})
    reply, tokens_in = chat(history)
    history.append({"role": "assistant", "content": reply})
    print(f"   [{tokens_in:4} tokens in] {turn}\n                     -> {reply}")

# 3) The system message steers everything
print("\n3) Swap the system message")
grumpy = [{"role": "system", "content": "You are a grumpy pirate. One sentence."},
          {"role": "user", "content": "When does my course start?"}]
print("   ", chat(grumpy)[0])

# 4) Assistant messages you write yourself teach a pattern
print("\n4) Teach a format with example turns")
pattern = [SYSTEM,
           {"role": "user", "content": "Status of TC-10001"},
           {"role": "assistant", "content": "STATUS: CONFIRMED | STARTS: 12 Jan"},
           {"role": "user", "content": "Status of TC-10002"},
           {"role": "assistant", "content": "STATUS: WAITLISTED | STARTS: 2 Feb"},
           {"role": "user", "content": "Status of TC-10293"}]
print("   ", chat(pattern)[0])

Drill 02.6

Write a tested history-trimming function

    Reference solution
    """Drill 02.6 (reference solution): keep the system message and the most recent turns."""


def trim_history(messages, max_turns):
    """Return a NEW list with the system message (if first) plus the last `max_turns`
    user/assistant pairs. The kept turns never start with an assistant message."""
    if max_turns < 0:
        raise ValueError("max_turns must be >= 0")
    system = [m for m in messages[:1] if m["role"] == "system"]
    rest = messages[len(system):]
    kept = rest[-(max_turns * 2):] if max_turns else []
    while kept and kept[0]["role"] != "user":
        kept = kept[1:]
    return system + kept
    """Tests for history.trim_history. Run with:  pytest -q test_history.py"""
from history import trim_history

SYS = {"role": "system", "content": "You are Traincrest Assist."}


def turns(n):
    out = []
    for i in range(n):
        out += [{"role": "user", "content": f"u{i}"}, {"role": "assistant", "content": f"a{i}"}]
    return out


def test_keeps_system_and_last_pairs():
    result = trim_history([SYS] + turns(5), max_turns=2)
    assert result[0] == SYS
    assert [m["content"] for m in result[1:]] == ["u3", "a3", "u4", "a4"]


def test_short_history_is_unchanged():
    messages = [SYS] + turns(1)
    assert trim_history(messages, max_turns=6) == messages


def test_never_starts_with_assistant():
    messages = [SYS] + turns(3) + [{"role": "user", "content": "new question"}]
    result = trim_history(messages, max_turns=2)
    assert result[1]["role"] == "user"
    assert result[-1]["content"] == "new question"


def test_works_without_system_message():
    assert trim_history(turns(3), max_turns=1) == turns(3)[-2:]


def test_does_not_modify_input():
    messages = [SYS] + turns(4)
    snapshot = list(messages)
    trim_history(messages, max_turns=1)
    assert messages == snapshot

3

Check

Roles and state.

1. A learner says "I told you my enrolment ID five messages ago!" and the bot doesn't know it. Likely cause?

The history was trimmed (or never sent), so that message wasn't in the request. Fixes: keep more turns, summarise older turns, or pull key facts like the enrolment ID into the system context (Module 07).

2. Where should "Never promise refunds" go: system or user message?

The system message. Rules belong to you, not to the user's turn, and the system message has the strongest influence.

Takeaway

The model is stateless; your app is the memory. Decide deliberately what you resend.
