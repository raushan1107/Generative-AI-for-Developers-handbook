The Request/Response Lifecycle

Strip away the SDK and an LLM call is one HTTPS POST with a very particular shape. Knowing that shape is what lets you debug at 2 a.m. You'll read a real response and have your assistant build a small inspector that pulls out the fields that matter.

1

Learn

One POST, several gates.

Here's the Chat Completions format, which Azure OpenAI, OpenAI, Ollama and many other providers all accept.

The request 
POST https://<resource>.openai.azure.com/openai/v1/chat/completions
api-key: ••••••••
Content-Type: application/json

{
  "model": "chat",                              # deployment name on Azure
  "messages": [
    { "role": "system", "content": "You are Traincrest Assist, TrainCrest's support assistant." },
    { "role": "user",   "content": "What does 'batch confirmed' mean?" }
  ],
  "max_completion_tokens": 400                  # optional parameters
}
The response (trimmed) 
{
  "id": "chatcmpl-…",
  "model": "gpt-5.4-mini-2026-03-17",           # the model version that answered
  "choices": [{
    "index": 0,
    "message": { "role": "assistant", "content": "It means your seat is reserved…" },
    "finish_reason": "stop"                     # why generation ended
  }],
  "usage": {
    "prompt_tokens": 38,                        # you pay for these…
    "completion_tokens": 54,                    # …and these, priced higher
    "total_tokens": 92,
    "completion_tokens_details": { "reasoning_tokens": 0 }
  }
}

Read finish_reason every time

ValueMeaningWhat your code should do
stopFinished naturally or hit a stop sequenceUse the answer
lengthHit the output token cap mid-answerDon't show a half answer as complete; raise the cap or ask for brevity
content_filterOutput blocked by safety filteringShow a safe fallback message; log it
tool_callsThe model wants your code to run a functionModule 04
Chat Completions vs the Responses API

OpenAI and Azure also offer a newer Responses API (client.responses.create) with server-side conversation state and built-in tools. This handbook uses Chat Completions because it's the common format across Azure, OpenAI, Ollama and many others. Messages, parameters, streaming and usage carry over directly.

In the real world

Production teams log at least the request ID, model version, finish_reason, token usage and latency for every call. When a customer says "the bot gave me a weird answer yesterday", those five fields are how you find out what happened: which model version, whether it was truncated, how long it took.

Interview cue

"A chat request is model + messages + parameters; the response gives choices, finish_reason and usage. I always check finish_reason, because a 200 can still be a truncated or filtered answer."

Before you run this code

Run every drill from your genai-labs folder with its virtual environment active. Two files must be there: .env (settings) and llm.py (the shared helper every drill imports). By default they use a free local model with Ollama: install Ollama, then ollama pull llama3.2; no key is needed. To use Azure OpenAI or OpenAI instead, change LLM_PROVIDER in .env.

Easiest: download the genai-labs starter kit (every helper, data file and drill script), unzip it, copy .env.example to .env, and run pip install -r requirements.txt. Full walkthrough: Helpers and smoke test.

llm.py
"""Shared helper for every drill: returns an OpenAI-compatible client for
Azure OpenAI (Microsoft Foundry), OpenAI or Ollama, chosen in .env."""
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads .env from the current folder

PROVIDER = os.getenv("LLM_PROVIDER", "ollama").lower()   # default: a free local model (Ollama)


def get_client() -> OpenAI:
    if PROVIDER == "azure":
        # Azure OpenAI v1 API: the standard OpenAI client, pointed at your resource
        return OpenAI(
            base_url=os.environ["AZURE_OPENAI_BASE_URL"],
            api_key=os.environ["AZURE_OPENAI_API_KEY"],
        )
    if PROVIDER == "openai":
        return OpenAI()  # reads OPENAI_API_KEY
    if PROVIDER == "ollama":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    raise ValueError(f"Unknown LLM_PROVIDER: {PROVIDER!r}")


# On Azure this is the DEPLOYMENT name; elsewhere it's the model name.
MODEL = {
    "azure": os.getenv("AZURE_OPENAI_DEPLOYMENT", "chat"),
    "openai": os.getenv("OPENAI_MODEL", "gpt-5.4-mini"),
    "ollama": os.getenv("OLLAMA_MODEL", "llama3.2"),
}.get(PROVIDER, "")
Drill 02.4

Build a response inspector

~15 minAI assistant · no API cost

Goal: a script that prints the fields that matter from a saved response, including error bodies, using response.json from Drill 02.2.

  1. Ask AI 
    Look at #response.json (a saved Azure OpenAI chat completion). Write inspect_response.py that
takes an optional path argument (default response.json) and prints, one per line: model,
finish_reason, the first 200 characters of the answer, prompt and completion tokens, reasoning
tokens (0 if absent), and whether any content filter category was flagged. If the file is an
error body ({"error": {...}}), print the error code and message and exit with code 1.
Standard library only.
    Why this prompt works: it points the assistant at a real example of the data (so it doesn't guess the shape), lists exact outputs, and covers the error case and missing fields explicitly.
    Reference solution
    """Drill 02.4 (reference solution): print the fields that matter from a saved chat completion."""
import json
import sys
from pathlib import Path

path = Path(sys.argv[1] if len(sys.argv) > 1 else "response.json")
data = json.loads(path.read_text(encoding="utf-8"))

if "error" in data:
    print("ERROR:", data["error"].get("code"), "-", data["error"].get("message"))
    sys.exit(1)

choice = data["choices"][0]
usage = data.get("usage") or {}
details = usage.get("completion_tokens_details") or {}

print(f"model            {data.get('model')}")
print(f"finish_reason    {choice.get('finish_reason')}")
print(f"answer           {(choice['message'].get('content') or '')[:200]}")
print(f"tokens in / out  {usage.get('prompt_tokens')} / {usage.get('completion_tokens')}")
print(f"reasoning tokens {details.get('reasoning_tokens', 0)}")

filters = choice.get("content_filter_results")
if filters:
    flagged = [name for name, result in filters.items() if isinstance(result, dict) and result.get("filtered")]
    print(f"content filter   {'flagged: ' + ', '.join(flagged) if flagged else 'nothing filtered'}")
  2. Verify

    Run it on your saved response, then create error.json with the content below and run it again:

    {"error": {"code": "DeploymentNotFound", "message": "no such deployment"}}

3

Check

Read the response.

1. A response is HTTP 200 but the answer stops mid-sentence. What do you check?

finish_reason: it's length. The output cap was hit (reasoning tokens count too).

2. Which five fields would you log for every call?

Request ID, model version, finish_reason, token usage and latency (plus your own prompt version, from Module 03).

Takeaway

A 200 is not the same as success. Read finish_reason and usage on every response.
