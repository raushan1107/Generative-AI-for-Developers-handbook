Managing API Costs

Every token in and out is metered. One call costs a fraction of a cent; 25,000 learners chatting four turns each, with a bloated prompt on an expensive model, is a real monthly bill. You'll do the maths once, build a cost meter, and have your assistant turn the logs into a usage report.

1

Learn

A taxi meter that runs on words.

Definition

LLM API cost per call is input tokens × input price + output tokens × output price (prices usually per million tokens), where output includes hidden reasoning tokens. Total cost scales with volume, prompt size, conversation length and model choice.

In plain words

It's a taxi meter that runs on tokens, with the meter running faster for output than input. The good news: most of the bill comes from a few things you control.

Do the maths once (illustrative prices)

Say your model costs $0.40 per million input tokens and $1.60 per million output tokens (check your model's current price). TrainCrest has 25,000 conversations a month, averaging 4 turns: 100,000 turns.

ScenarioPer turnMonthly tokensMonthly cost
Lean prompt, short answers1,500 in · 250 out150M in · 25M out$60 + $40 = $100
Bloated 6,000-token prompt7,500 in · 250 out750M in · 25M out$300 + $40 = $340
Bloated prompt, model 10× the pricesamesame$3,400

Same feature, a 34× difference, from two decisions: prompt size and model choice.

The cost levers, easiest first

  1. Measure. Log usage per call with a feature name. You can't optimise what you can't see.
  2. Choose the smallest model that passes your quality bar (Drill 01.11, Module 11).
  3. Trim the prompt: remove repeated instructions, send only relevant documents, trim history.
  4. Cap the output with max_completion_tokens and instructions like "under 80 words".
  5. Lower reasoning effort for simple tasks; hidden reasoning is billed as output.
  6. Cache and batch repeated and non-urgent work (Module 11).
  7. Set budgets and alerts so surprises arrive by email, not on the invoice.
In the real world

Teams running AI features at scale track cost per feature and per user, set quotas so one heavy user can't run up the bill, and use provider discounts: prompt caching for repeated prompt prefixes, batch APIs for overnight work, and committed capacity for steady high volume. Many discover that a long, repeated system prompt is their single biggest cost line.

Common trap

Testing cost with a three-message demo and multiplying. Real conversations are longer, history is resent every turn, and a few power users send ten times the average. Project from real logged usage after a pilot.

Interview cue

"Cost is input × input price + output × output price, times volume. My biggest levers are model choice, prompt size, history trimming and output caps, and I log usage per feature."

Drill 02.14

A cost meter: tokens → dollars → monthly projection

~10 minAzure OpenAIPython

Goal: measure how prompt size and brevity change the projected bill, and log each call to usage.jsonl for the next drill.

  1. Run

    Put your model's real prices in .env (PRICE_IN_PER_M, PRICE_OUT_PER_M), then:

    """Drill 02.14: a cost meter. Usage -> dollars -> monthly projection. Also logs to usage.jsonl."""
import json
import os
import time

from llm import get_client, MODEL

PRICE_IN = float(os.getenv("PRICE_IN_PER_M", "0.40"))     # USD per 1M input tokens
PRICE_OUT = float(os.getenv("PRICE_OUT_PER_M", "1.60"))   # USD per 1M output tokens
TURNS_PER_MONTH = 25_000 * 4                              # TrainCrest: conversations x average turns

client = get_client()


def cost_usd(usage):
    return (usage.prompt_tokens * PRICE_IN + usage.completion_tokens * PRICE_OUT) / 1_000_000


LEAN = "You are Traincrest Assist, TrainCrest's learner-support assistant. Be brief and friendly."
BLOATED = LEAN + " Always follow the TrainCrest tone guide and be warm and professional." * 120
question = "My lab environment expired before I finished the final exercise. What can I do?"

for label, system in [
    ("bloated prompt", BLOATED),
    ("lean prompt", LEAN),
    ("lean + 'under 60 words'", LEAN + " Answer in under 60 words."),
]:
    r = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "system", "content": system}, {"role": "user", "content": question}])
    u = r.usage
    details = getattr(u, "completion_tokens_details", None)
    reasoning = getattr(details, "reasoning_tokens", 0) or 0
    per_turn = cost_usd(u)
    print(f"{label:26} {u.prompt_tokens:5} in · {u.completion_tokens:4} out ({reasoning} reasoning) · "
          f"${per_turn:.5f}/turn · ~${per_turn * TURNS_PER_MONTH:,.0f}/month")
    with open("usage.jsonl", "a", encoding="utf-8") as log:
        log.write(json.dumps({"ts": time.strftime("%Y-%m-%dT%H:%M:%S"), "label": label, "model": MODEL,
                              "tokens_in": u.prompt_tokens, "tokens_out": u.completion_tokens,
                              "cost_usd": round(per_turn, 6)}) + "\n")
    $ python lab02_14_cost_meter.py
    Expected shape (numbers depend on model and price) 
    bloated prompt              1561 in ·  212 out (0 reasoning) · $0.00096/turn · ~$96/month
lean prompt                   41 in ·  205 out (0 reasoning) · $0.00034/turn · ~$34/month
lean + 'under 60 words'       47 in ·   78 out (0 reasoning) · $0.00014/turn · ~$14/month
  2. Verify
    • The bloated system prompt is paid on every turn: boilerplate is the most expensive text you'll write.
    • Brevity cut output tokens, the pricier ones.
    • usage.jsonl exists with three JSON lines. Run the script two more times to give the next drill more data.
Drill 02.15

Build a usage report from your logs

~15 minAI assistant · no API cost

Goal: turn raw usage logs into the table a product owner actually asks for: "what does each feature cost, per call and per month?"

  1. Ask AI 
    #usage.jsonl has one JSON object per line with keys: ts, label, model, tokens_in, tokens_out,
cost_usd. Write usage_report.py (standard library only) that reads it (path argument, default
usage.jsonl), groups by label, and prints a table with: label, number of calls, average tokens
in, average tokens out, average $ per call, and projected $ per month for --turns-per-month
(default 100000). Sort by average cost per call, most expensive first. Skip blank lines.
    Why this prompt works: the exact input schema, the exact output columns, the default volume and the sort order. A real example file for context means the assistant doesn't have to guess the data shape.
    Reference solution
    """Drill 02.15 (reference solution): summarise usage.jsonl by label and project a monthly bill."""
import argparse
import json
from collections import defaultdict
from pathlib import Path


def main():
    parser = argparse.ArgumentParser(description="Summarise LLM usage from a JSON-lines log.")
    parser.add_argument("log", nargs="?", default="usage.jsonl")
    parser.add_argument("--turns-per-month", type=int, default=100_000)
    args = parser.parse_args()

    totals = defaultdict(lambda: {"calls": 0, "in": 0, "out": 0, "cost": 0.0})
    for line in Path(args.log).read_text(encoding="utf-8").splitlines():
        if not line.strip():
            continue
        row = json.loads(line)
        t = totals[row.get("label", "unlabelled")]
        t["calls"] += 1
        t["in"] += row.get("tokens_in", 0)
        t["out"] += row.get("tokens_out", 0)
        t["cost"] += row.get("cost_usd", 0.0)

    print(f"{'label':26} {'calls':>5} {'avg in':>8} {'avg out':>8} {'avg $/call':>11} {'$/month':>10}")
    for label, t in sorted(totals.items(), key=lambda kv: -kv[1]["cost"] / kv[1]["calls"]):
        avg_cost = t["cost"] / t["calls"]
        print(f"{label:26} {t['calls']:>5} {t['in'] // t['calls']:>8} {t['out'] // t['calls']:>8} "
              f"{avg_cost:>11.5f} {avg_cost * args.turns_per_month:>10,.0f}")


if __name__ == "__main__":
    main()
  2. Verify 
    $ python usage_report.py
    Expected shape 
    label                      calls   avg in  avg out  avg $/call    $/month
bloated prompt                 3     1561      209     0.00096         96
lean prompt                    3       41      201     0.00034         34
lean + 'under 60 words'        3       47       80     0.00014         14
    • Calls per label match the number of times you ran Drill 02.14.
    • The most expensive label is at the top.

Try this: multiply by a four-times-longer real conversation (history is resent every turn) and a model with ten times the price. That's why Module 11 exists.

3

Check

Money.

1. The projected bill doubled after a prompt change. Where do you look first?

The usage logs: prompt_tokens per turn. A longer system prompt is paid on every turn, and history multiplies it.

2. Name three cost levers that don't require changing the model.

Any three of: trim the prompt, trim history, cap output, lower reasoning effort, cache repeated work, batch non-urgent work.

Takeaway

Log usage on every call. The bill is decided by prompt size, output length and model choice, all of which you control.
