Exercise 2 · An assistant that calls your functions


Module 04's hands-on exercise: an AI assistant that calls application functions: search products (here, courses), retrieve customer information, create a support ticket and check order (enrolment) status.


Task 1: Build the assistant


    
  
  1. Create l2_tools.py:
    
    2. 
  
  2. Read the three parts: the functions are ordinary Python; TOOLS describes them to the model as JSON Schema; ask() is the tool loop: call the model, run any function it asks for, send the result back, repeat until it answers (at most 5 rounds).
    3. 
  
  3. This exercise uses AGENT_MODEL from .env, the model for tool calling. Set it to qwen2.5:7b if you pulled it: llama3.2 often writes a tool call as text, or tells you to call the functions yourself.
    4. 
  
  4. Notice SIGNED_IN = "L-MEI": the app decides who the learner is. No tool takes a learner ID from the model, so a prompt can't make it read someone else's data.
    5. 



Task 2: Run it and watch the calls


    
  
  1. Run it with the three built-in questions:

    $ python l2_tools.py
    
    Real output with qwen2.5:7b (yours will differ)

    Q: Which beginner courses cost less than $300?
  -> search_courses({'level': 'beginner', 'max_price_usd': 300, 'text': ''}) = [{"id": "C101", "title": "Python Foundations", "level": "beginner", "price_usd": 290}, {"i

  -> check_enrolment_status({'enrolment_id': 'TC-RAG'}) = {"error": "not one of the signed-in learner's enrolments; call get_my_profile to see them"

    2. 
  
  2. For each question, check the arrows (->): which function did the model choose, with which arguments, and did the final answer use the result?
    3. 
  
  3. Look closely at the RAG question in the real run: the model guessed an ID (TC-RAG), got a clear error, said "Let's get your profile"… and stopped without calling it. Announcing a step instead of taking it is a common habit of smaller models. Run it again: the result varies from run to run, which is why real systems measure tool use over many runs (Module 09). A larger model, or the handbook's Azure deployment, does this reliably.
    4. 
  
  4. Try your own: python l2_tools.py "Is there an advanced course under $1,300?" and python l2_tools.py "Show me Diego's enrolments." (the second should fail safely: only Mei is signed in).
    5. 



Checkpoint
The model calls functions for the catalogue and ticket questions, your code runs them, and the answers use the results. You can explain what went wrong in any question where it didn't.

Troubleshooting



  

    
SymptomFix

    
      
AttributeError: ... has no attribute 'parse'Your openai package is old: pip install -U openai.

      
The model answers without calling any functionSmall models sometimes do. Ask more specifically ("check my enrolment status"), or try qwen2.5:7b as CHAT_MODEL if you have 16 GB of RAM.

      
does not support toolsThe chosen model has no tool support in Ollama. Use llama3.2 or qwen2.5.

      
model "nomic-embed-text" not foundollama pull nomic-embed-text.

      
Search results look random after changing dataDelete data/search_index.json to rebuild the index.

    
  





Review and cleanup


    
  
  • A schema makes output shape reliable; validation and common sense check the values.
    • 
  
  • Function calling is a loop you control: the model asks, your code decides and runs, the result goes back.
    • 
  
  • Identity comes from the app, never from the model's arguments.
    • 
  
  • Embeddings turn meaning into vectors; hybrid search combines meaning with exact keywords.
    • 



Cleanup: keep data/search_index.json; Lab 3 builds a similar index for its knowledge assistant.
