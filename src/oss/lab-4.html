Before you start

Open your oss-genai-labs folder and activate its virtual environment as shown in Lab 0. This lab uses only the Python standard library; the quality script does not read .env, call a model or send data anywhere. The complete lab download includes its scripts in the repository's code/oss-labs/ folder.

Exercise 2 · Evaluate a classifier with a release gate


Module 09 starts with an evaluation set and measurable outcomes. The five examples in CASES are intentionally tiny and fixed so you can verify the arithmetic.


Task 1: Inspect the metrics


    
  
  1. Find the expected and predicted labels in CASES. The positive label is fraud; a false negative is a fraud example predicted as another category.
    2. 
  
  2. Read classification_metrics() and failed_thresholds(). Precision answers how many fraud predictions were correct; recall answers how many actual fraud examples were found.
    3. 
  
  3. Compare the output with the data: accuracy is 3/5 (0.6), precision is 2/3 (about 0.667), and recall is 2/2 (1.0). The gate blocks because accuracy and precision are below their configured minimums.
    4. 
  
  4. Change the two incorrect predictions, rerun the script and tests, then restore the original values. Observe how the metrics change. Do not treat a perfect score on five examples as evidence of production quality.
    5. 



Checkpoint
You can distinguish accuracy, precision and recall, identify the two failed thresholds, and explain why a small evaluation set is not enough for release approval.



Exercise 3 · Test limited privacy and injection checks


The final functions demonstrate two narrow pattern checks. They do not replace data-loss prevention, content moderation or authorization.


Task 1: Probe what the patterns recognize


    
  
  1. Run python l4_quality.py again. The labeled account-number example is replaced with [REDACTED]; the injection example returns two indicator names.
    2. 
  
  2. Change the message to a number without a label, such as 1234 5678 9012. The masker will leave it unchanged. That is an intentional boundary of this teaching regex, not proof the text has no personal information.
    3. 
  
  3. Try an instruction not covered by the patterns, such as disregard your rules. An empty indicator list means only that these patterns did not match; it does not mean the input is safe.
    4. 
  
  4. Run python -m unittest test_l4_quality and check the tests for both a supported labeled identifier and an unlabeled number.
    5. 



Checkpoint
You can state exactly which patterns matched and why their absence cannot be used as a security decision.

Your metrics differ from the sampleCheck whether you edited CASES. The shown values correspond to the original five expected/predicted pairs.

Review and cleanup


    
  
  • A trace ID helps correlate stages; production telemetry also needs instrumentation, access controls, retention and data minimization.
    • 
  
  • Evaluation thresholds are explicit, but the dataset must represent real usage and relevant failure modes.
    • 
  
  • A regex can mask a limited labeled pattern; it cannot detect every sensitive value or injection attempt.
    • 
  
  • Human review, policy enforcement and provider security features remain separate controls.
    • 



Cleanup: remove only the synthetic session database with python -c "from pathlib import Path; Path('data/l4_sessions.sqlite3').unlink(missing_ok=True)". Keep the scripts and tests for review.
