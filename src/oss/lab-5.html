Before you start

Open the same oss-genai-labs project folder used in earlier labs and activate its virtual environment. This script uses the Python standard library only. It makes no model calls, provisions no Azure resources and does not deploy an application.

Exercise 2 · Create a versioned cache key


The hash includes the model, prompt version and messages, so changing the prompt version changes the key even when the user message stays the same.


Task 1: Verify key stability and limits


    
  
  1. Read cache_key() and the corresponding test in test_l5_release.py.
    2. 
  
  2. Run the tests:

    $ python -m unittest test_l5_release
    3. 
  
  3. Change the prompt version from assist-v1 to assist-v2 and compare the key. Restore the original value after the experiment.
    4. 
  
  4. Notice what is deliberately absent: this script does not store or return cached responses, set a TTL, isolate users, or check whether a result is still authorized. Do not build a shared cache for private banking responses from this hash alone.
    5. 



Checkpoint
You can explain why a cache key needs relevant model and prompt versions, and why a deterministic hash is not a complete cache design.



Exercise 3 · Run a release and health preflight


Module 12 covers release controls and operations. This script checks required fields, digest-string shape and three supplied health thresholds; it does not verify artifacts or observe a running service.


Task 1: Exercise the preflight


    
  
  1. Inspect validate_manifest(), health_failures() and HEALTH_LIMITS. The digest examples use repeated letters to demonstrate syntax only.
    2. 
  
  2. Run the tests. Then change p95_latency_ms in the script to 1600 and rerun it; the local preflight should block on that metric. Restore the sample value afterward.
    3. 
  
  3. Remove the rollback digest from manifest or replace it with an invalid string, then rerun the program. Check that the manifest validation reports a failure. Restore the original sample.
    4. 
  
  4. Discuss what a real release needs in addition: verified artifact provenance, deployment permissions, secrets management, live health telemetry, rollback execution, incident ownership and tested recovery procedures.
    5. 



Checkpoint
You can trigger a failed health check and explain why a passing local preflight does not certify or deploy a production release.



Troubleshooting



  

    
SymptomFix

    
      
The displayed cost is not $9.00Check the token counts and the illustrative input/output rates in main(); the calculation uses Decimal arithmetic.

      
The cache key changed unexpectedlyCompare the model, prompt version and message data. Any of them changes the canonical JSON and therefore the hash.

      
The health check blocksCompare each observed value to its matching limit. Restore the original sample only after you have recorded which check failed.

      
The manifest passes with a fake digestExpected: the check validates only the string's format. It does not retrieve the image or prove its integrity or origin.

    
  





Review and cleanup


    
  
  • Cost projections depend on token usage and the current, applicable rate card; the sample prices are fictional.
    • 
  
  • Routing decisions need explicit quality, privacy, latency and availability requirements, not only a task label.
    • 
  
  • Cache isolation, retention, invalidation and authorization are part of the design, not properties supplied by a hash.
    • 
  
  • A release preflight is one check in a delivery process; it does not deploy, monitor or certify the service.
    • 



Cleanup: these programs create no persistent cache or release files. Keep the scripts and tests so you can rerun the checks.
