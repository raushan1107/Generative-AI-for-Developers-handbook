Before you start: check your project folder

Every program in this lab imports its settings from two files in your oss-genai-labs folder. If you did Lab 0 they're already there; check them anyway, because a missing or wrong .env is the most common reason a lab program fails.

  1. Open the oss-genai-labs folder in VS Code and activate the virtual environment: .venv\Scripts\Activate.ps1 (Windows) or source .venv/bin/activate (macOS/Linux). The prompt starts with (.venv).
  2. Make sure Ollama is running (open http://localhost:11434: it says Ollama is running).
  3. Check that .env exists (with the leading dot) and contains the lines below. The default is a free local model with Ollama; there is no key to get: LLM_API_KEY=ollama is a placeholder.
    .env (default: local Ollama)

  4. Check that client.py exists. Every program imports get_client and the model names from it:
    
    client.py
    5. 
  
  5. Run python lab0_check.py. Every line should say [ OK ].

Exercise 2 · An agent that asks before it acts


Module 07's hands-on exercise: an agent loop that reads a request, requests card tools, receives their results and asks a person before a freeze takes effect.



Task 1: Choose the agent model


    
  
  1. Set AGENT_MODEL in .env to a model available in your Ollama setup. A tool-capable model such as qwen2.5:7b may be more reliable, but tool selection and wording vary by model and version.

  2. Find the five steps of the agent flow in run(): (1) understand the task (the model reads the request), (2) select a tool, (3) execute it, (4) evaluate the result (it goes back to the model, which decides the next step), (5) return a final response.
    3. 
  
  3. Find the safeguards: CUSTOMER and card data are hard-coded demo values; NEEDS_APPROVAL pauses freeze_card and shows a preview from the current in-memory card record; max_steps bounds the loop; AUDIT_LOG records successful changes only in memory.

  1. Test the function boundary without a model call: python -c "from l3_agent import AUDIT_LOG, freeze_card; print(freeze_card('9999')); print(AUDIT_LOG)". It should return an error and an empty log.
    2. 
  
  2. Try a read-only request: python l3_agent.py "What cards do I have?". It should not request approval for a read. Model behavior can vary, so inspect the calls.
    3. 



Checkpoint

Troubleshooting



  

    
SymptomFix

    
      
The knowledge assistant says "couldn't find" for everythingConfirm the embedding model is running and the source files exist. The 0.55 floor is a demo value; inspect scores and recalibrate for your embedding model and data. Delete data/kb_index.json after changing the embedding model.

      
The answer has no citations or cites the wrong factOpen the retrieved source and compare it with each claim. The code filters invalid source numbers but does not check entailment; try a different model or improve the chunking/prompt, then test again.

      
The public demo returns a staff factCheck the audience labels and retrieval filter in retrieve(). Remember that this local script's --staff flag is not secure authorization.

      
The agent does not call toolsConfirm the configured AGENT_MODEL is available and supports tools through your Ollama version. Try another supported model and inspect its calls; the model is not guaranteed to follow the requested workflow.

      
The approval preview says "?" or unknownCheck that the requested last four digits came from my_cards() and that the tool arguments match the expected card_last4 field.

      
A frozen card is active again after rerunningExpected: card state is in memory and resets when the process exits. This example does not persist customer state.

    
  





Review and cleanup


    
  
  • RAG retrieves source text before generation; inspect the source and verify every factual claim.
    • 
  
  • Apply access controls before retrieval, but do not mistake a local command-line flag for authentication.
    • 
  
  • An agent is a bounded loop that requests tools; application code validates and executes them.
    • 
  
  • Approval, durable authorization, persistence and auditability require production controls beyond this in-memory demo.
    • 



Cleanup: delete data/kb_index.json if you want to rebuild it; the index is recreated on the next run. To remove an Ollama model, use ollama rm MODEL_NAME.
