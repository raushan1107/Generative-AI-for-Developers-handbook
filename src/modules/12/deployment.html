Learn

Release a versioned system, not an untracked prompt change.

Definition

A release manifest records the application artifact, model deployment, prompt version, evaluation data and rollback target. A staged rollout limits exposure while health and quality are monitored. A rollback returns to a known prior artifact or disables the affected capability; it must be tested before an incident.

In plain words

Know exactly what you shipped, what it was tested against, and how to get back to the last safe version.

Imagine this

A bank changes a form used across branches. It records the approved version, pilots it with a small group, watches for errors and keeps the previous form ready.

In the real world

AI workloads have nondeterministic behavior, so a release pipeline should gate both software changes and model/prompt changes with relevant tests and evaluations. Keep credentials in an approved secret store or managed identity flow; never bake them into an image or a prompt.

In finance

Before rolling out a new fraud-triage prompt, compare it with the approved evaluation set, record the prompt and model versions and begin with a controlled deployment. Keep a tested path to disable automated drafting or return to the last reviewed version.

Traditional developer view

"The container tag identifies the release."

GenAI developer view

"The behavior also depends on model deployment, prompts, tools, policy data, evaluation set and safety configuration."

Common trap

Thinking that a syntactically valid image digest proves the image exists, was signed or passed policy. The M12 helper checks manifest shape only; the deployment pipeline must verify registry provenance and authorization.

Interview cue

"I version the application, model, prompts and evaluation set together, preflight them in CI, deploy gradually, monitor quality and keep a tested rollback or disable path."

Drill 12.1

Validate release artifacts

~15 minPython · pytestoffline

Goal: fail preflight when a release record is missing a model, prompt, evaluation dataset or rollback digest.

  1. Run

    The manifest check

    $ python -m pytest -q tests/test_release_checks.py
    Expected result
    4 passed
  2. Verify
    • Missing release artifacts produce named failures.
    • Digest format is checked, but registry existence and signature are not.
    • Secrets are not placed in the manifest.


3
Check
Release controls.
1. Why record the evaluation dataset version alongside the prompt?
So the team can reproduce the comparison and know which expected behavior supported the release decision.
2. Does passing the manifest check mean the release is safe to deploy?
No. It checks required fields and digest shape, not artifact provenance, evaluation quality, security approval or actual rollback behavior.


Takeaway
Make releases reproducible and reversible. A preflight helper is one gate in a pipeline, not the pipeline itself.
