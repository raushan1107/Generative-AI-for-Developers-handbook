Learn

Know what is being reused and what freshness it promises.

Definition

Model routing selects an approved model or deployment for a task. Prompt caching reuses provider-side processing for eligible repeated prompt prefixes; it is not the same as returning a previous answer. An application response cache reuses a stored result and needs a safe key, freshness rules and access boundaries. Batch processing runs many requests asynchronously when the use case can wait.

In plain words

Routing chooses the worker. Prompt caching may save repeated input work. A response cache returns a previous answer. Batch processing lets you submit a group and collect results later.

Imagine this

A bank teller may reuse the same printed policy reference, but must not reuse one customer's account answer for another customer. A nightly report can wait in a queue; a fraud alert cannot.

In the real world

Azure OpenAI prompt caching applies to supported models and repeated prompt prefixes; it can reduce input processing cost and latency, but does not change response meaning or guarantee a hit. Batch processing is asynchronous and has its own supported models and service limits. Check the current prompt caching guide and batch guide.

In finance

A bank may cache a stable public help article lookup, but should not reuse a prior customer's transaction answer. A daily evaluation run can be batched; an incoming lost-card request needs an interactive path.

Traditional developer view

"Caching is a transparent performance optimization."

GenAI developer view

"Cached data can be stale or cross a privacy boundary; define the exact key, tenant scope, TTL and invalidation rule."

Common trap

Assuming a model's automatic prompt cache stores and replays the answer. It reuses eligible prompt processing; response caching is a separate application behavior with separate correctness and privacy risks.

Interview cue

"I select routes based on measured task quality, check provider cache support and cache-hit telemetry, avoid caching customer-specific responses without strict isolation, and use batch only where latency requirements allow."

3
Check
Caching and batch choices.
1. Can an app response cache return one customer's balance to another?
It must never do so. Include tenant/user scope in authorization and cache design, or do not cache personal responses.
2. Which work is a better batch candidate: a nightly evaluation or a lost-card report?
The nightly evaluation can usually wait. A lost-card report is time-sensitive and needs an interactive, monitored path.


Takeaway
Distinguish model prompt caching, application response caching and batch processing. Each has different freshness, privacy and latency rules.
