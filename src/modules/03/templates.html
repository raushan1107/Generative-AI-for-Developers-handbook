Learn

Mail-merge for prompts.

Definition

A prompt template is a reusable prompt with named placeholders (for example $ticket or {customer_name}) that application code fills in at runtime, keeping the fixed instructions separate from the variable data.

In plain words

Like a mail-merge letter: the instructions are written once, the blanks are filled in by code. Prompts stay consistent, reviewable and in one place instead of scattered across f-strings in twenty files.

Treat templates like code

  • Keep them in one place: a prompts.py module or a prompts/ folder, not inline in business logic.
  • Version them: summarise_ticket@v2. Log the version with every answer so you can trace a bad answer to a prompt change (Module 12).
  • Review them in pull requests. A one-word change can shift behaviour.
  • Test them against fixed inputs before shipping (Module 09 builds the full suite).
In the real world
In finance

In a bank, a customer-facing prompt template is reviewed much like a template letter: product, legal and compliance check the wording, the approved version is recorded, and changes go through the same change-management process as code. Mandatory text (a fraud warning, a "this isn't financial advice" line, a complaints-process sentence) is often kept outside the model, added by code after generation, so it can never be paraphrased away. Logging the template version with every answer is what lets the bank show a regulator exactly which approved wording a customer received.

Mature teams manage prompts as assets: stored in the repository or a prompt registry, versioned, reviewed, A/B tested and rolled back like any release. Observability tools record which prompt version produced each response, which is how teams answer "why did the bot say that last Tuesday?".

Interview cue

"Prompts live in versioned templates with placeholders, reviewed in PRs and tested against fixed inputs, and every response is logged with its prompt version."

Check
Templates.



  
1. Why does Template.substitute beat an f-string for prompts?
It fails loudly on a missing value instead of quietly building a broken prompt, and the template lives in one reviewable place.

  
2. A customer complains about an answer from last week. What lets you find the cause?
Logging the prompt version (plus model version and inputs) with every response.




Takeaway
Prompts are code: one place, versioned, reviewed and tested.
