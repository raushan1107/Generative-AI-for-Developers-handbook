Learn

The senior agent sitting beside the new joiner.

Definition

Few-shot prompting includes a small number of input–output examples in the prompt so the model can infer the desired mapping, labels and format by analogy, without changing its weights (in-context learning).

Imagine this

On a new joiner's first day at TrainCrest support, a senior agent doesn't read out a 20-page labelling manual. They sit beside them: "This one asks for a refund but mentions the start date: we tag billing. This one wants more lab days: lab_access, not scheduling." A few examples and the new joiner gets it. Few-shot is that senior agent.

Getting examples right

  • Two to five examples usually suffice; more costs tokens on every call.
  • Cover the tricky cases, not just the easy ones. Examples should sit on the boundaries you care about.
  • Vary and balance them. Four billing examples and one other nudge the model towards billing.
  • Keep the format identical. The model copies format faithfully, mistakes included.
  • Use user/assistant pairs or a clearly delimited block in the system message; both work.
In the real world

Few-shot is the workhorse of production classification and extraction pipelines: routing tickets, tagging reviews, normalising product attributes. Some teams go a step further and retrieve the most similar labelled examples for each new input (dynamic few-shot), combining this topic with the embeddings of Module 05.

Common trap

Using real customer tickets as examples, complete with names, emails and phone numbers. That's personal data sent on every request and stored in your prompt files. Write synthetic examples, or anonymise real ones first.

Interview cue

"Zero-shot first; if outputs are inconsistent or the task has company-specific conventions, add a few diverse, balanced examples that cover the edge cases. It's in-context learning: no fine-tuning needed."

3

Check

Examples.

1. Zero-shot labels refund requests that mention dates as "scheduling". Cheapest fix?

Few-shot examples that include such a request labelled "billing", in a balanced set. Fine-tuning would be overkill for a rule that examples teach instantly.

2. What's the cost of few-shot, and how do you decide if it's worth it?

More input tokens on every call. Compare the accuracy gain on your test set against the extra cost at your volume.

Takeaway

When the model keeps missing your conventions, show it a few balanced examples, and measure the gain.
