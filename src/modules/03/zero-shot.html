Learn

Always try the simplest prompt first, and measure it.

Definition

Zero-shot prompting asks the model to perform a task from instructions alone, without worked examples, relying on what it learned in pre-training and instruction tuning.

In plain words

Describe the task and let the model do it, with no demonstrations. Try this first; add examples only when it isn't consistent enough.

Classify the RR Finance Bank customer message into exactly one category: card, dispute, fraud,
fees, transfers, loans, account, other. Reply with the category only, in lowercase.

Message: "I was charged twice for the same hotel night."
WhatInstructions only, no examples.
WhyShortest, cheapest prompt; easiest to maintain.
WhenCommon tasks with obvious categories and formats. Your default first attempt.
Where zero-shot struggles

Company-specific conventions ("is a payment the customer doesn't recognise a dispute or fraud?"), unusual formats, slang and mixed languages, and borderline cases. In all of these the model has to guess your convention. Examples fix that (next topic).

In the real world
In finance

Banks rarely start with real customer messages: privacy rules make them hard to use for development. Teams build a synthetic, labelled test set first (exactly like Drill 03.4), get the labels reviewed by experienced agents, and only later add carefully anonymised real cases. They also weight the score by risk: a missed fraud report counts far more than a branch-hours question labelled wrong, so "accuracy 83%" is reported alongside "fraud recall", the share of real fraud messages that were caught.

Before any prompt work, good teams assemble a test set: real (anonymised) or synthetic inputs with the expected answers. They measure the simple zero-shot prompt first to get a baseline, then every change is a measured improvement or it's reverted. Generating synthetic test data with an LLM is now standard practice, with human review of the labels.

Interview cue

"I start zero-shot to get a baseline on a labelled test set, then add examples or structure only if the numbers say it's needed."

3
Check
Baselines.



  
1. Why measure a zero-shot baseline before improving the prompt?
Without a number you can't tell whether a change helped, hurt or did nothing, and you'd keep extra prompt (and cost) that adds no value.

  
2. Your AI-generated test set passes the checker. Is it trustworthy?
Only partly. The checker verifies shape (keys, labels, counts, leaks). A human must still review whether the labels are correct.




Takeaway
Zero-shot first, measured. Its mistakes tell you exactly what to teach next.
