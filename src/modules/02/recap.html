Checklist for any LLM integration

  • The model is called only from the backend; credentials never reach the client (Drill 02.1).
  • Keys live in configuration or a vault, or better, there are no keys (Drill 02.3).
  • I check finish_reason and log request ID, model, usage and latency (Drill 02.4).
  • The app owns conversation history and trims it deliberately (Drills 02.5, 02.6).
  • Parameters are set per feature, and I know which ones my model supports (Drill 02.7).
  • Chat responses stream; I measure time to first token (Drills 02.8, 02.9).
  • Transient errors are retried with backoff and jitter; others fail clearly and kindly (Drills 02.10–02.13).
  • Every call logs tokens and cost, and I can project the monthly bill (Drills 02.14, 02.15).

Self-check

1. A front-end developer puts the Azure OpenAI key in a Vite environment variable "so it's not in the code". What's wrong, and what's the fix?

Build tools inline it into the public JavaScript bundle, so it's public. Call the model from a backend (or use managed identity there) and regenerate the key.

2. Traincrest Assist returns HTTP 200 but the answer stops mid-sentence. What happened, and how should the code react?

finish_reason is length. Don't present it as complete; raise the cap, ask for brevity, or lower reasoning effort. Milestone 2 records it in the done event and the log, so you can spot it.

3. Which errors should ChatService retry, and where does that retry happen?

429, 5xx, timeouts and connection errors. In Milestone 2 the SDK retries them (max_retries=3); ChatService only maps what's left after retries to friendly messages.

4. Why does Milestone 2 send its own delta/done/error events instead of forwarding Azure's raw chunks?

So the front end doesn't depend on one provider's format, and the backend can add its own data (cost, prompt version) and switch models freely.

5. A nightly summarisation job slows down daytime chat with 429s. What's the right fix?

Run it through a queue or batch API at a steady rate, ideally on separate capacity, instead of competing with interactive traffic.

6. Monthly cost doubled after a prompt change. What's the first number you check?

Input tokens per turn in the logs. A longer system prompt is paid on every turn and multiplied by history.
