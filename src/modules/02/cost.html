A taxi meter that runs on words.

Definition

For a token-priced API, a useful estimate is input-token usage × input rate + output-token usage × output rate. Exact billing varies: providers may price cached input, reasoning, images or other features differently, and not every API uses this pricing model. Check the provider's current usage fields and price list.

In plain words

It's a taxi meter whose rules depend on the provider. On many token-priced models, input and output have different rates, and some features use separate rates. The good news: prompt size, output length and model choice often matter.

Do the maths once (illustrative prices)

For illustration only, say a model costs $0.40 per million input tokens and $1.60 per million output tokens; these are not current prices for a named model. RR Finance Bank's assistant has 40,000 conversations a month, averaging 4 turns: 160,000 turns.

Check the current Azure OpenAI price list or the corresponding page for your provider; the arithmetic below is a teaching example only.

The cost levers, easiest first

  1. Measure. Log usage per call with a feature name. You can't optimise what you can't see.
  2. Choose the smallest model that passes your quality bar (Drill 01.11, Module 11).
  3. Trim the prompt: remove repeated instructions, send only relevant documents, trim history.
  4. Cap the output with the token-limit parameter your API supports (for example, max_completion_tokens or max_output_tokens) and instructions like "under 80 words".
  5. Where supported, tune reasoning effort for simple tasks; some providers count hidden reasoning tokens as output usage.
  6. Where supported, cache and batch repeated and non-urgent work (Module 11).
  7. Set budgets and alerts so surprises arrive by email, not on the invoice.
In the real world
In finance

Banks budget AI features the way they budget anything else: a business case with a cost per unit. A useful unit for a contact centre is cost per resolved conversation, compared with the fully loaded cost of a human-handled one (often several dollars). At 160,000 turns a month, the difference between $160 and $5,440 decides whether finance approves the project. Expect two more lines in the business case: the cost of the evaluation and monitoring runs you'll add in Modules 09 and 12, and a chargeback so each business line pays for its own usage.

Teams running AI features at scale track cost per feature and per user and set quotas so one heavy user can't run up the bill. Depending on the provider, they may use prompt caching for repeated prefixes, batch APIs for overnight work, or committed capacity for steady high volume. A long, repeated system prompt can be a major cost driver.

Common trap

Testing cost with a three-message demo and multiplying. Real conversations are longer, history is resent every turn, and a few power users send ten times the average. Project from real logged usage after a pilot.

Interview cue

"Cost is input × input price + output × output price, times volume. My biggest levers are model choice, prompt size, history trimming and output caps, and I log usage per feature."

1. The projected bill doubled after a prompt change. Where do you look first?
The usage logs: prompt_tokens per turn. A longer system prompt is paid on every turn, and history multiplies it.

  
2. Name three cost levers that don't require changing the model.
Any three of: trim the prompt, trim history, cap output, lower reasoning effort, cache repeated work, batch non-urgent work.




Takeaway
Log usage on every call. The bill is decided by prompt size, output length and model choice, all of which you control.
