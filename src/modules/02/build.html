  5. Ask AI
    Have your assistant build the chat page to your contract
    
        
    Create web/index.html: a single-file chat page (HTML, CSS and vanilla JavaScript, no frameworks,
no external files) for "Traincrest Assist". Contract with the backend in #app/main.py:
- On load, create sessionId = crypto.randomUUID().
- On submit, POST /api/chat with JSON {session_id, message}. The response is server-sent events:
  lines "data: {json}" separated by a blank line. Read it with fetch + response.body.getReader()
  + TextDecoder, buffering until "\n\n".
- Event types: {"type":"delta","text"} append text to the current assistant bubble;
  {"type":"replace","text"} replace the bubble's text; {"type":"error","message"} show the message
  styled as an error; {"type":"done","ttft_s","total_s","tokens_in","tokens_out"} show a small
  grey line under the bubble with those numbers.
- If fetch fails or the status isn't OK, show a friendly error in the bubble.
- A "New chat" button POSTs /api/reset {session_id}, makes a new sessionId and clears the log.
- Disable Send while a reply is streaming. Use textContent, never innerHTML, for message text.
Dark, clean design; user bubbles on the right, assistant on the left.
    
        
    Why this prompt works: it's a contract, not a wish. It names the exact endpoint, payload, wire format and every event type (including replace, which Milestone 3 needs), says how to parse a streamed body, and includes a security rule: textContent instead of innerHTML, so model output can never inject HTML or scripts into the page.

    Run it and try to break it
    
        
    $ uvicorn app.main:app --reload
    
        
      
          
    • Streaming: open http://127.0.0.1:8000, ask "How should I prepare for my first cloud certification?". Words appear within about a second.
      • 
          
    • Memory: in the browser at http://127.0.0.1:8000, send "Hi, I'm Mei, enrolled in AZ-305." then "Which course am I in, and what's my name?". The answer mentions Mei and AZ-305. If it doesn't, check your web/index.html: it must create sessionId once when the page loads and send the same value with every message (compare with the reference code above). A page that makes a new ID per message has no memory.
      • 
          
    • New chat: click it, ask "What's my name?": forgotten, as designed. It works because the button calls /api/reset and then creates a new sessionId.
      • 
          
    • Friendly errors: in .env set a model that doesn't exist (default local model: OLLAMA_MODEL=nope; Azure: AZURE_OPENAI_DEPLOYMENT=nope), restart uvicorn, send a message: a calm "temporarily unavailable" message, no stack trace. Restore the setting and restart.
      • 
          
    • Model unreachable: make the model server unreachable and send a message: "I couldn't reach the AI service". With the default local model, quit Ollama (Windows: right-click its tray icon › Quit; macOS: menu-bar icon › Quit; Linux: sudo systemctl stop ollama); turning off Wi-Fi changes nothing, because the model runs on your own computer. With Azure, disconnect Wi-Fi instead. Start Ollama or reconnect: the next message works.
      • 
          
    • Logging: open assist.log: one JSON line per turn with TTFT, tokens and cost_usd; errors logged with a code (config, unreachable), never your key. With a local model, cost_usd is what the same tokens would cost at the prices in .env; you pay nothing.
      • 
          
    • API docs: open http://127.0.0.1:8000/docs, try POST /api/chat with "message": "": 422, and the model is never called.
      • 
          
    • CLI: python cli.py streams the same way.
