Learn

Look it up, then answer.

Definition

Retrieval-augmented generation (RAG) is a pattern in which an application retrieves relevant information from an external knowledge source at query time, adds it to the prompt, and has the model generate an answer grounded in that information. The model's weights don't change; only its input does.

In plain words

Before the model answers, your code searches your documents for the few passages that matter, pastes them into the prompt, and says "answer from these, and say which one you used".

Imagine this

A closed-book exam tests what you remember; a confident student who half-remembers writes a fluent wrong answer. An open-book exam lets you look up the right page first. RAG turns every question into an open-book exam, and your code chooses which pages the model may open.

Why teams use RAG

Problem without RAGWhat RAG does about it
Knowledge cut-off: the model stopped learning months agoRetrieves today's version of the document
Private knowledge: your policies and wiki were never in its training dataBrings them into the prompt for this one question, without sending them to anyone's training pipeline
Change: prices and rules change monthlyEdit the document and re-index the changed chunks; no model work
Hallucination: fluent guesses about specificsGrounds the answer in real text and allows "not found" as a valid answer
Trust: "where does it say that?"Citations link each fact to its source, so people and code can check it
Access control: staff and learners may see different thingsRetrieval filters by who is asking, so the model only sees what that person may see
Cost: pasting the whole handbook into every promptSends only the 3 to 5 passages that matter

RAG, long prompts, fine-tuning or tools?

ApproachGood forNot for
RAGKnowledge in documents: policies, manuals, wikis, FAQs, contractsLive records (a learner's enrolment) or calculations
Put everything in the promptSmall, stable knowledge (Milestone 3's five policy lines)Hundreds of pages; it's slow, costly, and details get missed in long contexts
Tools / function calling (Module 04)Live data and actions: enrolment status, refund quotes, ticketsReading and summarising long text
Fine-tuningStyle, format, tone, a narrow task done many timesTeaching facts that change; it's expensive to update and can't cite sources

Real assistants combine them. Traincrest Assist will use RAG for "what is the policy?", tools for "what about my enrolment?" and code for "how much exactly?".

In the real world

Most enterprise AI assistants are RAG systems. Office-suite copilots answer from your files, mail and chats and show references to them. Customer-service bots answer from a company's help centre and hand over to a person when nothing matches. Internal "ask HR" or "ask IT" assistants search policy sites. On Azure, the usual building blocks are Azure AI Search for retrieval and an Azure OpenAI model for generation. A Foundry agent can also use an Azure AI Search index as its knowledge source. You'll build the same pipeline by hand first, so you know what those services do for you.

Traditional developer view

"The model is the brain. If it doesn't know something, we need a smarter model or to train it."

GenAI developer view

"The model is a reader and writer. Knowledge lives in documents I control. My job is to put the right passages in front of it and check that it used them."

Common trap

Believing RAG ends hallucination. It reduces it a lot, but the model can still misread a passage, mix two sources, add a "helpful" detail of its own, or answer from the wrong chunk if retrieval missed. In Drill 06.9 a small model cites a real source and still invents "1-2 billing cycles". RAG needs checks (topic 9) and evaluation (Module 09).

Interview cue

"RAG retrieves relevant passages at query time and grounds the model's answer in them. I'd choose it over fine-tuning for factual, changing or private knowledge, because updates are just re-indexing and answers can cite their sources. Fine-tuning is for behaviour and style; tools are for live data and actions."

Check
What RAG is for.



  
1. TrainCrest changes its lab extension price from $49 to $59. What do you update in a RAG system, and what in a fine-tuned one?
RAG: edit the help article and re-index its changed chunk; the next answer uses $59. Fine-tuned: prepare new training data, run another fine-tuning job, evaluate and redeploy, and the model may still remember $49.

  
2. "What is the status of my voucher?" Should that be answered with RAG?
No. It's a live record for one learner, so it needs a tool that calls the voucher system (Module 04). RAG explains the voucher policy; tools fetch this learner's voucher.

  
3. Name two things RAG gives you that a long system prompt containing all policies doesn't.
Any two of: scale beyond what fits in a prompt; lower cost per message; per-user access control by filtering retrieval; citations to specific sections; updates without editing and redeploying the prompt.




Takeaway
RAG makes every question open book: retrieve the right passages, answer only from them, and allow "not found". Use it for document knowledge; use tools for live data.
