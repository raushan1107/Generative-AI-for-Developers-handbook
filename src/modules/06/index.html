The mental map: index once, retrieve every time

Module 05 built the search half. RAG adds the other half: turning what search finds into a grounded answer. Every RAG system, from a help-centre bot to an enterprise "ask our documents" tool, is these two pipelines.

Takeaway

RAG is an open-book exam: find the right pages, hand them to the model, and insist the answer comes from them. Most RAG quality problems are retrieval problems, not model problems.

Why this module matters

Traincrest Assist's policy lives in its system prompt: five lines, typed by hand in Milestone 3. That doesn't scale. The help centre has ten articles and forty-seven sections; the support team's internal wiki has more; both change every month. Put all of it in every prompt and you pay for thousands of tokens per message and the model still misses details. Leave it out and the model guesses, confidently. In Drill 06.1 a model asked about error LAB-503 without the help centre explains it as a "malfunction in instrument communication".

The hands-on project of this module is a company knowledge assistant: it answers from TrainCrest's own documents, public and internal, says when they don't cover a question, and shows where each fact came from.

Imagine this

A new call-centre agent doesn't memorise the policy binder. When a caller asks something, they look up the right page, read it, answer from it, and say "that's in section 4.2" if challenged. A good RAG system works the same way: it looks things up every time, and it can show its page numbers.

Traditional developer view

"If the app needs to know something, put it in the database or hard-code it."

GenAI developer view

"Knowledge lives in documents. I keep them indexed, retrieve the few passages that matter for each question, make the model answer only from those, and verify the citations before anyone reads the answer."

  • Azure: the chat and embed deployments from Modules 02 and 05. Nothing new to create.

  • New data in genai-labs/data/internal/: four fictional internal documents for TrainCrest's support staff, in four formats (a markdown playbook, an HTML wiki export, a plain-text runbook and a CSV FAQ), plus a duplicate file to catch.
  • New helpers in genai-labs/: ingest.py, rag_chunks.py, kb_index.py, rag_prompt.py, citations.py, and rag.py, which puts them together. Each drill builds or uses one of them, with tests.
