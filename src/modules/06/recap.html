RAG checklist

  • You can say when to use RAG, tools, a long prompt or fine-tuning (Drill 06.1).
  • You can name the eight components and debug from retrieval first (Drill 06.2).
  • Every document is ingested with clean text, a source, an audience and a hash; duplicates are reported (Drill 06.3).
  • Chunks keep every word (introductions included), carry a title header and an id, and were chosen by recall and tokens (Drill 06.4).
  • The index embeds only changed chunks and records its embedding model and chunker version (Drill 06.5).
  • Retrieval filters by permission inside the search and uses a relevance floor calibrated for your model (Drill 06.6).
  • Follow-up questions are rewritten into standalone queries before searching (Drill 06.7).
  • The prompt has rules, numbered and tagged sources within a budget, the question last, and a NOT_FOUND exit (Drill 06.8).
  • The pipeline skips the model when nothing is relevant and handles NOT_FOUND in code (Drill 06.9).
  • Citations are checked in code before anyone reads them, and only cited sources are shown (Drill 06.10).

Self-check

1. A colleague wants to fine-tune a model on the help centre "so it knows our policies". What do you say?

Use RAG instead: policies change, fine-tuning is slow and costly to update, a fine-tuned model can't cite where a fact came from, and it still guesses on details. Fine-tuning is for style and behaviour; RAG for changing factual knowledge.

2. An answer about voucher validity is wrong. List the order in which you'd investigate.

Retrieved chunks first (was the right section there?), then chunking (is the fact in one chunk with its context?), ingestion (is the article current and clean?), the prompt (rules, budget), and only then the model.

3. Why does the knowledge index record its chunker version as well as its embedding model?

A new chunker produces different chunk ids and texts. Loading an old index with new code would break citations and incremental updates silently; recording the version makes the mismatch an error and forces a rebuild.

4. "Can I bring my dog to class?" scored higher than a real question. What protects the user?

Layers: the floor drops most off-topic questions; for the rest, the prompt requires answers only from sources and a NOT_FOUND sentinel; citation checks and, later, evaluation catch what slips through. No single layer is enough.

5. A model cites [5] when only four sources were sent. What does Traincrest Assist do?

check_citations removes the [5] marker, the chat sends a replace event with the cleaned text, logs an unknown_citations warning, and lists only the real cited sources.

6. Why is the answer to "how much would I get back?" a combination of RAG and a tool?

RAG explains the policy with a citation (14+ days 100%, 7 to 13 days 50%); the quote_refund tool applies it to this learner's enrolment, dates and price. Policy from documents, numbers from code.
