Learn

Garbage in, confident garbage out.

Definition

Document ingestion is the first stage of a RAG index: discovering source documents, extracting their text with a loader per format, cleaning and normalising it, attaching metadata (source, title, audience, date), and detecting duplicates and changes so the rest of the pipeline only processes what's new.

In plain words

Read every file, keep the words that matter, throw away the menus and footers, remember where each document came from and who may see it, and don't index the same thing twice.

Imagine this

A library receiving donations. Someone unpacks each box, throws away the packaging, notices that three boxes contain the same book, writes a catalogue card with the title and shelf, and marks reference-only books "not for loan". Skip that desk and the library fills with packaging and duplicates.

What good ingestion takes care of

ConcernWhy it matters for answersTypical fix
Page chrome (menus, footers, cookie banners)"Home · Sign out · 1,204 page views" ends up in chunks, wastes tokens and pollutes vectorsKeep <main>/<article>; drop nav, header, footer, aside, scripts
StructureHeadings become section titles, which chunking and citations rely onConvert headings to #/##, list items to -
Odd charactersNon-breaking spaces and Windows line endings make "identical" text differNormalise before hashing
DuplicatesThe same passage retrieved three times crowds out other sourcesContent hash; keep the first, report the rest
MetadataCitations need a source; access control needs an audience; freshness needs a dateAttach it now; it can't be guessed later
Change detectionRe-embedding everything nightly is slow and costlyStore the hash; reprocess only documents whose hash changed
Hard formatsScanned PDFs, tables, slides lose meaning as plain textOCR and layout-aware extraction (for example Azure AI Document Intelligence), tables kept as markdown
In the real world
In finance

Banks' knowledge lives in messy places: wikis, PDFs of policy manuals, spreadsheets of FAQs, email templates, scanned procedures. Ingestion must keep track of the version and effective date of every document, drop superseded copies (the "_FINAL_v2" problem in this drill), and mark which documents are internal. An assistant quoting last year's fee schedule is a misstatement, not a bug.

Enterprise RAG projects spend a surprising share of their time here: connectors to SharePoint, Confluence or Google Drive; PDF extraction that keeps tables; stripping templates that appear on every page; and syncing permissions from the source system so the index knows who may read each document. On Azure, Azure AI Search indexers pull from Blob Storage, SharePoint and databases on a schedule, and its skills can crack documents, run OCR and split text, so the pipeline you write here maps onto configuration there.

Traditional developer view

"Read the files and dump the text into the index."

GenAI developer view

"Ingestion is data engineering. Every document gets a loader, cleaning, a stable id, a source, an audience and a hash, and I can print a report of what was loaded and what was skipped and why."

Common trap

Ingesting internal and public documents into one index with no audience metadata. The first time a customer's question matches the internal approvals page, the model happily quotes "exceptions up to $100: any support agent". Decide who may see each document at ingestion, while you still know where it came from.

Interview cue

"Ingestion extracts text per format, strips boilerplate, preserves structure, attaches metadata such as source, audience and date, and uses content hashes for de-duplication and incremental updates. Bad ingestion can't be fixed downstream."

Check
Ingestion.



  
1. Why hash the text after cleaning rather than the raw file?
Two copies of the same document can differ in bytes only (Windows line endings, trailing spaces, non-breaking spaces). Hashing the cleaned text catches them as duplicates, and a re-saved but unchanged file isn't re-embedded.

  
2. Which metadata would you refuse to ship without, and why?
Source (needed for citations and debugging) and audience or permissions (needed so retrieval never shows a user something they may not see). Both are known at ingestion and can't be reconstructed later.

  
3. A wiki page's navigation menu is indexed with every page. What goes wrong?
Every chunk contains the same menu words, so vectors drift toward each other, searches for "support" match every page, and the model gets wasted tokens of "Home · Teams · Sign out" in its context.




Takeaway
Ingestion produces clean text, real structure, a source, an audience and a hash for every document, and a report of what it skipped. Every later stage relies on it.
