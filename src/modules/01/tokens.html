Learn

The unit of everything: memory, money and speed.

Definition

A token is the unit of text an LLM reads and writes: a word, part of a word, a punctuation mark or a space-prefixed fragment, mapped to an integer ID by the model's tokenizer. The context window is the maximum number of tokens the model can consider in one request, including the input and the generated output.

In plain words

A tokenizer chops your text into pieces the model knows (common words stay whole, rare words get split) and turns each piece into a number. The context window is how many pieces fit on the model's desk at once. Your instructions, the chat history, documents and the answer all have to fit on that desk.

Real output from the tokenizer used by recent OpenAI models, for the same customer question in four languages:

The context window is a desk, not a memory

Imagine this

The context window is your exam desk. You can bring some notes (documents), the question paper (prompt) and your answer sheet (output). The desk has a fixed size; bring the whole library and it won't fit. When the exam ends, the desk is cleared, and next time you start with an empty desk. That's why the model "forgets" between calls.

Facts worth remembering

  • You're billed per token, input and output separately; output tokens usually cost several times more.
  • Current large models offer context windows from roughly 128K up to about 1M tokens; the output limit per response is much smaller and separate.
  • Reasoning models also produce hidden reasoning tokens. You don't see them, but they count as output and cost money.
  • The response's usage field is the truth. Your estimate is just an estimate.
In the real world
In finance

Financial documents are long. A listed company's annual report is often 100 to 300 pages, roughly 60,000 to 200,000 tokens, and a year of card transactions for one customer can be several thousand lines. An analyst copilot can't send everything on every question, so it counts tokens first, then sends only the sections that matter (the risk factors, the segment table). Token counts are also how the bank budgets the feature: 40,000 customer chats a month at 2,000 tokens each is 80 million tokens, a number finance will ask you for before launch.

Coding assistants can't send your whole repository to the model, so they work hard on context assembly: which open files, which related functions, how much of the current file. Support bots do the same with knowledge articles. When an AI product feels "smart about your stuff", it's usually because someone engineered what goes into the window.

Common trap

"The model supports 1M tokens, so let's send all our documents every time." It works in the demo; then the bill arrives, each answer takes 40 seconds, and quality drops because the relevant paragraph is buried. A big window is a capability, not a strategy. Send the right content (Module 06).

Interview cue

"Tokens are the units the model reads and bills; the context window is the total token budget for input plus output in one request." Add that input and output are priced differently and that languages tokenize differently: it signals production experience.

Open alternative · Claude counts differently

      

        
Every model family has its own tokenizer. Claude's API counts tokens for free:


from claude_llm import client, CLAUDE_MODEL

for text in ["I was charged an overdraft fee twice. Can you check my account?",
             "当座貸越の手数料を2回請求されました。口座を確認していただけますか？"]:
    count = client.messages.count_tokens(model=CLAUDE_MODEL, messages=[{"role": "user", "content": text}])
    print(count.input_tokens, "tokens:", text)

        
The numbers won't match tiktoken's. Never estimate one provider's tokens with another provider's tokenizer.

      

    

  

  






  
Drill 01.6
Build a token-budget CLI with your AI assistant

    
~15 minCopilot · Claude Code · Codexno API cost

  

    
Goal: a small tool real teams use before sending documents to a model: how many tokens, what it costs, and does it fit?

    
    
      
  1. Ask AI
    Send this prompt
    
        
    Create token_budget.py, a command-line tool using argparse and tiktoken (o200k_base).
Usage: python token_budget.py FILE [--window 128000] [--reserve 4000] [--price-in 0.40]
It must print:
1) characters and estimated tokens in FILE,
2) estimated input cost in USD (price-in is USD per 1M tokens),
3) whether FILE fits in the context window after reserving --reserve tokens for the answer,
   and what percentage of that input budget it uses.
Exit with code 0 if it fits and 1 if it doesn't. Read the file as UTF-8. No other dependencies.
    
        
    Why this prompt works: exact usage line, defaults, outputs and exit codes leave nothing to guess. The exit code makes it scriptable, so a pipeline could block an oversized prompt (you'll see that idea again in Module 12).
    
        
    Reference solution (if your assistant gets stuck)

  2. Verify
    Test a file that fits and one that doesn't
    

    $ python token_budget.py tickets.py
$ python -c "open('big.txt','w').write('hello world ' * 200000)"
$ python token_budget.py big.txt
$ echo $LASTEXITCODE     # PowerShell; use: echo $? in bash
    
        
    • tickets.py fits, using a tiny fraction of the budget.
    • big.txt (about 400,000 tokens) does not fit, and the exit code is 1.
    • Change --window 1000000: now it fits. Same document, different model, different answer.

Check
Token sense.



  
1. A request has 3,000 tokens of instructions, 20,000 of documents, 4,000 of history and a 50-token question. What else must fit?
The output, including hidden reasoning tokens on reasoning models. If input nearly fills the window, the answer is cut off or the request fails.

  
2. RR Finance Bank adds Japanese support to its chat. What happens to cost per conversation, and why?
It rises: the same meaning takes more tokens in Japanese with this tokenizer, so both input and output token counts go up.




Takeaway
Think in tokens: they are the model's memory limit, your bill and your latency, all at once.
