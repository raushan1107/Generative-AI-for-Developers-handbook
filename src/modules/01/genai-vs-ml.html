In the real world
In finance

Card-fraud detection is the classic example of traditional ML in banking: a model scores every card payment in a few milliseconds from structured features (amount, merchant, country, time since the last payment), billions of times a year. Credit scoring is similar. Generative AI sits next to these systems, not in place of them: it reads the customer's free-text dispute, drafts the letter explaining a declined payment, or summarises an investigation for the fraud analyst. Regulators also expect lending and fraud decisions to be explainable, which a fixed, well-documented model makes much easier than a free-text answer.

Most production systems are hybrids. Card-fraud scoring and product recommendations are still classic ML because they need millisecond decisions on structured data at huge volume. LLMs sit on top for the language parts: explaining a decision to a customer, summarising a case for an analyst, understanding a free-text complaint. Search products work the same way: classic ranking finds results, a language model writes the summary.

Common trap

Using an LLM for everything. Calculating interest, validating an IBAN or an email address, checking whether a customer ID exists, sorting transactions by date: these have exact answers. Plain code does them perfectly, instantly and for free. Use the LLM for the fuzzy part (understanding the customer's message) and code for the exact part (looking up the account). Module 04 wires the two together.

Traditional developer view

"We need a model, so we need a data scientist, a labelled dataset and three months."

GenAI developer view

"A pre-trained model already understands language, so I can prototype with a prompt this afternoon. If volume, latency or cost demand it later, I can train a small classic model, using the LLM to help label the data."

Interview cue

"When would you not use an LLM?" Say: "When the task has an exact answer, needs millisecond latency at high volume, or is a narrow classification with plenty of labelled data. There, plain code or a small classic model is cheaper, faster and more predictable."

    5. 
      
  5. Think
    Read the results like an engineer
    
        
    Answer before opening: (1) Why did classic ML miss the Spanish ticket and the "$45 fee for my international wire" ticket? (2) Why did the LLM mix up dispute and fraud? (3) RR Finance Bank gets 40,000 messages a month. Which approach would you put in production, and why?
    
        
    Compare with my answers
    
          
      
            
    1. Classic ML only knows the words it was trained on. The training data was English only, so the Spanish message was a guess; and "wire" appears in many transfers examples, so word statistics beat the meaning ("refund the fee"). The LLM understood Spanish and the fee request for free.
      2. 
            
    2. "Money is missing after a text with a link" sounds like a payment problem, and "charged but the order was cancelled" mentions a card. RR Finance Bank's house rule (recognised but wrong = dispute; not recognised = fraud) decides which team handles it, and the bank's fraud team works to different deadlines. The LLM can't know a house rule you didn't tell it; Module 03 fixes this with clear instructions and few-shot examples. A small local model also makes more mistakes than a large hosted one: compare yours.
      3. 
            
    3. It depends, and that's the real answer. The LLM is more robust to wording and language with zero training; classic ML is thousands of times faster and free per call. Banks have run classic models for card-fraud scoring for decades for exactly that reason. A common production pattern: an LLM to label historical tickets, then a small classic model for high-volume routing, with the LLM as a fallback for low-confidence cases.

Check
Pick the right tool.



  
1. RR Finance Bank wants to reject payment forms with an invalid IBAN (the checksum fails). LLM or code?
Code. It's an exact rule with a known answer. An LLM would be slower, cost money and occasionally be wrong.

  
2. Customers write free-text complaints in 12 languages and you have no labelled data. Classic ML or an LLM to start?
An LLM: no training data needed and it handles many languages. Revisit with classic ML later if volume and cost justify it.
