The mental map: a loop with guard rails

Every agent, from a coding assistant to a travel-booking bot, is the same loop: the model looks at the goal and what it knows so far, chooses a next step, your code runs it, and the result goes back into the loop until the model answers or a limit stops it.

Takeaway

An agent is a model in a loop with tools, state and a goal. The loop is easy; the engineering is in the guard rails.

Why this module matters

After Milestone 6, RR Finance Assist can explain any policy and quote a customer's refund. But when Mei says "please extend my lab", it can only tell her how to do it herself, or raise a ticket that a person handles a day later. Half of RR Finance Bank's 25,000 monthly requests are of this kind: change a date, extend a lab, resend a voucher. The team wants Assist to do them, provided nothing changes without the customer's say-so, fees are never made up, and a model mistake can't move a booking twice.

The hands-on exercise of this module is an agent that understands a request, selects and calls the right tools, processes the results and returns a final answer. In Milestone 7 it becomes RR Finance Assist's ability to act, with a human approving every change.

Imagine this

A new assistant at a front desk. They can look anything up on their own, but for anything that changes a booking or costs money, they fill in the form, show it to the customer ("move to the 29th, $50, OK?") and only file it once the customer signs. They also have a list of what they may never do, and their manager can read the log of everything they did.

Traditional developer view

"Each feature is a fixed flow: form → validation → API call. Users click through it."

GenAI developer view

"The model chooses the flow at run time from a set of tools I designed. I control identity, limits, approvals and idempotency in code, and I keep fixed workflows where the path is always the same."

Lab kit for Module 07

  • Azure: your chat deployment from Module 02. Agents call the model several times per request, so a fast, inexpensive model is a good choice; use TOOLS_REASONING_EFFORT=none if a reasoning model rejects tools (Module 04).
  • Free, local alternative: ollama pull qwen2.5:7b. Agents need a model that's good at tool calling; on these pages, real outputs come from qwen2.5:7b, and you'll also see what a 3B model (llama3.2) gets wrong. On a laptop CPU, expect 20 to 60 seconds per model call.
  • Install: nothing new. Make sure your openai package is recent (pip install -U openai) so client.chat.completions.parse exists.
  • New files in genai-labs/: desk.py (stand-in RR Finance Bank systems that agents can read and change, with an audit log), desk_tools.py (the tools and a shared system prompt), agent.py (the agent loop, about 90 lines), memory.py, fake_llm.py (a scripted model for offline tests), and tests.
  • Cost: on Azure, a few cents for the module; an agent run costs several model calls, which the drills count for you.
  • Build: Milestone 7 lets RR Finance Assist propose lab extensions and date changes, shows the customer Approve and Decline buttons, executes approved actions once in code, and adds guards for repeated calls and tool calls written as text.
