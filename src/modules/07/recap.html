Agent checklist

  • You can explain what makes a system an agent, and trust audit logs, not the model's account of what it did (Drill 07.1).
  • Plans can be requested as structured output and validated in code before anything runs (Drill 07.2).
  • Tools have verb-object names, descriptions written for a model, separate reads and writes, and actionable errors (Drill 07.3).
  • Predictable paths are workflows; the model steers only where the path varies (Drill 07.4).
  • Working context, task state, history and long-term memory are separate, budgeted and protected (Drill 07.5).
  • Multi-step runs have budgets and traces, and report partial success from the log (Drill 07.6).
  • Write actions need approval of a code-computed preview, bound to one proposal, with expiry (Drill 07.7).
  • Guard rails are tested offline with a scripted model, and writes are idempotent under failure (Drill 07.8).

Self-check

1. A colleague's chatbot says "I've cancelled your booking" and nothing was cancelled. What went wrong, in one sentence, and the fix?

The model described an action it had no tool to perform; report actions only from tool results and logs, and give it tools (with approvals) if it should act.

2. When would you write a workflow instead of an agent?

When the steps for a kind of request are known in advance: route with one model call, run fixed code, and use the model only for language. It's cheaper, faster and easier to test.

3. Why do request tools return a proposal instead of performing the action after asking in chat?

A chat "yes" can be ambiguous or injected, and the model could change the arguments. A stored proposal freezes the arguments and summary, and only a structured decision bound to its id executes it, in code.

4. What makes a tool description good for an agent?

It says what the tool does, when to use it and what to call first, describes parameters with examples, and states whether it changes anything; errors then say what to do next.

5. What's the difference between task state and long-term memory?

Task state belongs to one task (goal, facts, pending approval) and ends with it; long-term memory is a small set of explicit, user-controlled facts recalled across sessions, filtered for sensitive data.

6. How do you test an agent's guard rails without paying for model calls?

With a scripted fake model that returns planned tool calls and texts, driving the real loop and tools: budgets, loops, approvals, errors and idempotency are then checked deterministically in milliseconds.
