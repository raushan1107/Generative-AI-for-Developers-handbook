Plan

From "I can't see your booking" to "here's your number".

RR Finance Bank· the brief for milestone 4

Pilot feedback is blunt: customers don't want the overdraft policy read to them, they want to know which of their fees come back. The contact-centre lead wants Assist to answer status questions (cards, recent payments) by itself and to open a case, with a clear summary, for anything that needs a person. Compliance insists fee refunds and dispute deadlines come from the same rules the bank's systems use. Security insists that one customer can never see another customer's accounts, whatever they type.

  4. Run
    The streaming tool loop
    
        
    The biggest change. Two details are new: tool calls arrive in pieces while streaming (id and name first, arguments a few characters at a time), so _model_round() assembles them by index; and yield from passes text deltas straight to the browser while the loop keeps the tool calls for itself. Only the final answer goes into history, so memory stays small.

  7. Ask AI
    Tests for the tool loop, with a scripted fake model
    
        
    Write offline pytest tests for the tool loop in #file:app/chat.py. No network calls.

1. tests/fakes.py: a FakeClient whose chat.completions.create(**kwargs) plays scripted "rounds"
   in order and records kwargs. A round is either {"text": "..."} or {"tools": [(id, name, args)]}.
   When stream=True, yield chunks shaped like the OpenAI SDK's: first a chunk with choices=[],
   then text word by word, or tool-call deltas (first id+name, then the arguments in 7-character
   pieces), a finish_reason chunk, and a final usage-only chunk (prompt_tokens=100,
   completion_tokens=10). Also support {"raise": "rate"} to raise openai.RateLimitError.
2. tests/test_chat_tools.py: a plain answer needs one call; a quote_fee_refund tool call followed by
   text sends the assistant tool_calls and the tool result (same tool_call_id) on the second call
   and sums usage to 200 input tokens; tools are strict and parallel_tool_calls is False; Mei asking
   for Diego's card gets "not allowed" in the tool result; the loop stops after MAX_TOOL_ROUNDS
   (monkeypatch it to 2) with a "replace" event; a rate-limit error yields a friendly error event
   and leaves the session history empty.
Use Mei (RR-10293, account AC-5512, cards 4821 and 1177) and Diego (RR-20877, card 9034) from app/backend.py.
    
        
    Why this prompt works: streaming tool calls are the hardest part to test, so the prompt specifies the exact chunk shapes, including the empty-choices and usage-only chunks that break naive code. Each test is a behaviour you care about (linking IDs, identity, the round limit, clean history on errors), not a line of code.
