What you're creating

Definition

Microsoft Foundry is Azure's platform for building generative AI applications and agents. A Foundry resource hosts model deployments (including Azure OpenAI models) and projects, and exposes them through secure, metered API endpoints.

In plain words

Foundry is where you rent a model in Azure. You pick a model from a catalogue, give your copy a name (a deployment), and Azure gives you a URL and a key. Your code calls that URL and you pay for the tokens you use.

Imagine this

A food court. The catalogue is the list of restaurants. A deployment is a table booked at one of them under a name you choose ("chat"). The endpoint and key are the table number and your token. You order (send prompts) and pay per plate (per token). An empty table costs nothing.

Name check

Azure AI Studio became Azure AI Foundry, which is now Microsoft Foundry (portal: ai.azure.com). Azure OpenAI Service is now offered as Azure OpenAI models inside Foundry. Older articles use the old names, and portal menus move. If a button isn't where a step says, use the search box.

Deployment types, and why the architect in you should care

Deployment typeWhere prompts are processedUse it for
Global StandardAny Azure region with capacityLabs, prototypes, most workloads. Widest model choice, best price.
Data Zone StandardInside a data zone (for example the EU or the US)Data must stay within a geography, but you still want pooled capacity.
Standard (regional)Only the resource's regionStrict residency needs. Fewer models available.
Provisioned (PTU)Reserved capacity, paid hourlyHigh, steady production traffic needing predictable latency. Never for labs.

Create it: pick one of two paths

Drill 00.1

Path A: create it in the Foundry portal

~10 minMicrosoft Foundry

Goal: a live chat deployment named chat, its endpoint and a key.

  1. Portal

    Create a project

    Go to ai.azure.com, sign in, and choose Create project. Name it proj-genai-labs; under advanced options create a resource group rg-genai-labs and pick a region. This creates a Foundry resource (it holds keys and deployments) and a project inside it. You need Contributor rights on the subscription or resource group.

  2. Portal

    Deploy a small chat model as chat

    Open the model catalogue (search Models), pick a small, cheap chat model (at the time of writing gpt-5.4-mini or gpt-6-luna; any current "mini"/"luna" tier works) and choose Deploy. Set the deployment name to exactly chat, keep Global Standard, and lower tokens-per-minute to about 20K so a runaway loop can't burn money.

  3. No-code

    Say hello in the playground

    Open the chat playground, select chat, and ask "Hello, who are you?".

  4. Portal

    Copy endpoint and key

    On the resource or project overview, copy one API key and the Azure OpenAI endpoint (https://<resource-name>.openai.azure.com/). You'll paste them into .env on the helpers page.

  5. Verify
    • The playground answered.
    • The deployment name is exactly chat (lowercase).
    • You have the endpoint and one key in a safe place (not in a chat or a document).
Drill 00.2

Path B: have your AI assistant write the Azure CLI script

~15 minAzure CLICopilot · Claude Code · Codex

Goal: experience the course in miniature. You describe infrastructure in plain English, a model writes the code, and you verify it before trusting it.

Before you start: install the Azure CLI, run az login, and set up an AI assistant (see Workstation and AI assistant). Open an empty folder in VS Code.

  1. Your prompt

    Write the prompt yourself

    Ask your assistant for a script that creates the resource group, the Foundry resource and the chat deployment. Use the template; fill every line.

    Goal:        a script that creates …
Context:     I'm logged in with az login; OS/shell is …
Constraints: names …, region …, model …, deployment type …, capacity …;
             idempotent where possible; no secrets printed or saved
Done when:   I can list the deployment with an az command you also give me

    Hint: name the shell (PowerShell or bash), the exact resource names (rg-genai-labs, a globally unique resource name like aif-genai-yourinitials), the deployment name chat, the model (gpt-5.4-mini), GlobalStandard with a capacity of 20 (20K tokens per minute), and ask for verification commands too.

    Compare with my prompt
    Goal: Write a PowerShell script (create_foundry.ps1) that uses the Azure CLI to create everything
I need for my GenAI labs.

Context: I'm already logged in with `az login`. I'm on Windows, using PowerShell 7.

Constraints:
- Resource group: rg-genai-labs in eastus2
- Foundry (Azure AI Services) resource: aif-genai-rr (kind AIServices, SKU S0, custom domain = same name)
- Model deployment named "chat": model gpt-5.4-mini, model format OpenAI,
  SKU GlobalStandard, capacity 20 (20K tokens per minute)
- Put names in variables at the top. Stop on the first error.
- Do NOT print or save API keys. Print only the endpoint at the end.

Done when: give me separate az commands to verify the resource group, the resource and the
deployment exist (table output), and explain what each script line does in one comment.
    Why this works: every blank that the model would otherwise guess (shell, names, model, SKU, capacity) is filled in, and "Done when" forces it to hand you a way to check its own work. That's the prompt design framework you'll study in Module 03.
  2. Run

    Read the script, then run it

    Read every line before running it. You're the reviewer. It should look broadly like the reference below (yours may differ in style). If the model version is rejected, ask your assistant to look up valid versions with az cognitiveservices account list-models.

    Reference script (PowerShell)
    # Names and settings
$rg       = "rg-genai-labs"
$location = "eastus2"
$name     = "aif-genai-rr"          # must be globally unique
$ErrorActionPreference = "Stop"

az group create --name $rg --location $location --output none

az cognitiveservices account create --name $name --resource-group $rg `
  --location $location --kind AIServices --sku S0 --custom-domain $name --yes --output none

az cognitiveservices account deployment create --name $name --resource-group $rg `
  --deployment-name chat --model-name gpt-5.4-mini --model-version 2026-03-17 `
  --model-format OpenAI --sku-name GlobalStandard --sku-capacity 20 --output none

az cognitiveservices account show --name $name --resource-group $rg --query properties.endpoint -o tsv
  3. Verify

    Prove it exists

    $ az group show -n rg-genai-labs -o table
$ az cognitiveservices account list -g rg-genai-labs -o table
$ az cognitiveservices account deployment list -g rg-genai-labs -n aif-genai-rr -o table
    • The deployment list shows chat with your model and GlobalStandard.
    • The script never printed a key.
    • Get a key safely: az cognitiveservices account keys list -g rg-genai-labs -n aif-genai-rr --query key1 -o tsv, straight into .env.

Remember: “The assistant wrote the script; you were the engineer. Reviewing and verifying is the job.”

Common trap

In code, model= must be the deployment name (chat), not the model name (gpt-5.4-mini). Mixing them up gives a 404 "deployment not found". It's the most common first-day error in every batch.

Optional: keyless sign-in with Microsoft Entra ID

Keys are simple, which is why the labs use them. In production you'd rather have no key at all: the app signs in with its identity and Azure checks its role. You'll do this hands-on in Drill 02.3; the quick version is az login, the Cognitive Services OpenAI User role on the resource, and DefaultAzureCredential in code.
