Learning project

This is an educational exercise using synthetic reports, not investment advice. Do not use the examples for real financial decisions.

The problem: an investment research copilot

RR Finance Capital· a fictional investment research desk

Analysts at RR Finance Capital review quarterly results from fictional companies. They want a research copilot that can find facts in the approved reports, extract selected metrics to validated JSON, compare periods, and draft answers with citations to the source file and page. Analysts—not the model—interpret the results and make investment decisions.

The assistant must distinguish reported facts from calculations and generated narrative, state when the source does not contain an answer, and never recommend buying or selling a security. Every input document, issuer and figure in the starter pack is synthetic.

The brief

Build a small analyst-facing application for the three synthetic issuers in the starter pack. A user selects an issuer and reporting period, asks a question or requests a metric extraction, and receives a reviewable answer. The system should use only the selected, approved reports as evidence.

RequirementAcceptance evidence
Report ingestionIngest all three Markdown reports with issuer, period, page and source metadata. A report replacement produces a new version, not a silent overwrite.
Structured extractionReturn revenue, operating income, operating margin, EPS and guidance in a validated schema. Include source page references for every extracted field; abstain when a field is not present.
Cited Q&AEach factual answer links to a report and page. Unknown, unsupported or out-of-scope questions receive an explicit limitation, not an invented number.
Period comparisonCompare two reports only when both are available. Label calculated differences and show the inputs and pages used.
Safety boundaryDo not generate buy/sell/hold recommendations, price targets or personalized portfolio advice. Provide the required disclaimer and an analyst-review path.
EvaluationRun the supplied cases, report extraction accuracy and citation/source correctness separately, and test abstention and recommendation requests.
OperationsRecord model, prompt, source-set and evaluation versions; estimate cost using current deployment rates; document latency, privacy, rollback and incident handling.

Data boundary
Do not mix real market data, analyst notes or material non-public information into this starter pack. If you extend the exercise, use clearly synthetic material and document its provenance.

Review checklist


    

  • Can an analyst open every cited report page?
    • 

  • Does the app distinguish source facts from its own arithmetic and explanation?
    • 

  • Does it abstain if a question asks for data absent from the selected reports?
    • 

  • Does it refuse to issue a personal or security-specific recommendation, without implying the disclaimer makes advice safe?
    • 

  • Are evaluation results tied to exact report, prompt, model and dataset versions?
    • 

  • Can the operator disable the feature or return to a known prior version?

Completion criterion
The capstone is complete when the application is useful, its claims are inspectable, its failure modes are measured and the analyst remains accountable for investment decisions.
