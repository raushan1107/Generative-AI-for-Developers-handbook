Capstone · RR Finance Capital Research Copilot

Design, build and evaluate a research assistant from a brief rather than step-by-step instructions. The starter reports and every company are fictional; the project must not produce investment recommendations or be used for real financial decisions.

Part V · AvailableResearch copilotSynthetic reports100-point rubric
Learning project

This is an educational exercise using synthetic reports, not investment advice. Do not use the examples for real financial decisions.

The problem: an investment research copilot

RR Finance Capital· a fictional investment research desk

Analysts at RR Finance Capital review quarterly results from fictional companies. They want a research copilot that can find facts in the approved reports, extract selected metrics to validated JSON, compare periods, and draft answers with citations to the source file and page. Analysts—not the model—interpret the results and make investment decisions.

The assistant must distinguish reported facts from calculations and generated narrative, state when the source does not contain an answer, and never recommend buying or selling a security. Every input document, issuer and figure in the starter pack is synthetic.

The brief

Build a small analyst-facing application for the three synthetic issuers in the starter pack. A user selects an issuer and reporting period, asks a question or requests a metric extraction, and receives a reviewable answer. The system should use only the selected, approved reports as evidence.

RequirementAcceptance evidence
Report ingestionIngest all three Markdown reports with issuer, period, page and source metadata. A report replacement produces a new version, not a silent overwrite.
Structured extractionReturn revenue, operating income, operating margin, EPS and guidance in a validated schema. Include source page references for every extracted field; abstain when a field is not present.
Cited Q&AEach factual answer links to a report and page. Unknown, unsupported or out-of-scope questions receive an explicit limitation, not an invented number.
Period comparisonCompare two reports only when both are available. Label calculated differences and show the inputs and pages used.
Safety boundaryDo not generate buy/sell/hold recommendations, price targets or personalized portfolio advice. Provide the required disclaimer and an analyst-review path.
EvaluationRun the supplied cases, report extraction accuracy and citation/source correctness separately, and test abstention and recommendation requests.
OperationsRecord model, prompt, source-set and evaluation versions; estimate cost using current deployment rates; document latency, privacy, rollback and incident handling.

Starter data

Use these synthetic files as the source of truth. Page numbers are printed inside each report so citations can point to stable locations.

  • Northstar Payments · Q3 2026
  • Riverstone Retail · Q3 2026
  • Cedar Grid Systems · Q3 2026
  • Expected metric values and source pages
  • Evaluation cases and expected evidence

Check that all source references resolve before beginning:

"""Check that the capstone's synthetic evaluation references point to report pages."""

import json
from pathlib import Path


ROOT = Path(__file__).resolve().parent
DATA = ROOT / "data"


def main() -> None:
    metrics = json.loads((DATA / "expected_metrics.json").read_text(encoding="utf-8"))
    cases = json.loads((DATA / "evaluation_cases.json").read_text(encoding="utf-8"))
    reports = {
        path.stem: path.read_text(encoding="utf-8")
        for path in (DATA / "reports").glob("*.md")
    }
    if not reports:
        raise ValueError("No synthetic report files were found")
    for case in cases["cases"]:
        matching = [text for text in reports.values() if case["source_document"] in text]
        if not matching:
            raise ValueError(f"{case['id']}: source document is missing")
        if case["source_page"] is None:
            continue
        report = matching[0]
        page_heading = f"## Page {case['source_page']} —"
        if page_heading not in report:
            raise ValueError(f"{case['id']}: cited page heading is missing")
    if set(metrics["issuers"]) != {
        "northstar_payments",
        "riverstone_retail",
        "cedar_grid_systems",
    }:
        raise ValueError("Expected metrics must cover all three synthetic issuers")
    print(f"OK: {len(reports)} reports and {len(cases['cases'])} evaluation cases")


if __name__ == "__main__":
    main()

OK: 3 reports and 6 evaluation cases
Data boundary

Do not mix real market data, analyst notes or material non-public information into this starter pack. If you extend the exercise, use clearly synthetic material and document its provenance.

What you deliver

  1. Design: a short architecture note showing trust boundaries, source versioning, schema, retrieval, model choice and deliberate non-GenAI code.
  2. Working app: a small analyst-facing UI or CLI with report selection, extraction, cited Q&A and an explicit abstention path.
  3. Evaluation evidence: results for the supplied cases plus at least five additional cases you author, including a failure and an out-of-scope recommendation request.
  4. Safety and operations: tests for source isolation and unsupported questions, a privacy and retention note, a current-rate cost estimate, and rollback/incident instructions.
  5. Demo: show a supported answer with citations, a comparison with calculations, an unsupported question handled safely, and the evaluation results.

Scored rubric · 100 points

AreaPointsFull-credit evidence
Data and source handling15All reports are versioned, page metadata is preserved, and evidence is isolated to the selected issuer/period.
Structured extraction15Schema validates, values match the expected file, source pages are included, and missing values are not invented.
Retrieval and citations20Relevant report sections are retrieved; claims link to the correct report and page; invalid or absent evidence is surfaced.
Evaluation quality15Supplied and authored cases run reproducibly; extraction, source correctness and abstention are measured separately.
Safety and privacy15No recommendation behavior; boundary cases are tested; inputs, logs and retained data are minimized; analyst review is explicit.
Architecture and operations10Components are explained, cost and latency assumptions are stated, versions are recorded and rollback is described.
Communication and demo10Shows a successful answer, a failure handled safely and the evidence behind the release decision.

Review checklist

  • Can an analyst open every cited report page?
  • Does the app distinguish source facts from its own arithmetic and explanation?
  • Does it abstain if a question asks for data absent from the selected reports?
  • Does it refuse to issue a personal or security-specific recommendation, without implying the disclaimer makes advice safe?
  • Are evaluation results tied to exact report, prompt, model and dataset versions?
  • Can the operator disable the feature or return to a known prior version?
Completion criterion

The capstone is complete when the application is useful, its claims are inspectable, its failure modes are measured and the analyst remains accountable for investment decisions.
