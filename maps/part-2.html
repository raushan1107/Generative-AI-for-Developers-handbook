Part II Concept Map: Connect the Model to Your App

Part II turns a model response into something an application can validate and use. First define the shape of the response and the functions the model may request. Then represent text as vectors and retrieve useful information by combining semantic similarity with metadata and keywords.

Why structured outputs matterA structured response follows a predictable shape that application code can parse and validate.
Definition
A structured response follows a predictable shape that application code can parse and validate.
Example
Return a support category and urgency as named fields rather than extracting them from a paragraph.
In finance
A bank can route a card dispute only after checking required fields and allowed category values.
Where it's used
Form extraction, classification, API payloads and downstream workflow decisions.
Keep in mind
A valid structure does not prove that the values are true, complete or appropriate.

Definition
A schema describes the expected fields, data types and sometimes allowed values for a response.
Example
A product request schema can constrain a family to accounts, cards or loans and represent an unstated fee as null.

Where it's used
Typed extraction, constrained classification and API-facing responses.

Function callingThe model requests a named tool with arguments; application code decides whether to validate and execute it.
Definition
The model requests a named tool with arguments; application code decides whether to validate and execute it.
Example
The model requests a product search with family=cards and a maximum annual fee.
In finance

Where it's used
Grounding answers in application data and initiating controlled workflows.

Malformed-response handling detects failed, incomplete or unexpected model output and returns an explicit error or safe retry.
