Part IV Concept Map: Build It Right

Part IV moves from a working prototype toward a system that can be observed, evaluated and reviewed for risk. Architecture gives the request a controlled path; evaluation measures behavior against examples and thresholds; security and responsible-AI work identify threats and add human and technical controls.

08AI Application ArchitectureGive requests controlled routes and observable state · 2 topics
Gateways and model routingA gateway provides a controlled interface to model services; routing selects a model or deployment for a request.
Definition
A gateway provides a controlled interface to model services; routing selects a model or deployment for a request.
Example
Send an eligible low-complexity request to a lower-cost deployment and route other requests according to tested rules.
In finance
A bank's route must respect data classification, residency, approved deployments and fallback policy.
Where it's used
Centralized policy, provider abstraction, observability and model selection.
Keep in mind
A gateway does not make an unsafe route safe; route decisions need explicit constraints and evaluation.

Sessions, queues and tracesSessions retain task context, queues manage asynchronous work and traces correlate events across a request path.
Definition
Sessions retain task context, queues manage asynchronous work and traces correlate events across a request path.
Example
Attach a trace ID to retrieval and model-call events while storing only the session data needed for follow-up.
In finance
Support history and trace attributes should minimize sensitive content and follow access and retention rules.
Where it's used
Multi-turn systems, background jobs, incident diagnosis and performance analysis.
Keep in mind
A trace ID is not a trace system, and persistent session data needs security, retention and deletion controls.

09Evaluating GenAI ApplicationsTest a representative dataset and gate on measurable behavior · 2 topics
Build an evaluation setAn evaluation set contains representative inputs, expected outcomes and, where useful, human-reviewed references.
Definition
An evaluation set contains representative inputs, expected outcomes and, where useful, human-reviewed references.
Example
Include routine, ambiguous and adversarial bank-support messages with expected categories and urgency.
In finance
Fraud and lost-card cases should be represented so important misses are visible, not averaged away.
Where it's used
Regression tests, model comparisons and ongoing quality measurement.
Keep in mind
Small or biased samples can hide failures; protect evaluation data and avoid training/evaluation leakage.

Metrics, judges and release gatesMetrics summarize selected behavior; judges may score outputs, and a release gate compares results with explicit criteria.
Definition
Metrics summarize selected behavior; judges may score outputs, and a release gate compares results with explicit criteria.
Example
Track fraud recall separately from overall accuracy and block a release if the required minimum is missed.
In finance
A high accuracy score can still hide missed fraud messages when classes are imbalanced.
Where it's used
Model selection, prompt regression and release decisions.
Keep in mind
No single metric proves quality; automated judges need calibration and human review for important outcomes.

10Security and Responsible AIThreat-model the system and use layered privacy and safety controls · 2 topics
Threat model and prompt injectionThreat modeling identifies assets, trust boundaries, threats and mitigations for an AI-enabled system.
Definition
Threat modeling identifies assets, trust boundaries, threats and mitigations for an AI-enabled system.
Example
Treat retrieved documents and user messages as untrusted input, and prevent them from directly authorizing privileged tool calls.
In finance
A support assistant must not expose staff procedures or act on payment instructions embedded in retrieved content.
Where it's used
Design reviews, abuse analysis and security testing.
Keep in mind
Prompt wording and keyword indicators are not security boundaries; enforce permissions and tool rules in code.

Privacy, safety and human reviewPrivacy and safety controls govern what data is used, what outputs are allowed and when a person must review a result.
Definition
Privacy and safety controls govern what data is used, what outputs are allowed and when a person must review a result.
Example
Minimize customer data sent to a model and require review for a high-impact account action.
In finance
Masking, access control, retention, escalation and user disclosure must be designed for the actual service and jurisdiction.
Where it's used
Reducing exposure and harm across collection, inference, storage and user interaction.
Keep in mind
A regex or content filter can miss cases; use layered controls, testing and accountable review.
